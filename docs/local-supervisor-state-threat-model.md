# Local supervisor state threat model

**Status:** D1 feature-branch baseline; not a worker-launch or production claim.

| Threat | Control | Verification | Residual boundary |
| --- | --- | --- | --- |
| A repository, `.git`, cache or temporary path is used as state. | The resolver accepts only the declared per-platform application-state root and returns typed `unavailable` when it is absent. | `local-supervisor-state.test.mjs` covers absent roots. | The operator must provide the platform state location; no fallback is attempted. |
| A relative, symlinked, non-directory, sticky/writable ancestor or concurrent creator redirects state. | The platform base must be absolute; setup walks every directory component with `lstat`, rejects symlinks/non-directories and every group/world-writable ancestor (including sticky directories), requires the final state root to be current-user-owned and non-group/non-world-writable, and acquires one `wx` lock attempt. | Relative-base, root/ancestor-symlink, writable-root, sticky-ancestor and foreign-lock fixtures. | The lock is a bounded same-host coordination primitive, not a distributed lease. |
| A child record, journal or lock is replaced by a symlink, non-regular file, foreign-owned file, permissive-mode file or hard-linked file. | Preflight and repair `lstat` every direct child before reading it; each direct child must be current-user-owned, non-group/non-world-writable, regular, non-symlinked, at most 65,536 bytes and have exactly one link. Unsafe state/journal/lock bytes produce typed non-adoption. | Child-symlink, writable-root and hard-link fixtures for `state.json`, `prepared.json` and `repair.lock`. | A privileged same-host actor can still race after a check. Owner: Nova B B1-I feature owner; review by 2026-08-01 and before worker-admission authority. |
| An interrupted prepare or malformed record is silently adopted. | The prepared journal and record are closed/digest-bound; unknown bytes return `recovery-required`, never takeover. | Interrupted-journal fixture and record validation. | Repair does not recover an unproven owner. |
| A prior record shape is treated as compatible after a schema change. | The persisted contract is v3; v1/v2/unknown records are rejected as `recovery-required`, with no implicit migration. | Version-rejection and candidate/subject mismatch fixtures. | A future migration needs distinct accepted authority. |
| Cleanup affects another process after PID reuse or a copied record is replayed. | Cleanup admission requires nonce, PID, process-start digest, boot digest, exact manifest-record membership, lease digest and an unexpired lease at supplied monotonic time. | Wrong-owner, missing-manifest and expired-lease denial fixtures. | This slice admits cleanup only; it sends no signal and launches no process. |
| Credentials or private coordinates become durable state. | The closed schema contains only digests, identifiers and repair metadata; no path or credential field exists. | Runtime/schema validation and Security scan. | Any broker or credential lease needs separate B2 authority. |

Rollback is an ordinary forward revert of the D1 slice followed by fresh Verify,
Security and Critic evidence. It never deletes a broad path or signals a process.

## ADR-0048 functional worker extension

| Threat | Control | Verification | Residual boundary |
| --- | --- | --- | --- |
| A worker shares or mutates the source Git control directory. | Each worker uses a private local `--no-hardlinks --no-checkout` clone below the exact ADR-0047 root, verifies detached `HEAD`, and revalidates the source HEAD/status after execution. | Real temporary-repository integration tests compare source/clone object inodes, prove overlap, run a second post-cleanup wave, and force source drift. | A clone is filesystem separation only; no OS isolation is claimed. |
| Capacity consumes the control or recovery lane or overlapping write sets race. | Admission subtracts the B1-C Elephant/Verify/Critic reservation and one B1-I recovery slot, rejects overlapping worker paths to serial fallback, admits the complete wave or returns `serial-fallback-required`, and caps at 16. | Exhausted-reserve, write-overlap and serial-fallback integration tests. | Host certification and pressure observations remain operator inputs. |
| Arbitrary argv, prompt argv, environment or credentials turn the worker into a confused deputy. | Production launch is fixed to digest-bound Codex `exec` argv and sends the instruction over stdin; fixture launch is fixed to the repository fixture. The environment is allowlisted and credential values are neither accepted nor persisted. | Closed-schema, executable-digest, runner-kind, stdin/argv and environment-denial tests plus Security. | Live provider authentication/network use requires a separate activation; this implementation block performs none. |
| PID reuse or a copied record signals an unrelated process. | Every heartbeat and signal re-observes nonce, PID, process-start, boot and executable digests; only that PID is signalled. | Wrong-start, wrong-boot, wrong-nonce, dead-process and timeout/cancel integration tests. | Linux `/proc` is the first certified identity adapter; unsupported hosts return unavailable. |
| Cleanup removes a foreign or still-needed workspace, or prevents a later wave. | Cleanup is a separate digest-bound activation and requires the exact terminal record, owner marker, path digest, lease and manifest member; it removes only those workspaces and retires the completed supervisor/cancel records. | Foreign marker, exact cleanup and second-wave integration tests. | Ambiguous or crash-recovered ownership stays `recovery-required`; there is no automatic takeover. |
| Cancellation is replayed or confused with terminal success. | A cancellation action needs activation plus the exact current record digest, exclusively writes a digest-bound intent, and signals only re-observed worker identities; the supervisor alone records terminal cancellation. | Explicit live-child cancel/drain/cleanup integration and cancellation-contract tests. | A killed supervisor or stale/foreign intent remains `recovery-required`. |
| Ignored or untracked output escapes the result boundary, or a zero exit/fixture overlap is reported as accepted Goldfish capability. | Result import enumerates tracked and all untracked paths including ignored files, validates candidate/source status and write set, and records a bounded mode/content manifest digest. Verify/Critic/PO remain separate and capability stays unadvertised until a live provider-backed `N+1 >= 2` observation. | Ignored unauthorized-write, source-drift, nonzero-exit and fixture-versus-live claim tests. | No selected-sandbox, provider model identity or OS-isolation attestation is made. |
