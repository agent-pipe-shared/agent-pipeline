# Capability-first ordering for Advisor and Critic dispatch transport

## Description

Evidence gathering, consent requests, and wait times currently occur
before a usable transport has been demonstrated. This means costs are
incurred even when the underlying sandbox lane is not actually available.

## Triggering situation

From a greenfield happy-path test report (pipeline version
0.6.0+codex.20260818162535.96cf805, test repo Rune_Test1_Codex_060_52),
full report at docs/pipeline-greenfield-happy-path-handover.md in that
test repo. Section 9, item P1-2.

## Affected artifact

Advisor/Critic dispatch coordinator, selected-sandbox preflight.

## Proposal

Reverse the order of operations: (1) run a model-free preflight of the
selected-runner transport; (2) if unavailable, immediately record a
deferred state note and continue; (3) only once a usable lane is
confirmed, proceed to export consent, packet assembly, and model start.

Acceptance test: if the sandbox lane is missing, the entire Advisor/Critic
path must end in under ten seconds, with no export question, no bundle,
no PTY wait, and no model attempt.

## Triage (filled in by the Elephant of the next Pipeline session)

- **Decision:** Accepted — minimal targeted reorder: move the codex-executable check before consent/evidence-bundle in `codex-advisory-bootstrap.mjs`, and add an equivalent cheap non-spawning pre-check to `advisor-consult/SKILL.md`'s trigger gate.
- **Rationale:** PO 2026-08-18 accepted the analyst's recommendation as-is.
- **Assignment (if accepted):** Nova Wave 4 implementation. Must stay inside ADR-0062's frozen boundary (no new authority store, no change to `pipeline.control-execution-exchange.v1`).
- **Date:** 2026-08-18


## Design proposal (Wave-4 prep), 2026-08-18

*Prep material for PO triage, not a decision — a Triage section, if/when added, records the actual PO decision. Generated by a Workflow-dispatched read-only design pass (dispatch NVA-W4-DESIGN-capability-first-advisor-critic-dispatch) grounded in the current repo state.*

**Problem (restated):** Backlog item backlog/items/2026-08-18-capability-first-advisor-critic-dispatch.md (status: open, Triage empty, source: an external greenfield test repo's happy-path handover report, Section 9 item P1-2 -- that report file does not exist in this checkout, so I could only ground the claim against this repo's actual code) reports that, on the Codex Advisor path, consent recording, evidence-bundle assembly and wait time are paid BEFORE it is confirmed a usable Codex/selected-sandbox transport even exists. Its 'Affected artifact' line ('Advisor/Critic dispatch coordinator, selected-sandbox preflight') does not name one real file -- I resolved it by grep/read across plugins/pipeline-core/scripts/codex-advisory-bootstrap.mjs, advisory-host-bridge.mjs, sandboxed-readonly-host-bridge.mjs, codex-sandbox-select.mjs, codex-host-advisor-route.mjs, plugins/pipeline-core/skills/advisor-consult/SKILL.md, plugins/pipeline-core/skills/critic-review/SKILL.md, and lib/selected-sandbox-disposition.mjs / scripts/invocation-preflight.mjs / scripts/selected-sandbox-launch.mjs (the last three ARE the reducer/launcher named 'selected-sandbox' in the codebase, but selected-sandbox-launch.mjs's own header states it 'is never imported by any bootstrap/preflight/Verify entrypoint' -- confirmed by ADR-0062, which describes it as a manual/standalone launcher, not the live advisor/critic dispatch path). Reading the ACTUAL runtime order in codex-advisory-bootstrap.mjs's runCodexAdvisoryBootstrap (lines 82-140): (1) requireProjectOnboardingReady (L85, already model-free/local per lib/project-onboarding-ready-gate.mjs L92-164 -- this step already IS capability-first), (2) read pipeline.user.yaml and reject if advisor_export consent is declined (L90-92), (3) build+hash the evidence bundle from disk (L95-97, local I/O, up to ~1MB), (4) read the bounded stdin question (L98-99), (5) ONLY THEN resolve whether the codex executable even exists (L100-103, throws 'Codex executable is unavailable' if not) and hand off to advisory-host-bridge.mjs -> the real sandbox selection/spawn/PTY machinery in sandboxed-readonly-host-bridge.mjs/codex-sandbox-select.mjs. So the item's complaint is real and verifiable for the Advisor path specifically: consent + evidence assembly precede the codex-executable/sandbox-transport check. Interestingly, the Critic path (plugins/pipeline-core/skills/critic-review/SKILL.md lines 12-41) already implements roughly the desired shape at the protocol/skill level: it instructs the Elephant to run `codex-app-server-health.mjs --critic-ready` and `critic-dispatch-preflight.mjs` BEFORE assembling the review packet, and to dispatch only when both a 'packet-ready' result AND a usable transport execution-readiness result exist -- i.e. transport-first is already the documented Critic pattern, just not the Advisor one. This is an asymmetry, not a from-scratch design problem.

**Options:**

1. **Full reorder exactly as the item proposes (new deferred-state-note step)** — Implement the item's literal 3-step proposal: (1) a new model-free preflight step that checks selected-runner transport availability first: for Codex Advisor, at minimum resolveSystemExecutable('codex') plus a cheap, non-spawning form of the sandbox-selectability check codex-sandbox-select.mjs already does deeper down; (2) on failure, record a new typed 'deferred state note' (a new schema, e.g. pipeline.advisory-deferred.v1, since nothing in this codebase currently persists an unavailable-transport note this way) and return immediately; (3) only past that gate, proceed to codex-advisory-bootstrap.mjs's existing consent check (L90-92), evidence bundle build (L95-97) and the host-bridge/model path. Apply the mirror change to the Claude same-runner chain referenced in advisor-consult/SKILL.md's 'Claude consultation' section, and to any place in the Critic path that isn't already transport-first. Impact: Meets the item's own acceptance test most literally: when the sandbox lane is missing, the whole path ends in well under 10 seconds with no consent question, no evidence bundle built, no PTY wait, no model attempt -- for BOTH Advisor and Critic, and with a durable, typed record of why it deferred (useful for later debugging/telemetry, and for a human later asking 'why didn't the Advisor answer'). Tradeoffs: Largest surface: touches codex-advisory-bootstrap.mjs, advisory-host-bridge.mjs (or a new thin wrapper), advisor-consult/SKILL.md, likely codex-host-advisor-route.mjs, and needs a brand-new closed/validated schema plus its own test file, consistent with this codebase's heavy validate-everything convention (every other schema here -- pipeline.selected-sandbox-disposition.v1, pipeline.advisory-demand.v2, etc. -- has exact-keys validation, a digest, and a dedicated *.test.mjs). Must be reviewed against ADR-0062's frozen boundary ('no new authority store', 'no schema change to pipeline.control-execution-exchange.v1') -- a new deferred-state-note schema is advisory-side bookkeeping, not the execution DTO, so it likely fits, but that reasoning needs to be made explicit rather than assumed. Existing tests (codex-advisory-bootstrap.test.mjs, advisory-host-bridge.test.mjs, advisor-consult-v3.test.mjs) all need updates for the new step order.
2. **Minimal targeted reorder: give Advisor the same transport-first shape Critic already has, without new schemas** — Reuse the pattern that already exists for Critic instead of inventing a new one: move the cheap, already-present resolveSystemExecutable('codex') check (codex-advisory-bootstrap.mjs L100-103) to run BEFORE the consent check (L90-92) and evidence-bundle build (L95-97), and add an equivalent lightweight, non-spawning transport-readiness call analogous to critic-review's `codex-app-server-health.mjs --critic-ready` gate (SKILL.md L19-22) as a documented pre-step in advisor-consult/SKILL.md's trigger gate, ahead of its step 2 (consent) and step 3 (evidence bundle binding). No new persisted 'deferred state note' schema -- on failure, just throw/return the existing typed unavailable code (e.g. reuse 'advisory-unavailable', already named in SKILL.md L74) fast, the same way codex-advisory-bootstrap.mjs already throws today, just earlier. Impact: Fixes the concrete, evidenced asymmetry (Advisor pays consent+evidence cost before transport check; Critic mostly doesn't) with a small, low-risk change: reordering a handful of existing statements in one function plus a doc update, no new schema, no new validation surface, no new test file beyond updated ordering assertions in the existing *.test.mjs files. Gets most of the acceptance test's benefit (no consent question, no evidence bundle, no PTY wait, no model attempt on missing transport) without the durable-note bookkeeping. Tradeoffs: Weaker than Option 1 on observability: a human debugging 'why did the Advisor refuse' gets only an error code, not a persisted state note explaining the deferral. Also doesn't formalize parity between the Codex and Claude same-runner chains (Claude's V3 chain in advisor-consult/SKILL.md's 'Claude consultation' section isn't touched by this option and may have its own version of the same ordering issue, unexamined here).
3. **Defer -- reproduce and measure on this checkout before committing to either refactor** — The only evidence for this item is an external greenfield test at a different pipeline build tag (0.6.0+codex.20260818162535.96cf805) in a repo that isn't this checkout, and the actual local-only steps paid before the transport check (onboarding-readiness, consent-declined check, an up-to-1MB evidence-bundle hash) are all local I/O with no network/model cost -- the genuinely expensive part (PTY wait, model start) already sits behind those steps in the code as read. Before changing the dispatch order, instrument codex-advisory-bootstrap.mjs (or run it once with codex genuinely absent) to confirm the real observed latency and confirm it's actually >10s and not, e.g., a few hundred ms that just LOOKS costly in the external report's framing. Impact: No code change now; either confirms the item is worth prioritized Wave-4 slotting with real numbers, or downgrades it to a documentation/telemetry fix if the pre-transport-check cost turns out to already be small. Tradeoffs: Costs a triage cycle without shipping the fix; given the PO's stated general preference for deciding and acting now rather than deferring, and given the Critic-path precedent already shows the pattern is cheap to add, this option is only worth taking if Wave-4 capacity is genuinely tight -- the asymmetry itself is not in serious doubt from the code reading, only its exact magnitude is.

**Recommendation:** Option 2 (minimal targeted reorder), not Option 1's full literal proposal. The code reading shows this is narrower than the item frames it: the Critic path already has the transport-first shape documented in critic-review/SKILL.md (codex-app-server-health.mjs --critic-ready + critic-dispatch-preflight.mjs, both gating BEFORE packet assembly); the gap is specifically that codex-advisory-bootstrap.mjs checks codex-executable presence (L100-103) AFTER consent (L90-92) and evidence-bundle build (L95-97) instead of before. Fixing that ordering plus adding one cheap non-spawning transport-readiness pre-check to advisor-consult/SKILL.md's trigger gate gets nearly all of the item's acceptance-test benefit (fast-fail, no consent/evidence/PTY/model cost on a missing lane) with a small, low-risk, single-file-plus-doc change that reuses an existing pattern rather than inventing a new deferred-state-note schema. If the PO wants the durable note/telemetry from Option 1 as well, it can be layered on later as a separate, smaller follow-up once the ordering fix is proven -- don't block the ordering fix on designing a new schema.

**Risks/dependencies:** 1) The item's own 'Affected artifact' phrase is misleading: it points at 'selected-sandbox preflight' as if it were one coordinator, but lib/selected-sandbox-disposition.mjs / scripts/invocation-preflight.mjs / scripts/selected-sandbox-launch.mjs are a separate reducer+manual-launcher subsystem NOT wired into the live advisor/critic dispatch path (confirmed by the launcher's own header comment and ADR-0062) -- whoever picks up this item must be pointed at codex-advisory-bootstrap.mjs / advisory-host-bridge.mjs / codex-sandbox-select.mjs instead, or they will fix the wrong files. 2) Any change here should stay inside ADR-0062's frozen boundary (no new authority store, no change to pipeline.control-execution-exchange.v1) -- Option 2 doesn't touch that DTO at all, which is part of why it's lower risk than Option 1. 3) The Claude same-runner advisory chain (advisor-consult/SKILL.md 'Claude consultation' section) was not independently verified for the same ordering issue in this pass -- worth a quick follow-up check before considering the fix complete for 'Advisor' generally, not just the Codex half. 4) Existing test files that will need updates regardless of chosen option: codex-advisory-bootstrap.test.mjs, advisory-host-bridge.test.mjs, advisor-consult-v3.test.mjs, sandboxed-readonly-host-bridge.test.mjs. 5) No dependency on other named Wave-4 items was found in docs/state.md (grepped, no hits) or in the item file itself; this appears independent of other open Pipeline work as far as this read went.
