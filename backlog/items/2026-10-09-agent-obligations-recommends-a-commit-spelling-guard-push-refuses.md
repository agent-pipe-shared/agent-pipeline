# agent-obligations recommends a commit spelling that guard-push refuses

## Description

`templates/prompts/agent-obligations.md` (generated by `harness/scripts/generate-agent-obligations.mjs`) tells every
agent to prefer `git commit -m "<subject>" --trailer "AI-Assisted: true" --trailer "Dispatch: …"` and to use
`-F <msgfile>` only for multi-paragraph bodies (lines 35–39). guard-push refuses exactly that spelling with "push target
is not unambiguous… only git [-C <path>] push is accepted". The trailer value `Dispatch: <ID> (goldfish)` carries a
parenthesis, which guard-push treats as a possible hidden push (Ruling 81, option B); `--trailer` itself is also an
option the push classifier does not know (the T85 fail-closed path). The `-F <file>` form is admitted.

## Triggering situation

2026-10-09 deep night: three dispatches (TR-I-T3, WIN-D3b, and TR-C-T earlier through the same family) followed the
obligations file, were refused at commit, and ran out of budget before they could fall back to `-F`. Two had to be
integrated by the orchestrator. Cost: 3 lost commits, 2 orchestrator integrations, about 8 calls.

## Affected artifact

`harness/scripts/generate-agent-obligations.mjs` (the source of the generated recommendation) and guard-push (the
classifier that refuses it).

## Proposal

Make the generated text and the guard agree. Either the generator recommends `git add -- <paths>` plus
`git commit -F <msgfile> -- <paths>` as the one admitted provenance-bearing spelling (the cheap fix, and the one every
Elephant briefing already prescribes), or TR-C-F admits `git commit` with `-m`/`--trailer` as a non-push verb (a
security trade under Ruling 81). Until one of them lands, the obligations text must not recommend a refused spelling.
Pin the agreement with a test that runs the recommended spelling through the guard union.
