# Compaction-stable bootstrap lease to prevent redundant full re-bootstrap

## Description

A compaction event in the same root thread triggered a full re-bootstrap,
even though the repository, runtime, and authority digests had not
changed. There is currently no machine-readable lease that lets
compaction skip a redundant full re-check.

## Triggering situation

From a greenfield happy-path test report for pipeline version
0.6.0+codex.20260818162535.96cf805, test repo Rune_Test1_Codex_060_52,
full report at docs/pipeline-greenfield-happy-path-handover.md in that
test repo. Section 9, item P1-3.

## Affected artifact

compact/post-compact-reground hook; pipeline-start-preflight.mjs.

## Proposal

Implement a session lease produced by ready-readback that carries a
repository fingerprint, runtime readback, authority digests, and an
expiration condition; have compaction consume this lease in
machine-readable form, invalidating it only on repository change, runtime
change, drift, or explicit recovery.

Acceptance test: after a compaction event, pipeline-start-preflight is
not re-run as long as the lease and digests remain unchanged.

## Triage (filled in by the Elephant of the next Pipeline session)

- **Decision:** Accepted — fix `codex-session-start-hint.mjs`/`codex-hooks.json` to reuse `post-compact-reground.mjs`'s existing exported projection logic on `source==='compact'`; do not build a new lease schema.
- **Rationale:** PO 2026-08-18 accepted the analyst's recommendation as-is.
- **Assignment (if accepted):** Nova Wave 4 implementation.
- **Date:** 2026-08-18


## Design proposal (Wave-4 prep), 2026-08-18

*Prep material for PO triage, not a decision — a Triage section, if/when added, records the actual PO decision. Generated by a Workflow-dispatched read-only design pass (dispatch NVA-W4-DESIGN-compaction-stable-bootstrap-lease) grounded in the current repo state.*

**Problem (restated):** Backlog item pipeline.compaction-stable-bootstrap-lease (backlog/items/2026-08-18-compaction-stable-bootstrap-lease.md) reports that a compaction event triggered a full re-bootstrap even though repo/runtime/authority state hadn't changed, sourced from a Rune greenfield Codex happy-path test (pipeline 0.6.0+codex.20260818162535.96cf805). Its Proposal asks for a new machine-readable 'session lease' (fingerprint + runtime readback + authority digests + expiration) produced at ready-readback and consumed by compaction, invalidated only on repo/runtime change, drift, or explicit recovery. Its Affected-artifact list names 'compact/post-compact-reground hook' and 'pipeline-start-preflight.mjs'.

**Options:**

1. **A. Build the item's proposed lease as a new artifact/schema** — Implement a dedicated lease record (new schema, new .mjs validator alongside continuity-state.mjs) written at end of a ready bootstrap, carrying repo fingerprint (HEAD sha / manifest+plugin version), runtime readback, authority digests, and an explicit TTL/expiration condition. Wire it into both plugins/pipeline-core/hooks/post-compact-reground.mjs (Claude) and a new Codex-side equivalent, replacing/augmenting the current PCR-* projection. Impact: Gives a first-class, cross-runner, explicitly time-bounded lease concept independent of an active feature existing. Tradeoffs: Substantially duplicates machinery that already exists: plugins/pipeline-core/lib/continuity-state.mjs's pipeline.continuity.v0 object already carries revision, authority.{prd,spec,result}.sha256, and runtime.{humanFacingLanguage,activeDuty}, is CAS-protected, size-bounded (CONTINUITY_STATE_MAX_BYTES=8192), and already gets read+validated by post-compact-reground.mjs's resolveRegroundProjection() into a PCR-READY/PCR-BLOCKED/... projection on every compact SessionStart (hooks/hooks.json matcher "compact"). A second parallel schema means two places that can drift out of sync, double test/maintenance surface, and no clear reuse story. Medium-large effort.
2. **B. Fix the actual observed gap: port the existing Claude-side compact logic into Codex, don't invent a new artifact** — Root-cause read shows the reported failure is NOT a missing lease concept -- it's a missing Codex wiring. plugins/pipeline-core/.codex-plugin/hooks/codex-hooks.json routes every SessionStart source ("startup|resume|clear|compact") through one hook, codex-session-start-hint.mjs, whose main()/sessionStartDecision() never even reads the hook's stdin JSON (no source/matcher branching at all) and unconditionally emits 'run pipeline-core:pipeline-start and report the resolved Pipeline version' for a governed repo -- i.e. it actively instructs a full bootstrap on every compact too. Meanwhile Claude's own plugins/pipeline-core/hooks/post-compact-reground.mjs already exports pure, runner-neutral functions (resolveRegroundProjection, buildRegroundMessage) that read the SAME continuity state and produce a PCR-READY/PCR-BLOCKED/etc. skip-or-continue signal. Fix: give codex-session-start-hint.mjs (or a new sibling hook reusing post-compact-reground.mjs's exports) a compact-aware branch, and add a "compact" entry to codex-hooks.json's SessionStart wiring that actually runs it, mirroring hooks.json's existing Claude wiring. Impact: Closes the exact defect the Rune test reported, for the runner it was reported on, using code that already exists, is already tested (post-compact-reground.test.mjs), and is already schema-validated. SKILL.md's '## Compact' section (added 2026-08-02, commit 8b23be6d) already documents the intended behavior; this makes it actually true on Codex, not just on Claude. Tradeoffs: No explicit time-based expiration is added -- validity stays purely structural (revision/digest/featureId match via validateContinuityState), matching what Claude already has today. Doesn't help the pre-activeFeature/onboarding compaction case (resolveRegroundProjection fails closed to PCR-ACTIVE-FEATURE-INVALID when no activeFeature.id/phase exists yet) -- but that gap is pre-existing and identical on both runners today, not a regression. Small-medium effort.
3. **C. Minimal/defer: reject the new-lease framing, ship only the Codex hook-wiring bugfix, close the rest as duplicate-of-existing-mechanism** — Treat this backlog item as substantially already addressed by continuity-state.mjs + post-compact-reground.mjs; retitle/re-scope it to exactly what's missing (Codex compact wiring), fix only that, and explicitly decline to build a new 'lease' schema or TTL semantics unless a concrete future need appears (e.g. a real incident where digest-identity was unchanged but staleness still mattered). Impact: Smallest possible change and smallest new surface; avoids scope creep into a second continuity-like schema that nothing currently needs. Tradeoffs: If the PO's actual intent behind 'expiration condition' in the original Proposal was a genuine time-based safety net (protect against a session sitting compacted-but-idle for a long time while things drift in ways digests don't catch), this option doesn't deliver that and would need a follow-up item later.

**Recommendation:** Recommend B, with C's discipline about not overbuilding: fix codex-session-start-hint.mjs / codex-hooks.json to reuse post-compact-reground.mjs's existing exported projection logic on source==='compact', instead of building the item's proposed new lease schema. The item's own Proposal (Option A) is solving a problem that is already substantially solved on the Claude side by pipeline.continuity.v0 + PCR-READY; the actual bug -- confirmed by reading the code, not the item's prose -- is that pipeline-start-preflight.mjs (the other named 'affected artifact') has nothing to do with compact at all (it's plugin-distribution-identity + scratch-lifecycle housekeeping), while the real culprit, codex-session-start-hint.mjs, isn't named in the item's Affected-artifact section at all. Triage should correct the Affected-artifact scoping before assigning work. Only add an explicit TTL/expiration field to continuity.runtime (a small additive change) if the PO confirms they want time-based staleness protection beyond digest/revision matching -- don't build it speculatively.

**Risks/dependencies:** 1) Affected-artifact mismatch: neither file named in the item's own Affected-artifact section is the actual defect site for the Codex case that generated the report -- pipeline-start-preflight.mjs is unrelated to compact, and the real gap (codex-session-start-hint.mjs / codex-hooks.json) isn't named at all. Any dispatch built directly from the item's Proposal text without this correction would very likely edit the wrong files (echoes the CLAUDE.md hunt-list-contamination and stale-claim-reverification rules already in force in this repo). 2) Overlaps backlog/items/2026-08-09-codex-restart-cannot-recover-operational-context-from-its-own-prior-transcript.md, which already touches codex-session-start-hint.mjs's compact-handling gap from a different angle (the PRIOR_ROLLOUT_TRANSCRIPT_LINE addition) -- worth sequencing or combining rather than two separate dispatches editing the same file's compact path. 3) guard-lifecycle-ready.mjs (2561 lines, no 'compact' handling found) re-derives readiness fresh from disk on every guarded tool call rather than caching a 'bootstrap done' flag, so a redundant full re-bootstrap is a wasted-tokens problem, not a correctness/gate problem -- this bounds the urgency and the blast radius of getting the fix wrong. 4) Whatever ships should stay inside continuity-state.mjs's existing CAS/schema discipline (pipeline.continuity.v0, CONTINUITY_STATE_MAX_BYTES=8192) rather than inventing a parallel one, per this repo's evident pattern of one canonical state object.

**Estimated complexity:** small
