# agent-obligations section 1 says "No `&&`" while the guard admits up to six `&&` segments

## Description

`templates/prompts/agent-obligations.md` section 1 states "No `&&`, no `;`, no redirects". `guard-lifecycle-ready` actually admits up to 6 `&&`-chained segments when every segment is itself an admitted read-only shape (its own refusal text lists this). The doc is stricter than the guard, so agents avoid a valid form and the document is a second, drifting copy of a rule the guard owns.

## Triggering situation

Noticed while reading both during the 2026-10-05 session. Section 1 is marked hand-maintained because no component exports the grammar as data.

## Affected artifact

`templates/prompts/agent-obligations.md` (generated by `harness/scripts/generate-agent-obligations.mjs`), `plugins/pipeline-core/hooks/guard-lifecycle-ready.mjs`.

## Proposal

Edit the generator source text to match the guard ("one simple command per call; up to 6 `&&` segments only when every segment is an admitted read-only shape"), regenerate the file, keep the byte-equality test green. Better: export the grammar bounds from the guard so the section is derived rather than hand-written.
