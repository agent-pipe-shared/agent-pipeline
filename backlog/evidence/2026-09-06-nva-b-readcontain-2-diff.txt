    fix(guard-lifecycle-ready): admit two session-derived read exception roots
    
    NVA-B-READCONTAIN-2 (backlog: 2026-09-01-read-containment-was-removed-a-
    day-after-it-was-added-with-no-recorded-decision.md). NVA-B-READCONTAIN-1
    restored project-root read containment but left one legitimate need
    unmet: an agent's own session transcript and per-session memory
    directory are always outside the project root by construction.
    
    Adds exactly two new admitted read roots, resolved from the PreToolUse
    hook's own `input.transcript_path`, never guessed or pattern-matched:
    
    1. The transcript file itself (`input.transcript_path`), realpathed via
       a new claudeSessionTranscriptFilePath(), admitted as an EXACT
       single-file match only -- never a directory-prefix admission.
    2. `dirname(transcript_path)/memory/`, via claudeSessionMemoryDirectory()
       (MEMPATH-1), reused directly rather than re-derived a second way.
    
    Both flow through the same realpath-safe containment discipline
    (isRealpathedWithinBoundary / rawReadCandidatePath) NVA-B-READCONTAIN-1
    hardened -- no new lexical-only check.
    
    Threaded an optional `extraRoots` parameter (default `[]`, additive to
    BOUNDED_PIPELINE_ADDITIONAL_ROOTS, so every pre-existing call site is
    unaffected) through isReadOnlyDiagnosticCommand and its own internal
    composition: isBoundedReadOnlyAndChain/isChainSegmentAdmitted (the `&&`
    chain recurses into isReadOnlyDiagnosticCommand itself), the git-pipeline
    call, isReadOnlyDiagnosticCommandWithTrailingStderrRedirect, and
    retryActionsForDeniedCommand (a different question -- per-segment
    read-only classification for typed retry hints -- answered at a call
    site that also has `input` in scope). sessionRoots is computed once in
    evaluateLifecycleReadyGuardCore (Bash-only) and passed at the two
    input-bearing call sites.
    
    Deliberately NOT threaded, each for a traced reason rather than a guess:
    - gateStrengthShellRefusal / rebaseAuthorityShapeRefusal (both inside
      evaluateAfterGrammarAdmission, reached only after the primary
      isReadOnlyDiagnosticCommand fast path already returned false for the
      identical command/root -- by determinism, threading here can never
      observe a different result).
    - isForbiddenCrossRepositoryMutation's `git -C` branch -- that branch's
      containment question is answered by subcommand trust alone, never by
      any root set; a plain single-command read never reaches its
      mutatingTargets branches at all.
    - isOutsideRootSingleCommandRead / isOutsideRootBoundedDiagnosticRead --
      denial-code classifiers only, reached only once the command is already
      refused; their own self-lift widening already makes the "shape-only"
      question independent of which roots are in scope.
    - guard-command-grammar.mjs's rg-to-rg/rg-to-head bounded pipeline --
      lexical containment only (`pathInside`, no realpath); widening it here
      would reintroduce exactly the lexical-only shortcut
      NVA-B-READCONTAIN-1 closed.
    - isBoundedCatPipeline -- would need a three-function signature change
      not required by this task's DoD wording.
    
    Tests: 4 new (transcript-file admission, memory-dir admission, a sibling
    negative case proving the exception stayed narrow, and a symlink-through-
    memory-dir regression mirroring dotdotThroughSymlinkFixture). Reproduce-

    negative case already passed pre-fix, as expected). Full suite green

+function claudeSessionTranscriptFilePath(input, dependencies = {}) {
+  const transcriptPath = input?.transcript_path;
+  if (typeof transcriptPath !== "string" || transcriptPath.trim() === ""
+    || transcriptPath.includes("\0") || !isAbsolute(transcriptPath)) return null;
+  const realpath = dependencies.realpathSyncFn ?? realpathSync;
+  const statFn = dependencies.statSyncFn ?? statSync;
+  try {
+    const real = realpath(transcriptPath);
+    return statFn(real).isFile() ? real : null;
+  } catch {
+    return null;
+  }
