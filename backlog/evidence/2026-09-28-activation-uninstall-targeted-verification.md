## Reproduced Git-hook lifetime defects

Actual terminal `d76c16` exited 0. Its child error/signal fields were independently
checked: all null. Only temporary local repositories and an owned library copy
were modified; no real user cache, global settings or remote push was touched.

- **Reset interaction:** The three canonical installers and canonical digest-bound
  reset apply ran. Reset removed the private implementations while retaining all
  three executable shims. A subsequent real Git commit failed with
  `MODULE_NOT_FOUND`. Reset also removed ownership records, preventing ordinary
  removers from recognizing some surviving shims. Correct removal must precede
  private-state deletion and preserve genuinely foreign hooks.
- **Install-time path lifetime:** A commit-msg hook accepted its message with a
  controlled current library copy (exit 0), then failed after that owned copy was
  removed (exit 1). The canonical remover still succeeded while ownership metadata
  existed. This confirms the dependency mechanism; actual runner cache pruning
  and global-uninstall behavior remain unmeasured.

The first workspace-bound probe had EPERM/timeouts and is not counted as a
