    fix(guard-git): scope GG-22's pathspec fast path to flags proven exclusive
    
    fe2d7afe (NVA-B-GG22FIX-1) scoped GG-22's status-flip-debt check to an
    explicit `--` pathspec to fix a real deadlock, but assumed that pathspec
    is ALWAYS the commit's whole content. True for a plain `-F <msg> --
    <paths>`; false for `-i`/`--include` (stages the pathspec paths IN
    ADDITION to whatever is already staged, then commits the whole staged
    set) -- a pathspec'd `-i` commit with an unrelated disallowed path
    already staged was admitted where the pre-fe2d7afe full-index check
    would have refused it. Confirmed reachable by a T1 Critic review
    (backlog/evidence/2026-09-06-nva-b-gg22fix-1-findings.md F1).
    
    Default to the full `git diff --cached` check (fail closed) unless the
    flag set on this invocation is KNOWN, from git-commit(1), to keep the
    pathspec exclusive: message/authorship/signing/display metadata only
    (-o/--only, -s/--signoff, -e/--edit, -n/--verify, --allow-empty(-message),
    --reset-author, -v/-q, -S/--gpg-sign, --author, --date). Any other token
    (-i/--include, -a/--all -- undocumented interaction with a pathspec,
    -p/--patch/--interactive -- interactive, --amend -- rebases onto a
    different parent) falls through to the full index check, never assumed
    safe.
    
    Also fixes F3: the disallowed-path filter compared a pathspec token's
    literal string prefix against `backlog/items/`/LEDGER_PATHS without
    normalizing `../` segments, so `backlog/items/../../src/x.js` passed the
    prefix check while git resolves it outside `backlog/`. Each pathspec
    token is now lexically normalized (pure string `.`/`..` segment collapse,
    no filesystem access) before the disallowed check.
    
    Reproduced RED (against a scratch snapshot of the pre-this-fix code) then
    GREEN via scratch/gg22fix-2-repro.mjs, captured durably this round per F5
    (backlog/evidence/2026-09-06-nva-b-gg22fix-2-{red,green}.txt) -- unlike
    round 1's citation of gitignored paths. Full guard-git.test.mjs regression
    (232/232) and check-consumer-safe-paths.test.mjs (9/9) captured alongside.
    
    F2 (no committed permanent regression test, TP-1 blocks guard-git.test.mjs
    in-session) and F4 (tokenizer used outside its documented single-segment
    contract) remain open, tracked separately, unchanged by this dispatch.

+/**
+ * normalizePathspecLexically(token) -- pure STRING segment collapse for a `--` pathspec
+ * literal (GG-22's own fast-path exclusivity question, NVA-B-GG22FIX-2 F3, backlog/evidence/
+ * 2026-09-06-nva-b-gg22fix-1-findings.md). No filesystem access -- `existsSync`/`realpathSync`
+ * resolve a REAL path on THIS machine, which a pathspec literal being compared against a
+ * `backlog/items/`/LEDGER_PATHS string prefix is not. This applies the same `.`/`..` segment
+ * arithmetic git itself uses when resolving a pathspec, on the string alone: a `.` segment is
+ * dropped; a `..` segment pops the previous segment, or (for a relative token with nothing left
+ * to pop) is kept literally -- an escape past the pathspec's own root, which then correctly
+ * fails every `backlog/`-prefixed check below instead of silently stopping at the root the way
+ * a filesystem `path.resolve` would.
+ */
+function normalizePathspecLexically(token) {
+  const isAbsolute = token.startsWith("/");
+  const out = [];
+  for (const segment of token.split("/")) {
+    if (segment === "" || segment === ".") continue;
+    if (segment === "..") {
+      if (out.length > 0 && out[out.length - 1] !== "..") out.pop();
+      else if (!isAbsolute) out.push("..");
+      continue;
+    }
+    out.push(segment);
+  }
+  return (isAbsolute ? "/" : "") + out.join("/");
+}
