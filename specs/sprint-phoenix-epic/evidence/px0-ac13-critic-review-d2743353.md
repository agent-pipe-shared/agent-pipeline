### F1 — The host-attested spawn re-derives the boundary from environment labels and never delegates; a sandbox-resident invocation still issues the doomed network call

**Gap.** `createWslHostAttestedSpawn` does not use the selected host transport. It spawns `/usr/bin/git` **in the calling process's own sandbox** with a sterile environment after a Codex App-Server health check, and the decision to take that path comes solely from `WSL_DISTRO_NAME`/`WSL_INTEROP`/`CLAUDECODE` — never from the preflight-selected boundary binding. The App-Server health probe is a local exec plus control-channel read, not a network operation, so it cannot discriminate "running at the selected network-open boundary" from "running in the network-denied workspace sandbox".

**Risk.** In exactly the situation PX0-AC-13 governs — the CLI invoked inside the network-denied Codex+WSL workspace sandbox — attestation succeeds and the `git ls-remote` is issued and fails: the known-failing sandbox attempt is consumed, and the result is a generic `status: "unknown" / reason: "remote-unavailable"`, indistinguishable from a genuine remote outage. The criterion's guarantee is not established by the code. Severity: **major**.

**Evidence.**
