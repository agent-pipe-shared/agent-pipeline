# Reusable consumer Critic consent wiring

The PO requires the standing project/service consent mechanism to work in
consumer repositories, not only a Nova scratch coordinator. A selected normal
review inside the stored scope must reuse that attributed consent. A changed
candidate is not by itself a new human decision. Foreign projects, new
recipients, expanded source roots and excluded content are not silently
authorized. The Nova grant is never copied into consumer projects.

## Required delivered behavior

Wire the existing exported native Critic host entry itself to a reusable
consent admission helper before any candidate-bearing child execution.
Resolve the saved scope through the existing physical-project private state
reader. Normalize the already bound source/evidence reference records into
the existing consent invocation shape, validate their real bytes, and check
the actual stored decision. Use the declared selected OpenAI/Codex service;
never infer or fabricate a verified endpoint from a model identifier. Existing
selection, route, sandbox, candidate, source and preflight checks remain in
force. No generic transport fallback or host approval bypass is introduced.

The host must retain a structured consent coverage/disclosure result alongside
execution evidence. Missing, revoked, mismatching or stale consent must prevent
child creation with a concrete diagnostic. Explicit external host/provider
denial remains denial. A coverage result is not a host permission grant.
Do not ask for another decision when the stored scope covers a fresh candidate
and its selected records. Do not emit an invented decision or write consent
as a side effect of review admission.

The installed consumer instructions must point to this real shipped admission
path. A helper that remains unused by the public host, or instructions to copy
a Nova scratch script, do not fulfill the contract.

## Verification boundary

Extend the existing native-host/consent suites with an actual consumer Git
fixture separate from the plugin source. Verify one grant covers successive
candidates; absence/revocation/project or service mismatch/content drift
prevents child creation; the host's existing sandbox/selection checks still
run; external denial is not relabeled as coverage or permission. No real
provider run is needed for these deterministic regression tests.

This package does not widen the closed native range API. It must not claim
that read-only sandboxing hides prior verdict files or that a current-artifact
review fulfills a correction-only review. The separate exact-range and
coordinator-lineage obligations continue to apply. Do not add a broad history
read or prior-verdict reference while implementing consent reuse.

Host protocol and protected-preimage changes must follow the existing repair
path. Do not alter protected hashes in the same implementation dispatch or
weaken tests to make admission appear green. The coordinator retains final
independent review, protocol transcription where required and full Verify.
