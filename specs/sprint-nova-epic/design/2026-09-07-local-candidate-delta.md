and receives runner-specific build metadata. Publication and pushing are outside
this delivery. D.2–D.6 follow the test candidate and remain required for 0.6.2.

  model and effort. Generated compatibility projections must agree with it.

  configuration alone does not prove effective execution identity.

## Greenfield authoring and recovery

- A fresh consumer can retain its original requirements, collect missing setup
  answers together, generate PRD/spec scaffolding, author those generated paths
  and keep bounded temporary notes while bootstrap binding is pending.
- Original material, setup settings and recovered summaries remain distinct.
  Preserve original bytes and capture order; never present a recovered summary
  as a verbatim user quotation. Use source pointers and collect specific unresolved
  confirmations where original material is unavailable.
- Concurrent real session-capability probes must not report missing capability
  merely because another valid probe publishes or retires its descriptor.
  Remove only owned temporary artifacts and empty directories; preserve foreign
  state and genuine permission, identity and path failures.
- Scratch admission at intended onboarding stages retains traversal, symlink,
  authority-path and readiness boundaries. It does not authorize implementation
  before the actual human plan-approval gate.
- A native multi-file patch through the guard chain must admit legitimate
  generated document and scratch authoring. Validate this with a genuine generated
  intake checkpoint and real session probes; disclose any simulated host boundary.
  A fixture result must not be reported as a completed live user-session run.
- `GUARD-LIFECYCLE-NOT-READY` is nonliftable, alone or in a mixed denial set.
  Neither a new override plan nor a previously armed capability may bypass it.
  Preserve legitimate override ceremonies for other eligible denial classes.
- Recovery output states the failed ability and a usable next action or technical
  repair requirement. Repeating an unchanged inspection is not represented as a
  repair. Nonliftable failures offer no signing ceremony. Keep diagnostics bounded
  and distinguish plugin output from host rendering of the original tool request.
- Follow onboarding's current returned action. Do not insert later state or
  authority-orientation steps as unreachable pre-binding prerequisites.
