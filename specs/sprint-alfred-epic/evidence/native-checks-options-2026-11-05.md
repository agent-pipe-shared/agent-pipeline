# Native authority checks on Windows: what each protects, what it costs, what alternatives give up

Slice C19H-NATIVE-OPTIONS, criterion AC-108 (fresh bounded attempt), 2026-11-05. Options analysis only: no code changed. The document is result-neutral: no ordering of the options is implied and no option is recommended; the Elephant writes the recommendation afterwards.

Evidence legend. `[R]` = I read the cited file:line this session. `[I]` = inferred from what I read, not observed or measured. `[M]` = a number measured on Windows by the 19g run (candidate-19 plan, section "Windows measurement of 19g", lines 374-385). All paths are repository-relative; `lib/`, `hooks/` and `scripts/` below are `plugins/pipeline-core/lib/`, `plugins/pipeline-core/hooks/` and `plugins/pipeline-core/scripts/`.

## Scope and threat model

Scope: every per-operation native authority check that runs on Windows during (a) a Goldfish dispatch admission (`hooks/guard-dispatch.mjs` lines 1104-1119 calls `prepareNativeGoldfishHostState`; the registry part is `publishNativeAuthorityState`, `lib/native-goldfish-host-state.mjs` lines 824-921), (b) a SubagentStop host commit (`readNativeGoldfishPending`, same file lines 427-437, which for item deliveries enters a registry boundary at line 597) and (c) an override-eligible refusal (`hgoPlanningPublication`, `lib/human-guard-override.mjs` lines 6003-6026, reached from the record-denial path at lines 3949-3951).

Cost unit [M][R]. One native operation is one `powershell.exe` start (`lib/windows-owned-authority-backend.mjs` line 187, `spawnSync`, `-NoProfile`), about 470 ms. A warm admission runs about 145 of them (108.8 s, 110.7 s, 113.3 s); an eligible refusal about 107 (57.5 s warm, 107.5 s cold), almost all between the progress marks `hgo-publish-wait` and `hgo-publish-held` (`lib/human-guard-override.mjs` lines 3949 and 3951). Hot sites [M]: `lib/session-authority-registry.mjs` line 565 (`registryClosure`, 37 inspect calls, 18 s), line 380 (`installedSourceSha256`, 19 read-source calls, 9.5 s), `lib/session-authority-domain-owner.mjs` line 60 (`observedChain`, 15 ancestor calls, 7.5 s). Arithmetic caveat [I]: 145 x 0.47 s is about 68 s, but the warm admission took 108.8 s to 113.3 s, so about 41 s to 45 s of the admission is not explained by native spawns in the measurement. The refusal figure is consistent (107 x 0.47 s is about 50 s against 57.5 s warm).

Threat model, stated by the PO (German, verbatim): "Wir wollen hier nur den agenten einsperren mit der pipe nicht den human etc". In English: the pipeline confines the agent, not the human. The same rule is recorded as `guardrails/security.md` SEC-10 (lines 165-189). The agent and the human normally run as the same operating-system user on the same machine. Consequence, read into every row below: a check that compares the owner or an access-control entry with the current account passes for the agent by construction, because the agent is that account (`docs/adr/draft-windows-host-acl-boundary.md` lines 17-20 says the same: owner ACLs cannot tell a human from an agent under the same principal). A check is only protecting against the agent when some agent action can change the checked object: a tool call, a shell command, a file write through the runner, a process the agent spawns. I did not find, in the guard files I searched, a tool guard that names `.git/agent-pipeline` as a protected write path [I: the search was incomplete, see Open questions 5]. The layers I did read are the closed shell grammar (`templates/prompts/agent-obligations.md` section 1: one simple command, no redirects, no `;`) and the briefing rule that `.git/` is never a working location.

ADR provenance. I found no numbered ADR in `docs/adr/` that introduces the native owned-authority layer. What governs it, and what I cite: `docs/adr/draft-windows-host-acl-boundary.md` (PO direction D145, status proposed: ordinary host, project and plugin paths are observed and hashed but not gated on owner or ACL; strict checks stay for Pipeline-owned private authority, lines 22-34); the D145 row in `specs/sprint-alfred-epic/plans/po-decisions-2026-10-25-fix-wave.md` line 10; the PO decision of 2026-10-17 that directories strictly above the repository root or plugin root are human-controlled (comments at `lib/session-authority-domain-owner.mjs` lines 64-67 and 103-107); the K12 lock comment (`lib/session-authority-registry.mjs` lines 238-243); and the PF-86 lock-free read comment (same file lines 350-353).

What one native operation checks (the shared part of every row) [R]. The PowerShell helper (`lib/windows-owned-authority-native.ps1`) opens the object by handle (`Open`, line 139; read-share only, so a concurrent delete is refused) and calls `Verify` (lines 146-155): not a reparse point, file-or-directory kind as asked, link count exactly 1 for files, `GetFinalPathNameByHandle` equal to the requested canonical path (alias check), a non-empty security descriptor. For private authority (`privateOnly`, the default for `inspect`, `read`, `publish`, `remove`, `create-directory`) it also requires: owner equals the current account's SID, the DACL is protected (not inherited), and every ACE is an allow entry for the current SID; below a `.git\agent-pipeline` root, inherited ACEs are tolerated (lines 145 and 152). The returned "facts" string joins volume, file index, links, attributes, size, creation and write time and a SHA-256 of the raw security descriptor (line 153). For non-private operations (`ancestor`, `ancestor-above-root`, `read-source`) the owner and ACE conditions are skipped but the descriptor is still hashed into the facts (comment at line 144).

## Options

Every estimate is an estimate [I] derived from the three hot-site counts and the code read above; nothing here has been run on Windows. "Natives after" is a count of PowerShell starts, relative to 145 (admission) and 107 (refusal). The options are not exclusive and no combined figure is given. Two facts that bear on several options:

- Caching already exists in part [R]. `lib/windows-owned-authority-backend.mjs` keeps an in-process memo (lines 60-66, 159-180) and, since commit 49cb6468c (an ancestor of the measured stamp 5412f8937 [R: git ancestry and the string `PERSIST_SCHEMA` present in that stamp]), a cross-process memo file (lines 66-137). A hit still costs one `lstat` and requires the object's identity (volume, file index, mode, links, size, mtime, ctime, birthtime; line 147) to equal the stored one. The cross-process file accepts only results whose `bytes` field is a string no longer than 24576 base64 characters (`persistedValueShape`, lines 87-91; cap at line 77). `inspect`, `ancestor` and `ancestor-above-root` return `bytes` null (helper lines 243, 256-258) [I: read, not run], so the two hottest sites C3 and C6 are never persisted across processes. A source file above about 18 KB raw is never persisted across processes. I sized three participant sources (`wc -c`: `session-authority-domain-owner.mjs` 69,182, `native-goldfish-host-state.mjs` 180,051, `human-guard-override.mjs` 382,385 bytes), all far above that; the other 20 were not sized. Those large ones are therefore answered by the per-process `sourceDigestMemo` only (registry lines 375-381).
- A lock-free read path already exists [R]: `withSessionAuthorityReadScope` (registry lines 350-365) reads a generation digest before and after and refuses `read-generation-drift`. It has one production caller, the admission prescan (`lib/native-goldfish-host-state.mjs` line 1771, called from line 850).

### O0. Doing nothing

What changes: nothing. Natives after: 145 / 107. Gives up: nothing; all protections in the table stay. Consequence [M]: warm admission stays at 108.8 s to 113.3 s against the 60 s threshold named in the plan; the registry lock stays held across long multi-operation windows against a 1.5 s wait bound, so the second launch in one reply and the SubagentStop host commit keep losing (plan lines 378-379). The independent PO-decided work (lock retry at the site that refuses; stop-side holder evidence, plan line 385) is unaffected by this choice. Cost to build: none.

### O1. Check only the directory roots instead of every path

Two distinct readings, which can be taken separately.

O1a, ancestors: observe natively only the boundary roots (repository root, plugin root, the `.git\agent-pipeline` root) and take intermediate components from the JS lstat alone. Removes most of C6. Natives after: about 130-135 / reduced by the refusal's share of C6 (not itemised). Gives up: detection of an alias that lstat cannot see on an intermediate directory: a short-name (8.3) spelling, a case alias, a substituted or mapped drive, or an empty security descriptor. Concrete undetected agent action: `subst` or a mapped-drive/short-name spelling of an ancestor that makes the path resolve to a different directory while the JS lstat of each component looks like a plain directory [I]. A junction on an intermediate component would still be caught by the JS lstat if Node reports junctions as symlinks [I]. Components above the roots are already declared human-controlled (domain-owner lines 64-67), so what leaves is reparse and alias observation for them. Cost: small code change in `observedWindowsChain` (domain-owner lines 78-87); test restatement; Windows requalification.

O1b, registry closure: inspect natively only the directories in the closure walk and leave the files to the `read` that every indexed record already gets (C3 versus C4). Natives after: 145 minus the number of file entries in the 37. If the 37 hold about 10 directories, about 118 / unknown for the refusal. The directory/file split of the 37 is not in the measurement. Gives up: the second observation of each indexed file at the end of the walk, and the owner/ACL/alias check of any non-indexed file that the walk would have inspected before reading it (unknown entries still fail on name, via the JS listing). Concrete undetected action: a non-lock-honouring process replacing or re-ACLing an indexed record after it was read and before the boundary ends, where the decision does not write that record (a written record is covered by the publish compare-and-swap, helper line 208). Cost: small in `registryClosure`; the failing-closed "unknown entry" branch needs a native observation of unknown files kept.

### O2. Inspect before the registry lock, hold the lock only for the write

What changes: run the read-heavy work (the 12-producer baselines, closure, source digests, the dependency and collision reads) before `withSessionAuthorityBoundary`, as an optimistic snapshot guarded by the catalogue generation (`withSessionAuthorityReadScope`), and take the lock only for a short re-validation plus the reserve/advance/publish writes. Precedent in the code: the PF-86 prescan (host-state lines 846-850, 1771). Rows touched: C8 hold time (not count), C3, C5, C7, C9 move outside the lock. Natives after: about the same, plus the re-validation under the lock (about +5 to +15 [I]); the lock hold shrinks from the whole lock-held section (host-state lines 852-920) toward the measured reserve-to-done window of 14.4 s [M] as a lower bound for the hold. Gives up: nothing in detection if the re-validation compares the generation and each decision's inputs; the exposure is the gap. Concrete undetected action if the re-validation is incomplete: two parallel launches both pass the write-scope collision check (host-state lines 883-899) against a stale snapshot and both reserve overlapping scopes. Cost: medium to high: every `stateRead` caller (48 call sites in the registry [R: count]) must say whether it runs under a snapshot, the in-boundary native witnesses (registry lines 98-105) are per-boundary and would need a read-scope equivalent, and the stop path (line 597) would need the same split. Directly targets the lock-contention symptom, not the per-operation cost.

### O3. Cache verified identities per process or across processes

What changes: extend what the memo covers. Per process: already built for all read-only operations. Across processes, three gaps [I]: (i) persist `inspect`, `ancestor`, `ancestor-above-root` results (no bytes), (ii) persist a digest instead of bytes for `read-source` so the 23 source files stop being re-read, (iii) keep entries across registry writes where the identity of the object itself is unchanged. Rows touched: C3, C5, C6. Natives after: warm run about 95-130 / less for the refusal; the registry's own records change identity on every dispatch (mtime and ctime move), so the unchanged share of the 37 is unknown. Gives up: a hit trusts the `lstat` identity instead of re-observing owner, descriptor and final path. Concrete undetected action: any change to the descriptor or alias that leaves volume, file index, mode, links, size, mtime, ctime and birthtime equal, or an entry forged in the memo file itself (it lives under `%LOCALAPPDATA%\agent-pipeline`, written by the same account that runs the agent, backend lines 81-86, 124-125; file mode bits are not meaningful on NTFS [I]). The module's own comment (lines 70-75) states the intended bound: a stored entry is only a longer-lived copy of the same trust. Cost: small to medium (value shape, size cap and key changes in the backend; invalidation rules around writes; native test for ChangeTime moving on a descriptor change [I: unverified]).

### O4. Batch native operations into one helper call

What changes: new helper operations that take a list (inspect-many for a directory listing, ancestor-chain for a path, read-source-digests for the 23 files) and return one array, running the same `Verify` for each item inside one PowerShell start. Rows touched: C3, C5, C6, and the read bursts of C4 and C7. Natives after: about 10-30 / about 15-35 [I]; the figure depends on how much of the 470 ms is process start and type-cache import rather than the per-object work (Open question 2). Gives up: by construction nothing, if every per-item check is kept in the helper. Differences: one failing item fails the whole call (the failure envelope names one path, backend lines 190-191), and the observations of N objects fall into one short window instead of 37 sequential spawns. Cost: high. The helper source changes, so the pinned `HELPER_SHA256` (backend line 12) and the byte-identical copy contract with the second native helper (helper line 5) must be re-pinned; input is capped at 1.5 MB and output at 1.6 MB (backend lines 183, 187), which a batch of whole source files exceeds, so digests must be computed in the helper; the callers are synchronous loops with per-item control flow (`registryClosure`, `observedWindowsChain`, `readAuthorityNamespace`) and need two-phase restructuring; native Windows requalification.

### O5. Drop a check whose adversary does not exist under the threat model

Candidate checks, each with what leaves:

- O5a, owner = current SID, protected DACL and allow-only-current-SID ACEs for private authority (helper line 152). Adversary: another local account. Same-user: absent for agent and human (the check passes for both). Dropping it alone saves no spawns, because the spawn is still needed for handle custody and the alias check. Gives up: detection of a different local account (or inherited ACEs from a data drive, the original greenfield blocker) having write access to the private registry. D145 already took this step for ordinary paths and kept it for private authority (draft ADR lines 22-34), noting it as "a separate, narrower guarantee" (line 20). Cost: small, but it is a PO scope decision; whether SEC-10 covers another local account is Open question 6.
- O5b, drop the descriptor hash from the facts string. Gives up: an ACL change no longer moves the facts that compare-and-swap and the witnesses use. Saves no spawn.
- O5c, drop the native layer for private reads and inspects altogether and use Node (`lstatSync` bigint identity, `realpathSync.native` for the final path), keeping native only for create, publish and remove (lock and record writes). Natives after: about 15-25 / unknown [I]. Gives up: the owner and descriptor facts (O5a and O5b), the no-delete-share custody handle during a read (a concurrent delete or replace during the read is then caught only by comparing lstat before and after plus the hash), and the refusal of a reparse point at open time (Node's `O_NOFOLLOW` is not available on Windows, which the code acknowledges with `constants.O_NOFOLLOW ?? 0`, host-state line 136 [I]). Concrete undetected action: a same-user process swapping a record for a junction or hard link in the instant between lstat and read. The POSIX branches (registry line 141, domain-owner lines 122-131) cannot be reused as they are because their mode-bit tests (`mode & 0o077`) do not describe NTFS [I]. Cost: medium; new Windows `owned` semantics; native Windows requalification.
- O5d, drop the second observation of already-read files in the closure: this is O7.
- O5e, drop the identity spawn per lock attempt (C8) by recording the owner's start time without a PowerShell start. Gives up: dead-owner detection on Windows (`judgeSessionAuthorityLockOwner`, lines 207-216) falls back to `unknown`, which waits instead of retiring a dead holder.

### O6. Cheaper spawn (found while reading; not in the briefing's list)

The cost unit is the PowerShell start, not the checks (the checks are microseconds of Win32 calls [I]). Variants:

- O6a, one helper process per hook process: keep a PowerShell started once and send requests over its standard input. Natives after: about the number of hook processes in a dispatch (single digits [I]) / the same. Gives up: nothing in the checks; adds a resident process the agent could kill or crowd, and a request channel to authenticate. Cost: high; the callers are synchronous (`spawnSync` today) and a resident helper needs synchronous pipe I/O or an async rewrite; new hang and timeout behaviour (15 s per operation today, backend line 187).
- O6b, precompiled small executable in place of PowerShell plus `Add-Type`: same checks, a much shorter start [I: typical native process start is tens of milliseconds; not measured here]. Gives up: the property that the helper is plain, reviewable script text hashed before it runs (backend lines 26 and 187 execute the measured source bytes); an executable needs its own pin and build chain. Cost: high; a build and distribution route for a Windows binary does not exist in this repository [I].

### O7. Reuse the in-boundary witness instead of a second inspect

What changes: in `registryClosure`, skip the native `inspect` for a path that already has a native witness in this boundary from a `read` (the witness map at registry lines 98-105 holds the facts).
