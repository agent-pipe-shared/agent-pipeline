## Purpose/authority boundary

Registration's purpose:'advisor' is controller-local state. The namespace and registered root gate enforce the selected Advisor process location at creation, and the generic journal binds receipt ID, repository fingerprint, dispatch, candidate and request. Purpose is not a durable field of intent, and verifyRegisteredCodexOwnership has no expected-purpose field. The transcripts record purposePersistedInIntent:false explicitly. Root registration must be reconstructed by a trusted controller on re-entry; a receipt or namespace spelling alone cannot attest the original registered purpose or export decision.

The synthetic Git-common coordinate is an explicitly supplied fixture directory, not repository discovery or live Git authority. The callback approved/refused values are controlled protocol-test decisions, not an observed real host export capability. Session/model/configuration responses are produced by the Node fixture. This proves actual process namespace admission plus generic input ordering/shutdown/ownership composition; it does not qualify an ordinary Advisor recipe, actual model identity, Advisor host record/store transaction or native Codex run. Raw output custody and explicit StdioStatus remain outside the tested contract.
