Question/evidence content is transient in request construction; durable records
contain hashes and public repository paths only. Evidence digest preserves the
existing lifecycle bundle envelope including exact content and byte lengths.
The first prototype used a different serializer and therefore a different hash;
independent physical-bundle parity exposed it. The current request now uses the
canonical advisoryEvidenceBundleSha256 API and shares the pre-read public path
policy with the bounded reader. Both binding source reads use that reader.
Recipe digest includes instructions, dispatch, reason/profile, selected route,
question/evidence digests and output schema. Request digest matches the generic
host's JSON.stringify({model,effort,prompt,outputSchema}). Answer digest hashes
the exact decoded answer UTF8 bytes; response digest hashes the canonical parsed
structured report, not the original wire JSON serialization. Native raw-output
custody remains to be connected by the actual execution adapter.

The current generic journal requires a drh_ host ID. That lexical prefix is not
a Readiness qualification; the Advisor record schema and public receipt ID are
separate. Session and model-control booleans in process fixtures are synthetic
contract data. Their tests prove no actual model or Advisor execution.

## Remaining ordered implementation

1. Integrate the prepared model-free admission seam with real readiness, physical
   repository consent, host-owned export decision, candidate/route capability
   and metadata bindings. No prompt factory, content copy, provider or launcher
   before admission; declined/denied means zero calls and terminal no-child.
   Per-operation deadline/AbortSignal bounds async observations; no retry or
   late continuation occurs. Noncooperative or blocking synchronous callback
   work is not forcibly stopped; these dependencies must remain model-free.
2. Resolve the actual functional Advisor recipe using the registered resolver;
   current default is gpt-6-sol/max/host-consult. The prepared request accepts
   trusted resolver context but does not establish its provenance. Current
   registry/agent documentation still describes selected-sandbox isolation;
   tool-free host-observed assurance requires an explicit applicable contract.
3. Connect runIsolatedStructuredHost, managed ownership and this Advisor store
   through a sealed ordinary adapter. Reobserve admission immediately before
   input, validate actual strict answer and raw-result custody, recheck physical
   evidence/candidate and persist only after independent ownership readback.
4. Wire answered bridge/coordinator and private design-advisory transaction
   verification. The current prepared binding checker still receives governed
   question/package/demand/route from its private caller; live entry must derive
   them itself, including independently configured host executable selection.
   A journal may not choose the verifier's expected executable: its recorded
   digest must match independent host selection and a second current-file check.
   The Node test binary is synthetic; the live adapter selects actual Codex.
   A caller-returned expected object is never a substitute. Seal
   the store/provider dependencies; dependency injection in these scratch
   fixtures is not an externally admitted capability.
5. Persist the actual consult attempt only when execution really occurred;
   preserve governed no-child outcomes for admission/capability refusal. Produce
   the ordinary valid Advisor recipe and receipt, not a Readiness report.
6. Integrate/register these source surfaces and threat/architecture contract,
   then run actual admitted Codex/WSL replay on the frozen candidate and installed
   plugin. Canonical Verify, Critic and release stamps remain separate gates.
