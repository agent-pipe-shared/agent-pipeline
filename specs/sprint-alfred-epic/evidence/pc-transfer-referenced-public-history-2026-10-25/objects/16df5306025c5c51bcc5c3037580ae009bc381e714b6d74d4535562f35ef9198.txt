real test surface. There are no scratch paths in the test postimage. All new

## Seven cases and stronger no-write checks

- Missing binding refuses without creating the private namespace or identity.
- Legacy v1 refuses without migration or changed file bytes/identity.
- A real sanctioned v2 mint occurs only in explicit fixture setup; repeated pure
  reads return its stable fingerprint without rewriting/replacing its binding.
- Closed v2 validation rejects missing fingerprint, unknown extra field,
  malformed fingerprint, single-element array coercion, self/duplicate aliases,
  invalid epoch and unknown schema; rejected bytes remain unchanged.
- Root/file symlink aliases, multiple hard links and permissive file mode refuse.
- A physical 65537-byte oversized binding refuses with exact bytes retained.
- A linked worktree observes the shared Gitcommon identity; bare repositories
  remain unsupported and acquire no private namespace.

For legacy, valid, malformed and oversized binding cases, the adapted assertions
also compare dev/ino/mode/uid/nlink/size/mtime/ctime before and after. Read-induced
atime is deliberately excluded. This detects a replacement or same-byte rewrite;
it does not claim to audit every possible temporary syscall.

Two adaptation defects were found by early focused runs: a local `path` field
shadowed the canonical path import, and token replacement matched `linkSync`
inside `symlinkSync`. Both were corrected in this owned preparation. Final helper
bindings are separate and the final nine cases pass; the getter was not edited.

## Execution limits

The loader overlays only the exact proposed test and final getter at their
canonical module URLs. All other dependencies and all physical Git/filesystem
operations remain canonical/native. No filesystem provider substitution,
production observer API, global monkeypatch or VM translation is used.

This is an import-hook source-test run with synthetic temporary repositories,
not installed-native-host acceptance, full-suite qualification, authority minting
on a read, model execution, signing or productive integration. The registration
patch depends on the separate getter source patch; applying only this test patch
to unmodified HEAD would leave the new export unavailable.
