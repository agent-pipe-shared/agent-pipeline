# Common rules for the dispatches that build the PO decisions of 2026-10-23 (read with your own briefing)

Read `scratch/briefing-common-clone.md` first (clone rules, quality rules, report shape; replace `<name>` with your clone name), then `specs/sprint-alfred-epic/plans/po-decisions-2026-10-23-tiles.md` (the PO decisions; your briefing names the rows). The decisions are made; you build them, you do not re-decide. A point that the decision leaves open: choose the smallest reading, state it in the notes.

Base clone: your clone is created from the REHEARSAL clone `scratch/clones/k91` (the whole held-patch bundle C15 to C28 already applied there, in the order the sitting would use), unless your briefing says "base: main". So your diffs stack on the bundle. Check with `git log --oneline -3` that you see commits starting `rehearsal:`. Set the clone's git identity in the clone's local git config (guard-push refuses `git -c`).

Protected paths (guard-*.mjs and guard-*.test.mjs, `lib/guard/*`, `pipeline-state.mjs`, `verify.mjs`, `verify-suites.json`, `lib/protected-test-paths.mjs`, the paths in `plugins/pipeline-core/protected-baseline.json` and `NEVER_LIFTABLE_KERNEL_PATHS` in `plugins/pipeline-core/lib/guard-maintenance-window.mjs`): never committed for the main checkout. In your CLONE you may leave the change in the working tree. For every protected change deliver: `git diff --output=scratch/agent-out/<task>-<name>-protected.diff <paths>` (clone-relative paths; `git apply --check` must be clean against the main checkout PLUS the bundle: say "applies after the bundle" in the notes; verify by `git apply --check` inside a second throwaway clone of `scratch/clones/k91` only if cheap), unprotected parts as `<task>-<name>-unprotected.diff` (use `git add -N` for new files). Then revert the clone edits by hand (Edit tool) and leave a clean tree, OR state in the notes that the clone still carries the edits. Notes file: `scratch/agent-out/<task>-notes.md` in the MAIN checkout (max 60 lines: cause, change, every counted result before/after with the exact command, risks, ratchet line effect against `architecture/boundary-policy.json` (report only), proposed commit message with trailers exactly `AI-Assisted: true` and `Dispatch: <TASK_ID> (goldfish)`).

Quality: QG-04 (no assertion weakened or removed without a bounded justification citing the decision, no skips), RED-first where a new case is added (state the RED run), every claimed count measured. Run heavy suites ONE at a time with a private TMPDIR outside every repository and outside /tmp (working runners in the MAIN checkout: `scratch/k91-run.mjs`, `scratch/k90-run.mjs`; copy one to `scratch/<task>-run.mjs`, replace the clone name and label; read its header). Other dispatches run at the same time on the same machine: a result that differs from a baseline gets ONE lone retry before you call it red.

Forbidden: touching the main checkout other than `scratch/<task>-*` and `scratch/agent-out/<task>-*`; `CLAUDE.md`, `.claude/**`, `docs/state.md`, `backlog/**`, `specs/**` edits; signing; network; push/reset/stash/checkout/rebase in the main checkout; absolute home/repo paths, emails or secrets in any file; Advisor; looking for a bypass of a guard refusal (record its text). Shell grammar: `rg -n` on ONE file, `rg -n "..." file | head -N`, single Read/`find`; no `grep -E`, no `rg -o`/`-A/-B/-C`/`--glob`, no multi-path rg, no alternation with `|` inside a quoted pattern, no pipes except bounded `| head -N`, no composed commands; `git apply` of a saved diff on a protected target may be refused: apply via a Node script (`node scratch/<task>-apply.mjs`, execFileSync("git", ["-C", cloneDir, "apply", ...])) or the Edit tool.

Status wording: never "done"; end with "implementation complete in clone; independent Critic read, operator commit of the protected parts and PO acceptance pending". Tool budget: base cap 70, closing allowance +5. Ruleset `0.7.0+claude.20261022204428.79cda46`. Model Sonnet 5.5 (general-purpose carrier). Profile standard. Final report max 30 lines.
