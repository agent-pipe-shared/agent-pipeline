# Common rules for the Full-Verify fix dispatches K143 to K145 (read with your own briefing)

Read `templates/prompts/agent-obligations.md` (shell grammar, trailers) and `scratch/briefing-common-clone.md` first (replace `<name>` with your clone name; ignore any "base: k91" statement). Your clone is made with `git clone --quiet . scratch/clones/<name>` from the MAIN checkout; its HEAD holds the complete sitting, the K141 restate commit, the Codex runner fix (K142) and the hotfix stamp. Set the clone's local git identity from the main checkout's config. The PO decision is made: fix what the Full Verify of the dev build found. The evidence is `specs/sprint-alfred-epic/evidence/full-verify-2026-10-23-classification.md` (+ `-notes.md`, + `-dev-build.md`) and the series V section of `specs/sprint-alfred-epic/plans/greenfield-findings-2026-10-23.md`; raw per-step output of the classifier's runs is untracked under `scratch/k141-raw/` in the main checkout (r1: all 51 on 3 workers, r2: lone re-runs, r3: environment probes) and its runner is `scratch/k141-run.mjs` (worker clone synced to the committed HEAD, private HOME and TMPDIR; read its header and reuse it, do not write a new runner).

Rules: (1) Root cause before fix; state the cause in one or two sentences with file and line. (2) RED pin first where behaviour changes (extend an ALREADY REGISTERED suite, no new test file; a new test file needs a protected registration plus an inventory surface); a stale assertion is restated only under QG-04 with a bounded justification citing the evidence, never weakened or removed to pass. (3) Never revert a feature to turn a test green; if the product is right and the test stale, restate the test; if the test is right, fix the product. (4) Protected files (`plugins/pipeline-core/protected-baseline.json`, `NEVER_LIFTABLE_KERNEL_PATHS` in `plugins/pipeline-core/lib/guard-maintenance-window.mjs`, guard-*.mjs and their tests, `lib/guard/*`, `verify.mjs`, `verify-suites.json`, `pipeline-state.mjs`, `lib/protected-test-paths.mjs`): deliver as `scratch/agent-out/<task>-protected.diff`; everything else committed in the clone and delivered as `<task>-unprotected.diff`; `git apply` of a diff by tool call is refused by the guard, so apply through a Node script with `execFileSync("git", ["apply", ...])`. (5) Verify every diff with `git apply --check` and then for real in a throwaway clone `scratch/clones/<name>-check` of the main checkout, and run the affected suites alone there before and after (counts); also `node harness/scripts/check-doc-contracts.mjs` and `node plugins/pipeline-core/scripts/architecture-boundary-check.mjs --root .` (22 `unowned-path` findings for top-level `scripts/*.mjs` are the known baseline; report any other change; a line-bound overshoot needs a ratchet diff `<task>-ratchet.diff`). (6) Heavy suites only through private-HOME runners, ONE at a time or at most 3 workers; never against the real HOME (the PO's installed plugin uses it). (7) A step that was green alone but red in the Full Verify is class D: do not chase it. (8) Do not stop at "cause unknown" before you have bisected the failing assertion: read the failing case, run it alone with the full message, compare the fixture against the code it exercises. If after real effort a cause stays open, say exactly what you excluded.

Deliver: commit messages `scratch/agent-out/<task>-msg-protected.txt` and `-msg-unprotected.txt` (trailers exactly `AI-Assisted: true` and `Dispatch: stage-0 (elephant)`), notes `scratch/agent-out/<task>-notes.md` (max 60 lines: per step cause, fix, counts before and after, open items, risks). Status wording: never "done"; end with "implementation complete in clone; independent Critic read, operator commit of protected parts and PO acceptance pending". Forbidden: touching the main checkout other than `scratch/<task>-*` and `scratch/agent-out/<task>-*`; `CLAUDE.md`, `.claude/**`, `docs/state.md`, `backlog/**`, `specs/**` edits; signing; network; push/reset/stash/checkout/rebase in the main checkout; stamp, install; absolute home/repo paths, emails or secrets in any tracked file. Tool budget: base 80, closing allowance +5; use one batch script instead of one call per suite. Ruleset `0.7.0+claude.20261023185750.bd9ee06`. Model Sonnet 5.5 (general-purpose carrier). Final report max 30 lines.
