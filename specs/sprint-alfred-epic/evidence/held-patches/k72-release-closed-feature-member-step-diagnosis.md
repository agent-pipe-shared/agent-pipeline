## Case C cause (two stacked blockers; the call cannot reach either, the case uses the release-closed-feature private route)
Probe: `scratch/k72-gen-probe.mjs` builds `scratch/k72-probe.test.mjs` (a copy of the case plus `session-authority-repair.mjs inspect` calls), outputs `k72-probe*.log`.

1. First failure, `SessionAuthorityError onboarding-continuity:namespace-drift` at the bound start `invoke(["start", ... "session-after-private-release"])` (test line 1270): `bindOnboardingSessionCleanup` -> `reserveSessionAuthorityMember` (`lib/onboarding-continuity.mjs` 9576) -> `stateRead` reconcile (`lib/session-authority-registry.mjs` 422/379). The member created by the case's first start stays armed (inspect: `onboarding-continuity inFlight: 1` after the descriptor retire and still after the apply). The private closed release `recordClosedOnboardingSessionCleanupRelease` (`lib/onboarding-continuity.mjs` 3270-3378, `releaseProof === null` branch) writes the receipt and deletes the binding with NO registry step. The deletion/receipt move the producer namespace (drifted: cleanup-binding, cleanup-release, selected-state), and a drift with an in-flight member is never healed, so the next bound start refuses. Same defect class as D73 E (a binding release leaves its registry member armed), on the sibling route that D73 E (decided for the ordinary orphan release only) does not name.
2. Hidden behind it, measured by releasing the lost member and healing inside the probe (`releaseLostSessionAuthorityMember` + `healSessionAuthorityDrift` between the apply and the start): drift disappears, and the start then fails `SDC-AUTHORITY-UNAVAILABLE` 'unknown continuity private namespace entry' at `lib/onboarding-continuity.mjs` 9283-9284. The bound start rotates the private receipt (`archivePrivateCleanupReleaseReceipt` 2046-2057, which names a coordinator receipt `session-cleanup-release-receipt.<recoveryPlanSha256>.json`, the case asserts that name at test line 1277). The snapshot admission added for D73 E (9274-9284) requires the name to equal the file's BYTE digest, which holds only for the orphan receipt schema. Probe values: name 286a4b5caa44 = recoveryPlanSha256, byte sha fe993ddd6887.

Verdict: (b), a real product gap (two missing pieces), not a stale test. The case predates nothing: it asserts exactly the later bound start after the private release, which is the product contract; D73/K1D (corr-plan lines 426-431, 649-659) decide only the orphan route and the archive shape of the orphan receipt. The correction plan's earlier 'owner preparation refused' red for this case is the older layer; the K1c fixture work moved it to these two.

## Options and recommendation
- Option 1 (recommended, smallest correct): extend D73 E to the private closed release, protected kernel code: (i) after the private release's State lock is released, run the member step for the binding's session tuple in one registry boundary (`releaseLostSessionAuthorityMember` only when the descriptor is not active, then `healSessionAuthorityDrift` with strict read-back), idempotent so a crash before it is recovered by rerunning `apply-recovery` (replay returns `closed-unbound`; the replay branch `privateClosedReleaseReplay` would have to run the step too, or the replan must offer it); same lock-order constraint as K1D-E (the snapshot refuses a foreign State lock, so the step cannot run under `acquireLock(initial.path.lock)` at 3314). (ii) snapshot admission at 9275-9284: for a receipt whose schema is the private-closed one, accept the archive when the name equals its `recoveryPlanSha256` (still a bytes-bound check: parse, check schema, name == field), keep the byte-digest rule for the orphan schema. Files: `lib/onboarding-continuity.mjs` (kernel, NEVER_LIFTABLE list line 199, at its zero-growth bound: new logic should go into `lib/session-authority-orphan-member-step.mjs` or `lib/session-cleanup-lost-binding.mjs`, both kernel too) and possibly `lib/session-cleanup-recovery.mjs` (kernel line 247) for the apply wiring. Needs the PO's D73 extension (a security read, D65) before building.
- Option 2: change the fixture so the first member is released before the private release (e.g. the owning release instead of `cleanupSession`+`retireSessionDescriptor`). Rejected: it removes the exact recovery scenario the case pins (QG-04 weakening), and does not repair the archive-name blocker.
- Option 3: let the bound start auto-heal an armed member whose owner descriptor is retired. Broader authority relaxation; not recommended without a design decision.

No change was made to the case, to any lib source, or to the clone's commit history. The clone still carries exactly the original uncommitted `pipeline-state.mjs` edit (+14).
