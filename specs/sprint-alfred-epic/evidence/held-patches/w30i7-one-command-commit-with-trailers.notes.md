## What real Git does (measured, Git 2.53, throwaway repository; probe kept in the clone's scratch, not in the product)

`git commit` with `-m <subject> [-m <body>...] --trailer A --trailer B`:

| Spelling | Real result |
|---|---|
| (i) subject + two `--trailer` | `subject`, blank, `A`, `B`. Trailers parse as exactly the two. |
| (ii) subject + one prose `-m` body + two `--trailer` | blank line BEFORE the trailers. `%(trailers:only=true,unfold=true)` prints exactly the two. |
| (iii) the same with an extra `-m ''` | the empty paragraph is dropped (Git's whitespace cleanup); same bytes as (ii). The old reconstruction produced `\n\n\n\n` here. |
| (v) `--trailer 'Dispatch: C30I-S4 (goldfish)'` and the `--trailer=...` spelling | identical bytes; the parenthesis is no problem for Git. |
| two or more body paragraphs + two `--trailer` | blank line before the trailers. |
| body whose LAST paragraph Git reads as a trailer block (e.g. `-m 'Why: x'`) | NO blank line: the trailers are appended to that paragraph, and `%(trailers...)` lists the body line as part of the block. This is the coordinator's observation. |

Git's rule (trailer.c `find_trailer_block_start`): the first paragraph is the title and never a trailer block; the last paragraph is a trailer block when every line is `Token: value` (token = ASCII letters, digits, `-`, optional blanks before the colon; indented lines are continuations), or when one line has a Git-generated prefix (`Signed-off-by: `, `(cherry picked from commit `) and trailer lines are at least a quarter of the non-trailer lines. `https://x` counts as `Key: value`; `my_key: x` and `- bullet: x` do not. A trailing run of blank and `#` lines is a comment footer: the entries are inserted in FRONT of it (so a `#` line at the end of the body leaves the trailers not final). Git also rewrites glued lines (`Note : x` -> `Note: x`, `https://x` -> `https: //x`) and drops a `#` line inside a glued block.

## What the patch changes

A glued result is refused with the new typed finding `GIT-03-TRAILERS-GLUED-TO-BODY`, whose repair names the accepted spelling (`ONE_COMMAND_TRAILER_FORM`, new export) first and the message file as the fallback. ## Reconciling the coordinator's observation with the probe

The three last commits of the real repository were read: the queue commit (`docs(plans): queue C30-19 to C30-21 ...`) has NO blank line before its trailers, and its body is one paragraph starting `C30-19: the guard already admits ...`. `C30-19` is a valid trailer token, so every line of that paragraph reads as `Key: value` and Git glued the trailers on: the model predicts exactly this (both bodies are shapes of the agreement table: the `C30-19:` body is glued, the following commit's body `Found on the first real commit with the form: ...` is not, and that commit indeed has the blank line). So plain prose bodies keep the blank line, and the defect is the trailer-shaped last paragraph, not the spelling in general.

## Which guard refuses a parenthesised `--trailer` value (the false sentence in `agent-obligations.md`)

Searched `hooks/guard-push.mjs`, `lib/guard/*` and the other hooks. `guard-push` does NOT refuse a quoted parenthesised value in general: `guard-push.test.mjs` PGC-T82b admits `git commit -m "chore: tidy" --trailer "AI-Assisted: true" --trailer "Dispatch: X (goldfish)" -- docs/a.md` (Ruling 157 proof, about line 369). The proof has conditions: the whole command is one plain `git commit` (words 0 and 1 literal, no global option), printable ASCII only, no backslash, no newline, no unquoted marker characters. Outside it the refusal is "push target is not unambiguous / push command prefix is ambiguous" (I met it myself on a subject containing `(git-guard)` outside quotes, and the helper commit then needed a subject without parentheses). The only other parenthesis refusal is `guard-dispatch-budget.mjs` `isSingleGitClosingCommand` (about line 857): after the tool-budget working cap a `git commit` command containing `(` is not counted as a closing act, so the `-F` route is the one to use at that moment. The sentence "refused by guard-push" is therefore wrong; a real commit with the parenthesised value landed.
