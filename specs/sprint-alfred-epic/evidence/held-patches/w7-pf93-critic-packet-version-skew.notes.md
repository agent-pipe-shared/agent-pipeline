## (B) Options paragraph: release command for a claimed packet (PO decision)
A claimed packet holds in the registry (`critic-packets/<packetId>/`): packet.json, state records (prepared, claimed), session-admission.json, and the generic-batch reservation. No expiry exists because the claim is an exclusive reservation whose release would let a second verdict be produced for the same fresh course, and the packet digest chain makes silent removal indistinguishable from tampering. Options: (1) a `release` subcommand of the finalizer CLI that appends a terminal `released` state record (reason, actor, timestamp, prior state digest) and frees the batch reservation; audit trail needed: a PO-signed or Elephant-attested release record under evidence/, referenced from the state record; (2) a time-based expiry (rejected: loses verdicts silently); (3) leave manual deletion with `cleanupCandidatePacket` only. Recommendation: option 1, built as its own slice.
