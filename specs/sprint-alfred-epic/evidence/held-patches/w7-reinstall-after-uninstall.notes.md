2. `inspect` makes it the controlling action: manifest invalid + recognised uninstalled state -> `nextAction` = `plan-reinstall` (non-mutating). Pin: RIU-01, RIU-08.
3. `plan-reinstall` gets a typed case `after-uninstall` (verb reused, not a new verb: the guard admits mutating apply verbs by name in `lib/guard/sanctioned-args-onboarding.mjs:275`, which is outside the write scope, and `apply-reinstall` is already listed there with the argv `--root --plan-sha256 --activate [--intent]`). Statuses: `ready`, `conflict` (typed codes `reinstall_postimage_edited`, `reinstall_postimage_missing`, `reinstall_retained_state_unavailable`), `unrepairable` (`reinstall_projection_unavailable`). Pins: RIU-01, RIU-03, RIU-10.
4. `apply-reinstall --plan-sha256 --activate` regenerates the stripped files through the existing runtime-projection generator: the owned anchors are re-seeded (`language.human_facing` child, `modelRouting:` block at its fresh-manifest position, no emptied `session:` stub; `model`/`model_reasoning_effort` for Codex agent TOML), then `planRuntimeProjectionV3` writes the values from the current source. Write is CAS-checked (preimage digest), temp+rename, read-back (the regenerated files must be a fixpoint of the source), rollback on any failure. Pins: RIU-01, RIU-10, RIU-11 (Codex-enabled source, foreign bytes survive).
