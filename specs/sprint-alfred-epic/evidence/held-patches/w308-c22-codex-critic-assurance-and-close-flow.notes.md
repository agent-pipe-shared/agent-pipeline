# w308 — Critic route assurance before dispatch, a whole-flow close test, schema-based classification of generated metadata (candidate 22)

Delta on the candidate 22 chain (clone base 7b3b59dd9). Closest accepted criterion: AC-108 (PRD and Spec unchanged). Built by a Goldfish in a clone; delivered as a held patch. Findings: CGF-03 and CGF-20 (assurance and late acknowledgement), CGF-04 (whole-flow close test), CGF-06 (generated metadata versus scanners and classifiers).

## What

1. **CGF-03 / CGF-20, `lib/critic-route-assurance.mjs` (new, pure).** `describeCriticRouteAssurance` reads the planned route (runner from its markers, trigger, the feature rigor, the Codex launch route when one is decided) and states, in the receipt's own vocabulary (`source-issued-origin` / `caller-authored-fallback`, `freshContext`, `historyInherited`), what the finalized receipt will say. It also states whether the close will need its own PO acknowledgement, with the exact command for the packet id the admit request already carries, and the critical-profile status (`meets`, `below-required`, `conditional`, `not-critical`). An undecided Codex launch promises nothing: it names the floor and both outcomes. The one existing exception route (the PO acknowledgement of exactly this packet at the close, `approve-critic-acknowledgement`) is named as the deliberate exception, so the rule has no deadlock.
   `scripts/critic-dispatch-preflight.mjs`: one import, one small `featureRigor` reader, one call and one printed field `routeAssurance` in `preflightCriticDispatchWithAdmitRequest` only (the finalizer binds the library result by digest, so the library entry points are untouched and pinned that way by a new case). Three pinned destructurings of the printed result were restated in place with a comment (QG-04); no case was weakened.
2. **CGF-04, `scripts/close-path-e2e.test.mjs`.** Measured first: the existing walk drives the coordinator by hand and never calls `finish-feature.mjs --one-shot`, so the acceptance stop and the commit requests were only tested with an injected runner. The walk body became one function (the five existing walks run unchanged through it) and a second test runs the REAL one-shot CLI on the same fixture and Critic course: `ONESHOT-RESULT-NOT-BOUND` stop with nothing written, bootstrap and reconcile, `ONESHOT-ACCEPTANCE-REQUIRED` stop with nothing written, the answer recorded for exactly the HEAD it was given at, one `commit-required` carrying the acceptance record, an extra evidence-only commit between the close commit and the resume, then the resume through freeze, candidate Verify, security scan, final-verify-green and cleanup to `closed-local`, with the Critic-bound push Verify named. It asserts stored state and typed codes, and that the sequence is exactly one question, one commit request and the end (no `FCA-PACKAGE`, no repeated `ONESHOT-COMMIT-PENDING`).
3. **CGF-06, `lib/generated-artefact-schema.mjs` (new, pure).** `classifyGeneratedArtefact` claims a class only for a JSON object with a Pipeline schema id (`pipeline.<name>.v<N>`); it lists digest fields (bare lower-case hex of 32..64) apart from credential-shaped fields, and names the digests whose FIELD NAME the scanner reads as a credential (`idempotencyKey`, `scopeKey`, `reuseKeySha256`, `courseKey`, measured on this repository by running the scanner over the clone). `scannerSafe` is true only when every credential-shaped name holds a bare digest. BOM, CRLF, buffers, size and depth are handled; the output never carries a value.

## Why

- A caller-authored Critic (`freshContext:false`, `historyInherited:true`) was learned about at the close; stating it before the dispatch costs no run and no refusal.
- The close path had no test that walks its own CLI with the human stop and the commits the close asks for; a close that becomes unresolvable through its own evidence commits now turns the test red (the sequence assertion).
- Digests under key-shaped names were the measured cause of the scanner hits; a field-scoped, provable exception needs a classification that does not trust a path alone.

## Not changed (and why)

- `CCI-MIXED`: the move of a source document into the project-state record is already split into a deletion and an addition (earlier fix, `splitMoveIntoProjectState`); the reverse direction stays `CCI-MIXED` by that fix's own documented decision, so it was left as it is.
- The scanner configuration and the narrow close-artefact ignore: unchanged. The plugin default config is pinned byte-equal to the repo-root `.gitleaks.toml`, which is outside this patch's scope (only plugins/pipeline-core/ is touched); no blanket ignore and no history rewrite.
- The Critic preimage files (`agents/critic.md`, `skills/critic-review/SKILL.md`, `scripts/codex-critic-host.mjs`, the Critic schemas) and `nextStep` text of the preflight: untouched.
- `harness/verify-suites.json` and the case-completion registry: out of scope (they are not under plugins/pipeline-core/).

## Not proven / open

- The two new test files (`lib/critic-route-assurance.test.mjs`, `lib/generated-artefact-schema.test.mjs`) need registration in `harness/verify-suites.json`; the cases added to `critic-dispatch-preflight.test.mjs` and `close-path-e2e.test.mjs` change those suites' case counts, so the case-completion registry and the inventory need the usual rebaseline (Coordinator).
- The CLI cannot pass the Codex launch receipt (a new flag would change the pinned unknown-argument text and collide with the parallel preflight change); a Codex session therefore prints the conditional form. The library takes the decided route (`deps.criticLaunchRoute`). Wiring a flag is a small follow-up.
- The critical-profile rule is a named notice plus the existing exception route; it is not a refusal, because the exception (the PO acknowledgement) exists only after a packet is consumed. Options: keep the notice (built), or refuse up front unless a recorded exception exists, which needs a new signed record kind (a new signature).
- The classifier is not yet called by any scanner gate. A field-scoped allowlist rule for the measured names would need both `.gitleaks.toml` and its plugin mirror (outside this patch); the classifier is the check such a rule can cite.
- The one-shot walk passed against the unmodified product code (the earlier fixes C21C and 21e hold); it is a regression guard, and a mutation of the product that makes the close unresolvable was not run. The requalify path with a HEAD move after the package is completed stays covered only by the injected-runner suite.
- `critic-dispatch-preflight.test.mjs` has one red case that is not from this patch: the D216A drift pin on `criticCoverageAdvisory` (`lib/review-admission-read.mjs` versus `scripts/dispatch-record-write.mjs`, neither touched here).
