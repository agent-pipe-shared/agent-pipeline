# w30g3 — a plugin reload leaves no dead end (candidate 30, slice C30G-D3)

Criterion binding: AC-108 is the closest existing accepted criterion (a fresh bounded attempt under its unchanged text); the PRD and the Spec are unchanged. Held patch, developed and tested in a scratch clone of the applied chain; it applies to the repository HEAD (`git apply --check` exit 0, asserted by the check test). Text and readback only: no check admits or refuses anything different, nothing is auto-run.

## What it adds

- **Part A, the registry (`lib/session-authority-registry.mjs`).** One new export, `sessionAuthorityRefusalRepair(code, reason, root)`, and the shared failure helper `fail` now sets `error.repair` from it (`code`, `reason` and the message are untouched; `repair` is the existing mechanism that `native-goldfish-host-state` and `session-authority-repair` already forward). The table is closed and names a command only where it repairs the reason:
  - the two reasons the repair script's own `inspect` lists as healable besides namespace drift: `SDC-AUTHORITY-CAS` + `windows-native-identity-drift` (briefed) and `SDC-AUTHORITY-UNAVAILABLE` + `catalogue-source-closure` (a catalogue another plugin version wrote: the typical reload case; `inspect` treats it as healable and the heal migrates it): `session-authority-repair.mjs heal --root <root>`, stated for "once no Goldfish or other authority operation runs", then repeat the refused command; `inspect` as the fallback. `heal` takes no `--no-goldfish-running` flag in this script; the precondition is said in words (the routine-repair spelling `run heal ... --no-goldfish-running` was not chosen, so no second spelling exists).
  - `SDC-AUTHORITY-HELD` + `legacy-partial-registry` / `legacy-retained-registry` (records but no catalogue; heal returns `absent` there): `inspect`, then `move-aside --root <root> --no-goldfish-running --reason "<why>"` (retained, never deleted). The text does not name heal.
  - every other `SDC-AUTHORITY-HELD` reason raised by this module (contract refusals such as `retired-*`, `domain-transition-*`): the read-only `inspect` only, with the sentence that when it names no command the refusal is a rule and not a stale state. No heal, no release-lock.
  - every other CAS / UNAVAILABLE reason keeps no repair here; the namespace-drift refusal (`driftRepair`) and the lock refusal (`registryLockRepairText`, wait / release-lock with `--no-pipeline-running` / heal / move-aside) keep their own, untouched.
  - The command is spelled by the same `REPAIR_SCRIPT` that `sessionAuthorityRepairCommand` uses (a test compares the strings); the root comes from the active boundary, else the placeholder `<repository root>`. The texts do not claim that nothing was written (some refusals fire after a writer returned).
- **Part A, HOOK-SNAPSHOT-STALE (`lib/hook-currentness.mjs`).** The rendered hook refusal already named `refresh-mandatory-hooks.mjs --root <root>` (pinned by AC-179, spelled as that script's usage prints it); it now also says "run it once, then repeat the refused command". The preflight already carries the typed code plus the `hook-refresh-required` action (Elephant) and `prePushHook.installCommand`; those are role-scoped (withheld from a Goldfish/Critic by AC-245) and were left as they are.
- **Part B, the preflight (`scripts/pipeline-start-preflight.mjs`).** New export `describeClaudeRegistryBindingRepair({ version, pluginListSnapshot })`; the Claude `IPA-HOST-REGISTRY-BINDING-UNAVAILABLE` readback gains `installedPluginAttestation.repair`: the loaded version, `the host plugin registry lists: <versions>` (pipeline-core versions of the SAME plugin-list snapshot, at most 5, each at most 60 characters, control characters stripped, `none` when none or unreadable) and the person's recovery with the pointer to `references/local-plugin-attestation.md`. `resolveClaudeRegistryBinding` returns null for more than a version gap (not exactly one enabled entry of that version, a registration that is not a directory source, an install path that is not the loaded root), so two wordings exist: the loaded version is not listed (complete the host install or update so the registry lists it, restart, rerun the preflight) and the loaded version is listed (no single enabled entry binds to this loaded root: a person repairs or reinstalls the host registration so exactly one enabled entry names this root, restart, rerun). No path is printed or taken from the environment; `nextAction` stays null; the text is not an executable action, so a Goldfish/Critic keeps it.
- **Part C, `references/local-plugin-attestation.md`.** One section `After a plugin reload or update`: the happy path, then each recovery by code with its command (`IPA-HOST-REGISTRY-BINDING-UNAVAILABLE`, `HOOK-SNAPSHOT-STALE`, the heal reasons, `SDC-AUTHORITY-HELD`, `SDC-LOCK-HELD`).
