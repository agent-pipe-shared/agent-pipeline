## What the patch does

1. Dispatch time (`scripts/dispatch-briefing.mjs`, `lib/continuity-authority-drift.mjs`). `generateDispatchBinding` now reads the same projection the bootstrap emits (`observeContinuityAuthorityDrift` of `pipeline-start-preflight.mjs`, unchanged) and, when a recorded PRD or Spec digest no longer matches the file, refuses through the existing `soft` path with the new typed code `DBG-CONTINUITY-AUTHORITY-DRIFT`. The text names each drifted source (role and repo-relative path) and the recovery the bootstrap already names (code `CONTINUITY-AUTHORITY-DRIFT`, route `continuity-authority-revision-plan`, command `pipeline-state.mjs continuity-authority-revision-plan --proposal-file <repo-relative proposal json>`, or restore the recorded bytes). Because it goes through `soft`, `build`, `binding` and `probe` share one code path (probe lists it as a finding with its repair). Pure helpers `continuityAuthorityDriftSources` and `continuityAuthorityDriftRefusalText` live in the lib. No new repair verb.
   - No continuity record, a current record, a malformed record and a throwing observer all yield null: output is byte-identical (pinned by a test that compares `JSON.stringify` of three runs).
   - A source that cannot be compared at all (`unobservable`: missing, symlink, hard-linked) is NOT a refusal; it is the warning `DBG-CONTINUITY-AUTHORITY-UNOBSERVABLE`. Reason: a false refusal at the only dispatch route blocks all dispatching, and the bootstrap's own reading of that state is fail-open. The coordinator's wording ("no longer matches the file") is met by `changed`.
   - Result is not checked: the existing projection and the sanctioned revision route cover PRD and Spec only (`continuity-authority-revision-plan` rewrites `authority.{prd,spec}`), so a Result check would create a refusal with no sanctioned recovery (a dead end). Left as it is, named here.
2. Audit index collector (`scripts/audit-index.mjs`). New exports `collectAuditIndexInputs`, `collectAuditIndex`, `buildAuditManifest`, `writeAuditIndexEvidence`, new verb `collect --root <dir> --feature-id <id> [--commit <40-hex>]` (prints one index, exit 0 whenever generated; `complete` carries the verdict; typed refusals `AUDIT-INDEX-ARGS` and `AUDIT-INDEX-STATE-UNREADABLE`, exit 2). It gathers from the repository's own records: PRD, Spec and Result from the State, the plan approval's PRD/Spec digests (gates `plan-approval:plan` and `plan-approval:spec`, bound with `expectedSha256`), the delivery course `slice-queue.json` beside the PRD and the `evidence/dispatch-record-<id>.json` of each non-cancelled, non-deferred slice (gates `dispatch:<id>`), each record's `criticEvidence` (gate `critic:<id>`, digest compared with the receipt; a `criticRequired` record without evidence is a missing step), and the passing `pipeline.verify-evidence.v0` candidate evidence listed in the `lifecycle.json` beside the Result (gate `verify`). `buildAuditIndex` gained two additive optional inputs (`missing`, per-entry `expectedSha256` giving status `digest-mismatch`); with neither, its output is unchanged and the six pre-existing cases pass untouched.
3. Close course (`scripts/close-coordinator.mjs`). On the `feature-close-prepared` transition `closeAuditIndex` collects and writes `audit-index.json` into the coordinator-private evidence directory (next to the close evidence) and the apply result carries `auditIndex: { status: "written", file, sha256, complete, missingSteps }`. A replay of the same apply does not re-collect: it reads the file back (`readAuditIndexEvidence`) and reports the same summary and digest, so earlier evidence is never overwritten from a later State (pinned: the replay case edits the PRD after the close was prepared and asserts an identical `auditIndex`); only when no file exists does the replay write one. Any fault becomes `{ status: "unavailable", code }`, a screened index becomes `{ status: "held", code: "BT-PRIVACY" }`; neither can refuse or alter the close. A missing source is a named missing step in the index.
4. Sanitized auditor manifest (D152 clause). The index carries `manifest` (`pipeline.audit-index-manifest.v1`): present entries only, `{kind, id, path, sha256}`, no file body. Every collected path must be a plain repo-relative path; an absolute or private-looking recorded path never enters the index (it becomes a missing step with reason `path-not-repo-relative`). Each manifest entry and the whole written index are screened with `hasPrivateTransferContent` of `lib/bound-artifact-transfer.mjs`, the screen the repository already uses for public evidence; entries it rejects are counted in `manifest.held`, an index it rejects is not written.
