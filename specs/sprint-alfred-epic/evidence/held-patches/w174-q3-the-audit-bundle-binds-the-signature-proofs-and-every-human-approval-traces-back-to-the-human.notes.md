## What it adds

See the sections below; the list is kept in step with the commits of the clone.

- `lib/human-approval-trace.mjs` (new, read-only) with `traceHumanApprovals` and `formatHumanApprovalTrace`: for a candidate commit it enumerates the approval records the gates consumed and gives each a typed verdict `traced`, `attribution-only` or `untraceable` with the exact break.
  - Enumerated: private-store push and feature-package-reconcile approvals, legacy tracked-state approvals of those kinds, deploy approvals, the plan approval with its design approval, human guard override capabilities.
  - `traced` needs: the record names this candidate; the intent rebuilt from the record (feature, plan and spec digests, candidate, action digest) equals the recorded intent digest; the detached Ed25519 proof verifies over it against the project's committed trust anchors; the signing key is a registered human key (a committed anchor, or this machine's registered operator key when the anchor set is open); the recorded proof digest is the digest of the recorded proof; the proof appears exactly once in the store and once in the consumption journal. Breaks: `PROOF-MISSING`, `RECORD-INCOMPLETE`, `SUBJECT-MISMATCH`, `INTENT-MISMATCH`, `TRUST-MISMATCH`, `SIGNATURE-MISMATCH`, `PROOF-INVALID`, `DIGEST-MISMATCH`, `KEY-NOT-REGISTERED`, `REPLAYED`, `NOT-CONSUMED`, `THREAT-MODEL`, `STATE-AUTHORITY`, `NO-APPROVAL-RECORD`.
  - A chat-mode approval is `attribution-only` and carries no proof, as the repository already labels it.
  - The expiry of an approval is not a break (an audit reads past approvals); it is measured by the push guard at push time.

- `lib/audit-bundle.mjs`: `planAuditBundle` takes two optional inputs. `candidate` must equal the feature package's candidate exactly (`AB-CANDIDATE-MISMATCH` otherwise), so a bundle is never labelled with the parent of the audited commit. `evidence` (`traceReportPath`, `proofPaths`, `verifyRecordPath`, `securityScanPath`) carries the trace report, each detached proof, the release-mode Verify record and the security scan as bundle artifacts (classes `approval-trace`, `approval-proof`, `verify-record`, `security-scan`), by path and digest, plus one optional manifest key `evidence` listing every item as `carried` or as a typed `gap` (`NOT-REFERENCED`, `UNREADABLE`, `OTHER-CANDIDATE`, `NOT-RELEASE-VERIFY`, `NOT-PASSING`); a carried trace with verdict `untraceable` or `attribution-only` is named (`TRACE-UNTRACEABLE`, `TRACE-ATTRIBUTION-ONLY`), never hidden. Offline verification checks every carried item against the manifest and the carried trace against the manifest's candidate (`AB-EVIDENCE-ITEM`, `AB-EVIDENCE-TRACE-CANDIDATE`). With no `evidence` input the plan, manifest and README are byte-identical to before (the existing key-list case still passes). The four hand-written key lists were folded into one optional-key helper.
- `scripts/human-approval-trace.mjs` (new operator command, read-only): `--repo <root> [--commit <oid>] [--format table|json] [--out <repo-relative path>]`; prints the table and `verdict: <traced|attribution-only|untraceable>`; exit 0 for traced and attribution-only, 1 for untraceable, 2 for a command error; `--out` writes the JSON report create-only inside the repository for the bundle to carry. The guard admits only `--repo <this root>` with optional `--commit` and `--format` (`lib/guard/constants.mjs`, `lib/guard/command-catalogue.mjs`); `--out` is not admitted.
- `lib/feature-close-audit-preflight.mjs` passes the exact `candidate` and the optional `evidence` to the bundle plan, includes them in the collision check and, when evidence was named, adds `humanApproval: { traceStatus, gaps }` to the plan the close reads. `scripts/close-coordinator.mjs` accepts an optional `evidence` key in the audit request.

## Not changed / not proven

- The trace never signs, never pins a trust anchor and never consumes a proof; it only imports the pure readers of the authorization modules.
- Not enumerated (named in every result as `notEnumerated`): publication and release-preflight authorizations, briefed test authorizations (their intent builder is private to `human-guard-override.mjs`).
- A signature-mode design approval is reported `untraceable` with the break `DESIGN-INTENT-NOT-RECONSTRUCTIBLE` after its signature, key and digest were proven: the intent content is only rebuildable from the scratch approval request inside `pipeline-state.mjs` (`observeDesignApprovalRequest`), which this trace does not import. A plan approval that was cleared by signature through a bootstrap receipt is `PLAN-PROOF-NOT-RETAINED`; a signed human guard override capability is `PROOF-NOT-RETAINED-IN-CAPABILITY` (the capability stores no proof and is authenticated with a private key). These are real findings about what the stores retain, not defects of the trace; a follow-up that exports those intent builders or retains the proofs would turn them into `traced`.
