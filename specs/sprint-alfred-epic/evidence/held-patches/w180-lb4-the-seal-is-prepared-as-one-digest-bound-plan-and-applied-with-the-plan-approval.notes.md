## What it changes

- `lib/authority-seal-plan.mjs` (new, pure): `buildSealPlan` (plan with the digest of every PRD, Spec, design-input, result/plan entry, the design-input capture, the digest each review bound, the State revision, and the plan digest), `validateSealPlan`, `checkSealPlanForApply` (feature, revision, paths, and every byte still equal to the plan), `sealedAuthorityFromPlan` (the bound shape without the marker). Typed refusals, each with `exits` and a `repair` sentence: `PSP-OUT-OF-SCOPE`, `PSP-ALREADY-SEALED` (exits none: nothing to do), `PSP-AUTHORITY-INVALID`, `PSP-DOCUMENT-MISSING`, `PSP-PROVENANCE`, `PSP-STALE-REVIEW` (names the review and the re-request exit `re-request:<kind>`), `PSP-NOT-PREPARED`, `PSP-PLAN-INVALID`, `PSP-PLAN-STALE`, `PSP-APPLY-DRIFT`, `PSP-NOT-PRESENTED`, `PSP-REVIEW-UNREADABLE`.
- `scripts/pipeline-state.mjs`: new command `prepare-seal [--review-receipt <path>]...` (in `PIPELINE_STATE_COMMANDS`; it writes only `scratch/seal-plan.json`, replaced atomically on every run, never State; an identical re-prepare is an exact replay). `present-plan` for a draft requires a current plan and puts its digest into the design approval binding. `approve-plan` for a draft requires the plan (typed refusal otherwise), requires that the presented binding covers the plan digest, and inside the existing State writer transaction re-reads the PRD, Spec and design input and refuses on any difference (`PSP-APPLY-DRIFT`), then writes the digests into `continuity.authority`, removes the `sealed: false` marker and advances the continuity revision once (`allowContinuityAdvance`). The plan file is retired after the seal. `reopen-design` voids a prepared plan of a draft. A sealed or unmarked package takes the exact old path (pinned by LB4-19).
- `lib/design-approval-binding.mjs`: additive optional binding key `sealPlanSha256` (create, validate, verify take it as an optional key). It sits inside the binding, so the binding digest (the intent's subject) and therefore the one PO signature cover the plan digest; a package without a plan has the identical binding, digest and intent as before (LB4-8). No change to the intent, the signing path or the proof format, so existing signed approvals verify unchanged.
- `lib/plan-spec-state-v2.mjs` (`submitPlan`): a DRAFT package keeps its draft `continuity.authority` at the submission (it used to bind digests there, which would have sealed the package before the approval). The submission still records the PRD/Spec digests in `planSubmission` and still advances the revision; a sealed or unmarked package re-binds exactly as before. Consequence for the order: submit-plan, then prepare-seal, then present-plan, then approve-plan (a plan prepared before the submission is the plan of another revision and is refused with `PSP-PLAN-STALE`, exit `prepare-seal`).
- `lib/onboarding-continuity.mjs`: the mutual PRD/Spec pair check of the private promotion history is skipped for a draft (the design-input check stays); new export `readPromotionDesignInputCapture` (typed status `present|absent|drift|unavailable`) as the default provenance source.
- `lib/guard/sanctioned-args-scripts.mjs`: `prepare-seal` admitted with its closed flag set (no flag, or one/two `--review-receipt` with the same path rule as `present-plan`).
- Review binding sources the command reads: readiness review receipts passed as `--review-receipt` (their `sources` digests, the design input is found among the receipt companions), and `project/design-advisory-admission.json` (`admission.workflow.designSha256/evidenceSha256`). Both reviews already record the digests of the exact bytes they read (the readiness host store record `sources`, the advisory package binding that derives the receipt id), so no request record needed a new field.
- `lib/authority-seal-plan.test.mjs` (new, 21 cases LB4-1 to LB4-20): pure plan, every refusal code, the additive binding key, and real State walks through the public CLI sequence in chat mode (happy walk; draft -> prepare -> present -> a sealed byte changes -> approve refuses -> prepare -> approve refuses not-presented -> present -> seals; reopen-design voids a prepared plan and prepare-seal prepares again; a sealed package keeps its old path).
