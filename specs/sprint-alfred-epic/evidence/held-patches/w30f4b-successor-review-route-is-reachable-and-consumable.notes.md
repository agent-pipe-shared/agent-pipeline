# w30f4b — the successor-of-a-discarded-feature review route is reachable for an already registered successor, and the finalizer declares a later-introduced review unit (candidate 30f, C30F-G4B)

Applies AFTER the 30e chain plus C30F-G2 plus C30F-G4: the patch is the delta `0b702fe26a62..HEAD` of a clone that already holds all three, because it edits the same files. It does not apply to a checkout without them (`apply --check` on the C30F-G4 clone: exit 0; on the real repository before the chain: expected to fail). Criterion binding: AC-108 is the closest existing accepted criterion (a fresh bounded attempt under its unchanged text). The PRD and the Spec are unchanged.

## What it changes

- Observed (C30F-G4 notes, "Not changed"): no writer sets `supersedes` (`feature-package-registration.mjs` and `onboarding-continuity.mjs` write `null`, and an approved manifest cannot be edited without a new approval), and the finalizer read the review unit at the course's genesis base.
- Explicit predecessor input `successorOf` (a safe feature id), flag `--successor-of <feature-id>` on `prepare-dispatch.mjs critic` (pass-through, also kept in the "identical rerun" argv and named in the usage text) and on `critic-dispatch-preflight.mjs`. In the preflight it is a course selector: it becomes the optional sixth key of the closed `courseContext` and is handed to `readCriticCourseAdmission`; `deriveCriticCourseRegistrationCommit` takes it too, so the registration commit is still derived when no `--registration-commit` is given (without the flag nothing qualifies for a manifest holding `supersedes:null`).
- Admission (`critic-course-admission.mjs`): `successorOf` is an OPTIONAL key of the course request and of the identity input (absent for every ordinary course, so the closed shapes are unchanged for them). In `aliasRead` it must name a feature the State records as discarded (same reader as G4, now `discardedFeatureIds`), must equal the manifest's `supersedes` when the manifest declares one, can never name the feature itself and cannot turn a rename or split (a registered alias descriptor) into a successor. Every violation is refused with the new typed code `CCA-SUCCESSOR-OF`; `criticCourseRepair("CCA-SUCCESSOR-OF")` says what to do (record the discard, name the predecessor, or drop the flag). The flag only supplies the predecessor id: `successorGenesis` still demands the manifest unreadable at the base, the base a strict ancestor of the commit that first added the manifest, and that commit an ancestor of the candidate; with the explicit input the candidate's manifest may hold `supersedes:null`, never another predecessor. The course key subject, `COURSE_BINDING_KEYS` and the persisted records are untouched: the key is the G4 key, whichever way the predecessor was supplied.
- Later rounds without the input and without a manifest relation: the retained record stores only the course key, so `recoverSuccessor` recomputes the key subject for each feature recorded discarded and accepts the candidate that reproduces the retained key (and the retained first-added manifest sha). More than one match is refused `CCA-GENESIS-BINDING`; no match leaves the ordinary derivation, whose existing key check then refuses a mismatch as `CCA-GENESIS-BINDING`. The base manifest is probed only when a predecessor is supplied or a course is retained.
- Finalizer (`critic-generic-batch.mjs`, `reserveFeatureCriticReviewUnitOwnership`): the review unit is read with `git show <unitRef.commit>:<path>` and `readCriticReviewUnit` gets `declarationCommit` when that commit differs from the genesis base. `unitRef.commit` is the introducing commit the admission already resolves in `featureReviewUnit`: the reference of `readCriticReviewUnit` carries `commit` already, so no admission change was needed to expose it. It fixes the same shared cause for any review unit introduced after the base (D165-PF75B), not only a successor.
- Round cap, delta binding, `--confirm-full-round`, candidate binding, evidence-only classification and the alias route are untouched.
