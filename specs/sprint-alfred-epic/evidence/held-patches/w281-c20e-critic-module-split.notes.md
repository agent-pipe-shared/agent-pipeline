STATUS: Step 1 (measure) is complete and its answer is NO; the briefing's stop condition applies ("one round cannot carry several Critic children without weakening a check"), so no production code was written and there is NO `.patch` (the sibling check `w281-c20e-critic-module-split.check.test.mjs` is therefore red by design until a patch exists). ## What was measured

Greenfield `TabletApp_claude_070_3` (2026-11-08): the whole-feature Critic (about 10 modules, 287 tests) reached `DISPATCH-BUDGET-CHECKPOINT` at call 40 of 50 still in Phase 1; the grant of +40 was refused. Reading `lib/dispatch-budget-core.mjs`: `dispatchWorkingCap(65) = 65 - (CLOSING_ALLOWANCE 5 + SAFETY_MARGIN 10) = 50`; `effectiveDispatchWorkingCap` never rises above `maxTurns - CLOSING_ALLOWANCE - 1 = 59`; `dispatchGrantHeadroom(50, 65) = 9`. So no Critic can ever exceed 59 working calls, whatever is granted. (The greenfield repository is not on this machine; its range was not re-measured here.)

One review round, as the code binds it (all in `scripts/session-critic-finalizer.mjs` unless named):
- ONE packet: `admitSessionCriticReview` prepares and claims exactly one packet (`packetId`, 32 hex) over the whole range `base..candidate`, binds `sha256(canonical(preflightCriticDispatch(...)))` (`preflightSha256`, again at finalize: `SCF-PRELAUNCH-BINDING`) and ONE `sessionBinding.sessionId`.
- ONE reservation per round slot: `reserveGenericCriticBatchAdmission` / `featureReservationFor` (`lib/critic-generic-batch.mjs`) refuse a second packet for a reserved round (`CGB-BUDGET`, "Round N of this batch is already reserved for packet X"). N packets per round is therefore not possible without touching the round budget.
- ONE verdict and ONE receipt: `finalizeSessionCriticReview` -> `assertVerdict` (schema `critic-verdict.schema.json`, `additionalProperties: false`, a pass needs no blocker/major, no briefing violation, `trajectory_verdict` consistent) -> `recordCandidateResult` -> `consumeCandidatePacket` -> `receiptFor` (`session`, `verdictSha256`, `findingCount`, `reviewPass`, `independence`).
- The ORIGIN gate: `originGate` reads `source-return.json` of the packet. That record is written by `lib/critic-source-return.mjs` `issueForVerdict` from the Critic subagent STOP hook (Claude, Codex) or the Antigravity final-message hook: it binds the verdict sha256 of the FIRST Critic that returns to the one open admitted packet (`wx` create, "a second stop never overwrites", the next child gets `already-issued`; several open packets issue nothing).

## Answer to Step 1: no, not without weakening a check

N fresh Critic children under one admitted packet, merged into one verdict, run into the origin gate and nowhere else:
1. The first child's stop issues `source-return.json` with `sha256(canonical(child 1 verdict))`. `originGate` then requires the finalized verdict to equal that exactly (`record.verdictSha256 !== query.verdictSha256` -> `SCF-ORIGINAL-SOURCE-BINDING`). A merged verdict is never child 1's verdict, so on Claude and Codex (and Antigravity since G20-41) the merged round is REFUSED at finalize, after the whole review was spent.
2. Making the merged round finalize needs no record to exist. The only ways are (a) a child verdict the hook cannot extract (`extractCriticVerdict` returns null for a wrapped, non-schema message): no record, the merged verdict finalizes as `caller-authored-fallback`; or (b) a runner without a hook. That is the weaker label. `scripts/close-coordinator.mjs` `assertCriticIndependenceForClose` (C19-D2b) accepts it only at rigor 0 and low risk; every other close needs `pipeline-state.mjs approve-critic-acknowledgement` for that packet (a PO act). A whole-feature review is exactly the high-rigor case, so route (a) trades a budget problem for a PO acknowledgement on every split round and silently degrades the evidence gate on purpose. That is a weakening, not a design, and was not built around.
3. Not an obstacle, checked: one packet and one receipt per round are kept by a merge (the children are workers under the single packet; the packet diff covers the whole range, a child reads `git diff <base>..<candidate> -- <its paths>`); fresh context and path-only input hold per child because each child is an ordinary Critic dispatch from the same template; the 24 h review window (`SESSION_REVIEW_TTL_SECONDS`) covers sequential children; the verdict schema needs no change (merge = `pass` is the AND of the children, findings the union, `briefing_violations` the union, `trajectory_verdict` the worst of `inconsistent` > `not verifiable` > `consistent`; `assertVerdict` then behaves identically on the merged object).

So the only missing piece is origin evidence that covers several children. Changing it is a change to the independence evidence of the review (a guardrail/trust-boundary surface, class G) and was outside this dispatch's brief.

## Smallest design that keeps every check (NOT built)

1. Preflight (as briefed, additive, library result byte-identical): a `split` field in the w277 wrapper when the changed files exceed ONE named constant `SPLIT_MAX_CHANGED_FILES`, derived in its comment from the working cap (`dispatchWorkingCap(65) = 50` calls, of which about half are available to the read phase before the verdict is composed: 25 files at one read per file). The constant is a first estimate from the briefing's measured facts (call 40 of 50 still in Phase 1 for about 10 modules); calibrate it from the greenfield `diff --stat` before building. One entry per module of the approved architecture plan (`readPrdModules` + the cut of `lib/module-dispatch-scope.mjs`; the PRD is located from the feature of `--spec`), each with a path-only `reviewerInput` (the parent's input plus that module's owned changed paths), plus ONE shared entry for every changed path no module owns (never dropped). No approved plan for the feature: only the shared entry, flagged. The w277 case "actual direct CLI preserves complete packet-ready ... protocols" strips the admit fields before comparing with the library result; it needs a second in-place restatement (strip `split` too, comment G20-72, criterion kept). Per entry an MP-07 `Batch scope (MP-07):` line naming the module (the dispatch policy checks it per Critic prompt).
2. Merge: a pure script (JSON in, JSON out, no finalizer verb, so no auth-gate inventory change) `scripts/critic-split-merge.mjs --split <split.json> --child <entryId>=<verdict file> ...` that refuses a missing child, a child whose findings cite a changed path of another entry (the verdict has no id and no path field: scope is judged on the `evidence` text against the split's changed-path list), and a duplicate finding id. The schema has no finding id either: define it as `sha256(canonical({spec_ref, evidence}))` and say so. The entry a child reviewed is carried by the dispatch prompt (first words of `trajectory_evidence`: `scope:<entryId>`), a free string, so no pinned file or schema changes.
3. Origin evidence for a split packet (the part that needs the decision): (a) `admit` binds the digest of the `split` object into the admission record (it already holds the course digests); (b) the stop hook issues one record per returning child (`source-return-<verdictSha8>.json`, same `wx` rule, same packet/session/claimant fields) instead of one per packet, only for a packet whose admission carries a split; (c) `originGate` for such a packet requires N records, the merged verdict to equal the merge of exactly those verdicts, and the entry ids to be distinct and complete; the label stays `source-issued-origin`; (d) the receipt gains an optional `splitSha256` so the finalized receipt of a merged round verifies the same way. Files this touches: `scripts/critic-dispatch-preflight.mjs`, a new merge script, `lib/critic-source-return.mjs` (and the hook that calls it), `scripts/session-critic-finalizer.mjs` + `lib/session-critic-finalizer-read.mjs`, the packet admission validator. None is in the Critic preimage pin; a new kernel import must keep GMWKC01 green with its threat-model entry.
4. Cheaper alternative the PO may prefer instead of 3 (decision, not mine): ship 1 and 2 only and let a split round finalize as `caller-authored-fallback` (needs `approve-critic-acknowledgement` per packet above rigor 0). Buildable now, but it deliberately lowers the origin label for exactly the large reviews.
