## Changes
- finalizer: new `resumeHeldGenericPacket()` called first in admit. Generic-batch requests only (feature requests need the preflight for their course). It reads the existing packet (claimed read, then prepared read), requires the same taskId and the same resolved candidate commit, then returns `already-admitted` if the admission exists, otherwise finishes the half-done work (claim if needed, reserve, publishClaimedSessionAdmission) and returns `admitted` with `resumed: true`. Anything that does not match falls through to the unchanged path. New CLI verb `release` (request `pipeline.session-critic-release-request.v1`: packetId, reason) beside `export`.
- `lib/critic-packet-release.mjs` (new): `releaseCriticPacket`. Only prepared or claimed (else CPR-PHASE); reason 3..200 chars with no path characters (CPR-REASON); append-only `released/audit.jsonl` record (schema, packetId, phaseBefore, reason, releasedAt, actor; no account data, no paths) written BEFORE the move; reservations (`generic-batches/*/*-admission.json` naming the packet) are renamed `released-<id>-...`; the packet directory is renamed into `released/` (nothing deleted; `released` is not 32-hex so the held scan ignores it); second call returns `already-released` and writes no record; symlinked control root, packet, batch or released directories are refused.
- `critic-generic-batch.mjs`: `GenericCriticBatchError` takes an optional detail; the CGB-HELD refusal names the held packet id and the release verb. Default message unchanged for every other code.
- `critic-packet-preflight.mjs`: only the inherited PF-93 changes; nothing added for D60.
