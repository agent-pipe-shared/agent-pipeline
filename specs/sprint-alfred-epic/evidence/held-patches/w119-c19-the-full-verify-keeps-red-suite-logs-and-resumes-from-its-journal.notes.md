# w119 — the Full Verify keeps a bounded log of red suites and can resume an interrupted run (candidate 19)

Applies on the chain at the base `c0bed9f7f`. Criterion binding: AC-140 is the closest existing accepted criterion; the PRD and the Spec are unchanged.
Source: the candidate 18 Full Verify runs (2026-11-02). After a run the root cause of a red suite had to be rebuilt by re-running it, and a run the PO stopped on purpose (about one hour) had to restart from zero.

## What it adds

- `verify-journal.mjs` KEEP: when a suite exits non-zero, `buildRedExcerpt` writes `logs/<id>.red-excerpt.log` in the run directory: a header (suite, exit code, suite file relative to the repository root, how many lines were kept), then the last 200 lines, at most 64 KiB in total. The text goes through the repository's `redactResidualHostPaths` (capture-evidence.mjs) plus a pass that masks `NAME=value` pairs whose name contains TOKEN, SECRET, PASSWORD, API_KEY or PRIVATE_KEY. The environment is never read or logged. The suite's `completed` progress line gains an `excerpt` field with the relative path, only for a red suite; a green suite writes nothing and its line is unchanged.
- `verify-journal.mjs` RESUME: `loadVerifyResumeSource` reads an explicitly named earlier run (parameter `resumeFromRunId`, default from the environment variable `PIPELINE_VERIFY_RESUME_RUN`). A suite is skipped only if its last journal entry in that run is `completed` or `resumed`, for the same candidate commit and tree, with an exit-0 receipt whose digest, implementation, environment contract, inputs and log all match. A suite left at `started` is re-run. A source run of another candidate is refused with `VERIFY-RESUME-CANDIDATE-MISMATCH` before any suite runs; a missing, invalid or still-active source has its own typed code. A skipped suite is re-sealed into the new run as a receipt and a `resumed` progress line, and appears in the steps as `reused: true, resumed: true`, so the final record stays complete and is not counted as freshly run.
- `scripts/full-verify.mjs`: `--resume` picks the newest earlier run directory of the same clone, passes it through the environment variable (no change to `harness/scripts/verify.mjs`, which is protected), writes to `scratch/<label>-output-resume.txt` so the first output is kept, and the summary says how many suites were resumed over. `--resume` is separate from `--reuse` and `--no-reuse`; without it behaviour is today's.
- Tests: 5 new cases in `verify-journal.test.mjs` (KEEP; RESUME by parameter; by environment variable with a started-only suite re-running; candidate mismatch refused with no suite run; no flag means no resume) and a new `scripts/full-verify.test.mjs` with 3 pure-function cases.

## Not changed / not proven

- `harness/scripts/verify.mjs`, the evidence schema, receipt schema, exit codes, suite list, order and policies, and `--reuse` are untouched. The progress line schema is unchanged apart from the optional `excerpt` key.
- `scripts/full-verify.test.mjs` needs registration in the Verify suite list. The case count of the `verify-journal` suite grows by 5, so a case-completion policy for that suite (harness/verify-suites.json) may need to be extended by the Elephant; neither was touched here.
- Test-first order was not followed by the Goldfish: the production edit was written before the new cases were run (budget). The Elephant added the RED proof afterwards: the new test file run against the ORIGINAL `verify-journal.mjs` in a clone directly below the home directory gives 95 of 100 pass and 5 red; three of them are the new cases (KEEP; RESUME of the same candidate; RESUME refused for another candidate), the other two are the pre-existing reds below. The two remaining new cases (resume through the environment variable with a started-only suite; no flag means no resume) also pass on the original code because they assert behaviour that does not change; they pin it.
- `verify-journal.test.mjs` is 98 of 100 green with the change and 95 of 100 on the original code: the two red cases (`an already-bound cleanup owner remains borrowed ...`, `interruption keeps a borrowed descriptor ...`) fail with `SessionAuthorityError: domain-ancestor-unsafe` on the ORIGINAL code too (measured by the Elephant). They are an environment effect of running the file alone with a TMPDIR under `/tmp`, not caused by this patch; the Full Verify runs them with its private TMPDIR.
- The chained resume case (resuming a resumed run) is supported by the code (`resumed` counts as completed) but has no test. A full one-hour run was not made.
