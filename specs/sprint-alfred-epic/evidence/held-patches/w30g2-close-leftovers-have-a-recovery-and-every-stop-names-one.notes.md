## Deviation: Part A case 2 (the committed manifest already lists the file)

The briefing asks for "produce the evidence again with its producer command and register it with `--add-verify-evidence`". Reading `addVerifyEvidence` (`lib/feature-package-registration.mjs`): when the manifest already lists the path and the bytes differ from the registered digest it refuses `FPR-VERIFY-IMMUTABLE` ("registered evidence is never replaced"), and a fresh Verify run never reproduces the same bytes (timestamps). The named route would be refused, so it is NOT printed; the proven routes above are. This is a briefing-versus-repo contradiction (stop condition 2): the work is delivered with the corrected text and the question is left to the Coordinator.
