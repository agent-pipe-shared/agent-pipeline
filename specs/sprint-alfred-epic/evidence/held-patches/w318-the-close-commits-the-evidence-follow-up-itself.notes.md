## What it changes

- `scripts/finish-feature.mjs`, closed-local branch, `closeFollowUp()` (phase `closed-local` only, as in w314): after `prepareCloseAuditFollowUp` wrote files it commits EXACTLY those paths. The commit facts come from the same `commitOf` the close commit already uses (paths, subject, `armWriterCommitCapability`: a project that protects `audit-bundles/**` gets the capability armed by the writer before the commit, `commit.capability` is its id). The commit itself is `git add -- <paths>` then `git commit -m <subject> --trailer "AI-Assisted: true" --trailer "Dispatch: stage-0 (elephant)" -- <paths>`, run through the close's own `runner` (repository hooks stay on): the same subject, paths and trailers the printed `writerCommitSteps` name, with `-m`/`--trailer` instead of the message file (the writer's steps are a recipe for a human or an agent shell; a script needs no file).
- Result: `followUp.status` is `committed` (commit facts without `steps`, nothing left for the caller) or, when the commit fails or is refused, `written-uncommitted` with `followUp.code` (`AB-FOLLOWUP-COMMIT-REFUSED`), `followUp.reason` (git's own text, at most 300 characters, naming `followUp.commit.steps` and `pushEvidence`) and the unchanged B4 `commit.steps`. The close stays `closed-local`. A refused commit un-stages what the close staged (`git reset -q -- <paths>`), so nothing foreign rides on a later commit; the files stay on disk. Nothing is stored: the status is derived from the writer's result and the commit exit, and a rerun derives it again from git.
- Exactly the written paths: for a fresh `written` result the path set is the writer's file list (`commitOf` got an optional `only` filter). A rerun at the same HEAD (`already-followed-up`: list written, commit missing) derives the uncommitted paths under the bundle's `proofs/` and keeps only the names the writer gives its files (`follow-up[-NNN].json`, `NNN-<kind>.json`). A foreign staged file stays staged and uncommitted; a foreign file in `proofs/` stays untracked (both pinned).
- Idempotent: a second call at the new HEAD returns `nothing-to-carry` (the evidence is carried by the list the first commit holds) with no second commit and no `next`; a rerun after a refusal returns `committed`.
- `next` says the final Verify at HEAD (`pushEvidence`) runs AFTER the follow-up commit (it moved HEAD): `committed` has its own text, `written-uncommitted` keeps the B4 text. `pushEvidenceStep` captures no HEAD (it names the command only), so nothing is stale.
- Ordering: `followUp` is now computed BEFORE `featureRangeCommitSplit`, so the commit split (`commits`) counts the follow-up commit (pinned: the second call's split equals the first's).
- `lib/security-close-status.mjs`: `closeFollowUpSentence` knows `committed` ("... and committed it (exactly those files, followUp.commit.paths) ...") and `written-uncommitted` ("... but could not commit it (followUp.reason). Commit them with followUp.commit.steps ..."); `already-followed-up` without a pending commit now reads as nothing-left-to-add.
