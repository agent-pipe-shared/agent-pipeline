## Blocking finding (read from the code; now resolved, see above)

Dependency readiness (`observeGovernedItemIntegrationReadiness`, the worktree read in `computeNativeIntegratedSlices`) refuses while an integrated item's check source differs in the working tree; the refusal is raised by comparing the current check files with the `files` snapshot stored in `authority-integration-<sha>.json` (NGHS12 asserts it: a weakened checker must not release a dependent). The union with commit evidence replaces the integrated fact, not this refusal. After the retirement of step 2 the record is no longer in the namespace, so for a slice that commit evidence proves (dispatch id equal to slice id, the production shape) a weakened checker would no longer refuse the readiness read. That is a gate change (hard limit 3) that no case of the suite shows: `NGHS12` keeps its record because its dispatch id differs from its slice id, and `NGHS72` now passes without an integration record on disk, so it no longer exercises the K-37 read. Continuation candidates for the Coordinator: read the check snapshot from the retained aside in the readiness read (then the gate is derived from retained files), or keep the integration record out of the retirement (not possible while the host state reader refuses an authority record whose pending file is gone), or retire only when the snapshot is provably equal to the committed check sources.

## Step 1 — read-only proof (SM-8)

- The integration record `authority-integration-<pending sha>.json` is written in `integrateNativeGoldfishItemDeliveryOnce` (`lib/native-goldfish-host-state.mjs`), inside `withSessionAuthorityBoundary`, i.e. while the registry lock is held. The same boundary then refreshes and releases the registry member.
- The registry baseline of the native-goldfish producer is the membership hash of the whole host-commit directory. It is re-derived only inside `updateMembership` (the release). A file moved after that leaves the baseline stale, and the registry's own `healDrift` refuses to re-anchor while a bound member of the producer is armed or running. That is finding A7-3. A file moved before the release breaks `observeTerminal` (it reads the integration record).
- Failing-first cases written before the production edit and run RED against the unchanged code: `NGHS75` (the pending file of the integrated dispatch was still on disk after the integration) and `NGHS76` (no `retirement` report).

## Step 2 — what the patch changes (SM-9)

- After the release, in the same boundary, `retireIntegratedNativePending` moves the pending file, every `authority-*-<sha>[-<rev>]` record (it reuses `planSettledPending` of `lib/routine-repair.mjs`, so the sibling rule has one home) and any Codex `agent-*` association into `session-authority-abandoned/<stamp>-<12 hex>-integrated-pending/` (retained, never deleted), then re-anchors the producer baseline with the existing `healSessionAuthorityDrift` (no new registry code, no new stored status, no record shape or digest byte changed). The heal writes its usual `-drift-heal` marker, so every retirement leaves one retained marker next to the aside.
- It runs only while every fact is derived from the files in that boundary, and keeps the pending state otherwise (the report says why and names `routine-repair.mjs run settled-pending-aside`; heal retires it later exactly as before):
  - another pending state has no terminal record (a dispatch is in flight; its lineage proof or public terminal files may name this one): a running dispatch is never treated as "not in flight" (`NGHS76`);
  - a sibling still on disk names this pending state in the `foreignCommits` of its terminal receipt;
  - commit evidence (`Dispatch: <slice> (goldfish)`) does not prove the slice integrated: the integration record is read by dependency admission, so it leaves only when the same fact (the slice is integrated) is derived from commits; the checker-snapshot refusal it also carries is NOT covered by this guard (see "Blocking finding"). `NGHS12` (dispatch id different from the slice id) asserts the KEEP;
  - the files cannot be planned (symlink, unreadable), moved, or the baseline cannot be moved: files moved so far are put back.
- The stale in-memory operation of a process that scanned before the retirement (a sibling stop of the same hook process, an admission that waited on the lock) is dropped by the scan only when the retained aside proves this step retired its pending state (`retainedIntegratedAside`, read from the retained files: the integration record named by the full digest and a pending file whose bytes hash to it). Every other missing pending state keeps `native-authority-missing-pending`.
- A replay of `integrateNativeGoldfishItemDelivery` is still answered `integrated, replayed: true`: from the retained aside when the pending state is gone, or by asking the retirement question again while it is kept.
- The result gains an additive `retirement` field (`retired` with aside name and file count, or `kept` with reason and repair). Only `integrated` has a writer; `integrated-by-commit` and `cancelled` stay derived on read and retired by heal.

## Deviations and things to know

- The answer of a replay from the retained aside returns before the owner, ancestry and check-source checks the old replay ran (it has nothing left to check them against); it states a fact about retained files, not a new verdict. A replay that finds the pending state still on disk may now retire it, so a replay can write where it only read before.
- Every retirement writes one `-drift-heal` marker (the existing heal's retained prior producer record).

## Step 3 — built (routine-repair.test: 53 of 53 pass; session-authority-repair.test 48 of 48 incl. the new SAR04b)

`proveNothingInFlight` (lib/routine-repair.mjs) is consumed by heal; `session-authority-repair.mjs inspect` lists in-flight members (id, phase, binding digest), adds the binding digest to reservation rows (`nativePendingBindingSha256`, one home shared with the scan) and, only while a member is in flight, the open dispatch-record liveness verdicts and the derived `nothingInFlight`. Cases (RED before the edit for the first): gone proves and heal runs without the flag and records the proof; alive (with any reservation state), unjudgeable, no open record, another alive record, a member of another producer, an unlisted member and an unmapped member never prove (heal defers, the deferral text names why and keeps the flag command); the flag still works. The text below is the design as written before the build.

Heal proving "nothing in flight" itself instead of the hand-given `--no-goldfish-running` is not in this patch. Design for the continuation (fail closed; derive, never store):
- `session-authority-repair.mjs inspect` lists, per producer, the bound members armed or running (member id, phase, binding digest), adds the binding digest to each reservation row (one exported helper in `native-goldfish-host-state.mjs`, used by the scan too) and the open dispatch-record liveness verdicts of `dispatch-record-liveness.mjs`.
- A pure `proveNothingInFlight(inspect)` in `lib/routine-repair.mjs`: proven only when no dispatch record is judged `alive`, every in-flight member belongs to native-goldfish and maps to exactly one reservation whose dispatch record is judged `gone`. `alive` beats any reservation (a Goldfish that committed by itself may still run); `unjudgeable`, an absent record, a `cancelled` reservation, a member of another producer or a producer that lists no members never prove. Heal then takes the branch it takes today for `--no-goldfish-running`; every other case keeps today's deferral and the flag as the fallback.
- Failing-first cases: alive plus `integrated-by-commit` stays deferred; gone proves; unjudgeable, absent and other-producer members do not.
