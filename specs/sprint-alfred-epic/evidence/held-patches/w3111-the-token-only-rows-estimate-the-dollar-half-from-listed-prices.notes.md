The Critic is suspended by the PO for candidates of this repository and no Full Verify ran: this change is verified by tests only.

## What

PO decision 2026-11-19: list prices for all runners, the dollar half is ESTIMATED and labelled as an estimate.

- New data file `config/model-list-prices.json`: per model `input`, `cachedInput` (null = cached tokens priced at the input price, an upper bound) and `output`, in US dollars per million tokens; top-level `source` ("third-party list-price trackers, 2026-11-19; not verified against the vendor page; estimate"), `asOf` "2026-11-19" and a note that vendor pages win. Entries: gpt-5.3-codex and gpt-5.2-codex 1.75 / 0.175 / 14.00; gpt-5-codex 1.25 / null / 10.00; gemini-3.8-flash and gemini-3.6-flash 1.50 / 0.15 / 7.50 (the higher listing, PO decision; the introductory 0.75 / 3.75 is not used); gemini-3.1-pro 2.00 / 0.20 / 12.00 (up to 200K context); gemini-3.1-flash-lite 0.25 / 0.025 / 1.50. Each entry says it is low confidence. No schema or registration list names the config files, so none was touched.
- `usage-ledger.mjs`: the Codex and Antigravity rows price the token sums. The existing Claude mechanism is reused (`estimateUsd`, `fmtUsd`, `fmtDe`, dollars per million); only the table is the new file (the Claude table `scripts/model-prices.json` and the default Claude path are untouched, byte-identical). A model name is matched by the longest listed name that is a prefix at a `-` boundary after the tier or effort suffix (`-minimal|-low|-medium|-high|-xhigh|-max`, optionally `-tiered`) is dropped: `gemini-3.8-flash-medium` prices as `gemini-3.8-flash`, `gemini-3.8-flashy` has no price. The dollar half prints as `approx $X (estimate from list price, <asOf>; cached tokens at <rule>)`; the row says its model source (`model source: observed | configured route | argument`); the total reads `TOTAL approx $X (estimate from list price, <asOf>)`; the notes say it is an ESTIMATE from third-party list prices, not verified, vendor pages win. No match: `$ unavailable (no list price for <model>)`.
- Antigravity model: optional `--model <name>`, else the project's configured `duty.implement` route for Antigravity from `pipeline.user.yaml` in the working directory, read with the existing reader `readProjectRouting` (no hand-written yaml parsing); only the project's own validated routing counts, the plugin registry fallback does not. With neither: `$ unavailable (model not recorded; pass --model <name>)` and no dollar. `--model` is refused for `--codex-rollout` and for a malformed or repeated value, each refusal naming the runnable form.
- Cached tokens: Codex defines `input_tokens` to include `cached_input_tokens`, so only input minus cached is priced at the input price and the cached part at the cached price. For Antigravity whether input includes cache-read is not measured, so cache-read is counted in addition to input (an upper bound, printed in the row). Several models in one rollout: dollar half unavailable ("several models in one rollout, no per-model split"); no model: "model not recorded in this rollout".
- Texts: `close-feature/SKILL.md`, `runner-capabilities.json` (cells, with the guide table in `happy-path.md` as its row-for-row projection, and its close step 4 line) and `close-light-and-extensions.md` now say "token row plus an estimated dollar half from list prices (labelled)" instead of "token-only, no dollar".

The B5 rows left the dollar half empty; the PO decided the closer should get an estimated, clearly labelled figure instead.
