## Decisions the briefing left open

- Single-input limit: the CLI takes exactly one `--input` and the catalogue pins six arguments (a protected file outside the scope), so the three
  per-runner files each carry the runner's pipeline case plus the same Codex no-pipeline control case, and the published comparison
  was generated from the Codex file only (Codex with vs without the Pipeline, the one same-runner pair). A cross-runner comparison needs
  a multi-input command and a catalogue change; that is the follow-up. Stated in the README.
- `pipelineVersion` is a third additive field beyond the two the briefing names: the backlog acceptance says each evidence file "names the
  Pipeline version", and the case had no field for it.
- `taskSha256` is the digest of a publisher-declared label printed in the README (the briefs are not in the committed material); a test recomputes it.
- Values the reports state only rounded, or inconsistently, are `null`: Claude input/cache tokens; Claude and Antigravity `waitMs` (reported
  wait plus active exceeds the reported wall interval); `firstCode`/`initialBuild` everywhere; `cacheWriteTokens` everywhere; `rulesetSha256`
  everywhere (the Antigravity `sourceSha256` is a plugin source digest, not a ruleset digest). Claude `outputTokens` is the per-phase table sum
  (595678); its prose total (~608k) disagrees and is not used. Codex `waitMs` is wall minus active (904800), matching the report's rounded 15.1 min.
- Dates: the Antigravity report prints none; 2026-10-25 comes from the evidence folder name. Claude (minutes) and Antigravity (seconds) instants are
  padded with zero milliseconds. All of this is in the README.
- Refusal codes are counted as named in each report's event listing (Antigravity rows counted per row; Codex names only two). Not a refusal census.

- Consumer-name guard: the committed-set test derives each analysed repository name from line 1 of the sanitized reports and asserts no published file
  contains it, so no consumer name (not even a prefix) is spelled in the test file. Added after a first draft that spelled a prefix literal.
- Provenance: which report line each number came from is recorded only in the generator `scratch/agent-out/w7gfcmp/gen-observations.mjs`
  (untracked, outside the scope); the README gives the rules, not per-field provenance. Critic: read that script next to the reports.
- Failing-name sets: both registration runs print 16 UNREGISTERED lines (same pre-existing suites). Had either new suite been unregistered the clone
  would print 18, so neither is in the set; the two extra inventory FAILs in the clone name exactly the two new suites.

## Driver defect to know about

`driver.mjs revert` saves each production file as `saved-<basename>`. The two production files here share the basename
`greenfield-public-comparison.mjs`, so the second save overwrote the first and the restore wrote the CLI script over the library (and set mode 755).
I rebuilt the library from the candidate text plus my three hunks, reset the mode to 644, and confirmed with `git diff` that only my hunks differ and
`git diff --summary` is empty; all suites were re-run afterwards (c3). The revert proof itself ran against genuinely checked-out candidate files, so it stands.
Do not use `revert` for slices whose production files share a basename without fixing that.
