## 1. What it changes (all in `critic-course-admission.mjs` and `review-economy.mjs`; nothing stored changes)

- ONE helper, `splitCriticDeltaChangedPaths({ repoRoot, featureId, baseCommit, candidateCommit, changedPaths })` (exported), returns `{ behaviourPaths, evidencePaths }`. It is derived from the existing per-commit classifier, never from a second path list: for each commit of `base..candidate` it asks `classifyEvidenceOnlyCommit` with the `followers` profile (manifest registrations, exports of consumed reviews, disposition addenda; chosen deliberately: it is the briefing's list, and the `carry` profile would also exempt close and documentation commits) or the course's own registration rule `evidenceCommitV2` (the rule the course counters already use for what is not a correction) CONFINED to commits whose every changed path is the manifest or lies under `specs/<feature>/evidence/` (the course rule itself accepts any registered path, so a source file registered as candidate-evidence would otherwise have been exempted; C31-M11-6 was written RED first and shows exactly that). A changed path is registered evidence only when EVERY commit of the range that touches it is evidence-only; a path that any correction commit also touches is behaviour. A merge, an unreadable range, an unknown feature or a malformed input exempts nothing (the strict result).
- `requestRead` (was `CCA-DELTA-MAP` on "keys equal the changed paths exactly"): the map must key every behaviour path and may key only changed paths; an evidence path may be keyed (the unchanged verb still writes full-key maps) but need not be. `request.changedPaths` is still compared to the full range diff (`CCA-DELTA-BINDING`): the Critic still sees the evidence paths as changed paths. The read result carries the derived `evidencePaths`; it is not part of any hashed or stored object.
- `deriveCriticCourseAdmissionV2`: the admission attempt carries `evidencePaths` (only when there are some). `review-economy.mjs` `admitReviewAttempt`: new optional binding `evidencePaths` (a duplicate-free list of changed paths, else `RE-DELTA-BINDINGS-INVALID` naming the field and the expected form); `RE-DELTA-UNKNOWN-PATH` skips those paths only; `affectedInvariantIds` stays the union over every keyed path, so a full-key request yields the same decision bytes as before. Absent `evidencePaths` is today's strict rule for hand-built callers.
- `prepareRegisteredCriticDeltaRequest` (about line 1152): NO edit; this is the place where the briefing's premise did not hold (it lists this spot as one that must move). The function stores the supplied map verbatim and `changedPaths` from the raw range diff, the descriptor keeps the full changed path list by design (the Critic must still see the evidence paths), and nothing there enforces a key (the verb and the reader do). Adding a coverage check there would, by reading the verb's error mapping (REASONED, not run), turn its `FPR-DELTA-MAP` refusal into `FPR-DELTA-COMPILE`, which `PF94 DELTA (c)` pins.
- The stale help step 3 of the course repair (about line 144) now names the two required and the two optional input fields.
