# w3112 — the delta registration verb needs no invariant key for registered evidence paths, and the help says so (candidate 31, C31-M12, lane L10a verb part)

Chained patch: it is the delta `05d306e0920c295e5b48dd56511bf51492f87348..HEAD` on the base clone of candidate 31 that already carries the held patches w312 (C31-M2) and w3111 (C31-M11, the reader side). ## 1. What it changes (nothing stored changes)

- `feature-package-registration.mjs` `addCriticDeltaRequest`: the unkeyed range paths are now filtered through `splitCriticDeltaChangedPaths` (the helper w3111 added to `critic-course-admission.mjs`; the verb imports it, no second path list). A registered evidence path of the range (lineage file, registered diagnostic and log, registered Verify evidence, the manifest) is no longer refused `FPR-DELTA-INVARIANT-UNKNOWN`, gets no stand-in id for the compile and no key in the registered map. A changed source path without a key is refused exactly as before (typed code, the paths, the example from lane M2, the one command); the text now also says the registered evidence paths need no entry. `FPR-DELTA-MAP` (a key that is not a changed path) is unchanged. `descriptor.changedPaths` is unchanged: the Critic still sees every changed path. A path the course registered ids for earlier is still filled in from them (so the C31-M2 same-digest behaviour holds).
- The path skeleton the verb writes for a missing input file still lists every changed path (the consumer-chain-walk pin, outside this write list, pins that); its completion sentence now says how many of them are registered evidence that needs no entry. The function got the feature id parameter for that.
- `register-feature-package.mjs` help: new line "pathInvariantMap needs an entry for every behaviour path ...; registered evidence paths need no entry"; the refusal line says "A changed behaviour path with no registered id". The help no longer says the map must hold exactly the changed paths (that sentence had already gone with C31-M2; no remaining text claims it).
