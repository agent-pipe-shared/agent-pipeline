# w316 — Recursive grep is admitted behind its own all-files tree screen (candidate 22b)

Delta on the candidate 22b chain (clone base 13335278821, one change commit on top: tests first, then the change). Closest accepted criterion: AC-108 (PRD and Spec unchanged). Built by a Goldfish in a clone; delivered as a held patch that the PO applies (the grammar files are kernel paths, `NEVER_LIFTABLE_KERNEL_PATHS`). PO decision of 2026-11-09: agents type `grep -r` very often and every refusal costs a turn, so the shell grammar admits it for the shapes agents actually type, behind a screen of its own.

## What

1. **`lib/passive-read-policy.mjs`: a second tree screen, selected by an option.** `isAllowedPassiveReadTarget` takes `allFiles` (default off) and `excludeDirs`. With `allFiles: true` a directory operand goes through `safeAllFilesTree` instead of the rg-inventory screen `safeRecursiveTree`; the rg route is not edited (the old function and every other caller are byte-for-byte the same, the option is off unless asked for). The new screen uses no rg and no ignore semantics:
   - it visits every entry under the operand, hidden and ignored ones included, and refuses the operand beyond 10000 entries (same bound as the existing fallback; the operand directory itself counts as the first entry);
   - it refuses on any secret basename (the shared `SECRET_BASENAME` rule) or protected root, for the lexical and the physical identity of each entry;
   - a directory named `.git`, or a `.git` file, anywhere under the operand refuses it, and so does an operand that sits inside a `.git` directory, unless the command names `.git` in `excludeDirs`; the comparison for the refusal is case-insensitive, the comparison for an exclusion is exact (case-insensitive only on win32), so `.GIT` is never pruned by `--exclude-dir=.git` on a case-sensitive host;
   - `excludeDirs` (plain directory names only: no slash, no backslash, no glob character, not empty, not `.`/`..`) prunes exactly the directories with that name at any depth, which is what `grep --exclude-dir=NAME` does; nothing else is relaxed (a secret name is refused whatever is excluded);
   - a symbolic link met during the walk is not descended (grep -r does not follow one). Its name and its resolved target are screened (secret basename, protected roots); a link whose target lies outside the operand's tree is refused; a dangling link is ignored. A link given as the operand itself is followed, as grep does for a command-line operand.
2. **`lib/guard/shell-grammar.mjs` (`isSafeExactGrepArgs`) and `hooks/guard-command-grammar.mjs`.**
   - Boolean flags added: `-r`/`--recursive`, `-l`/`--files-with-matches`, `-w`/`--word-regexp`, `-s`/`--no-messages`; the clusters `-rn`, `-rl`, `-rln`, `-rE`, `-ril` work through the existing `expandBooleanShortClusters`. `-R`, `--dereference-recursive`, `-f`, `--file`, `-P` and `-z` are not in the set, so they stay refused (also inside a cluster).
   - With `-r`, and only with `-r`, a path operand may be a directory and is judged by the new screen; without `-r` the file-only rule (`isSafeExactPassiveFile`) is unchanged. An operand-free `grep -r x` stays refused.
   - Filters: `--include=GLOB`, `--include GLOB`, `--exclude=GLOB` take the bounded filename shape that rg's `-g` already has (`isBoundedFilenameFilter`, now exported from `guard-command-grammar.mjs`, no new module edge: `shell-grammar.mjs` already imports from it); `--exclude-dir=NAME` takes one plain name. Each kind at most 8 times. Filters may stand before the pattern or after the operands (`grep -rn x . --exclude-dir=.git`), as GNU grep reads them. Only `--exclude-dir` is passed to the screen; `--include` and `--exclude` relax nothing.
   - The pipeline source legs use the same function (`isValidScopedPipelineGrepSourceArgs` delegates to it), so `grep -rn x src | head -n 20` works. The pipeline sink `isValidPipelineGrepArgs` is untouched: no `-r`, no filter, no `-l`.
3. **`lib/read-command-diagnosis.mjs` + `lib/guard/evaluate.mjs`: refusal help.** `recursiveGrepHint` is asked only when no glob value and no single flag explains the refusal. It names ONE command, and only after `isReadOnlyDiagnosticCommand` admitted exactly that string: the same command with `--exclude-dir=.git` appended, else the `rg` form (`rg -n <pattern> <paths>`, built only from flags that mean the same in rg: `n i l w F v c H o`; `-r`/`-E` are dropped because recursion and regular expressions are rg's defaults). A command with a filter, `--`, `-R`, a pipeline or a redirect gets no rg form; nothing is printed when no candidate is admitted (for example a `.env` at the top: both screens refuse it). The refusal prints it as `Rejected element: the tree this recursive search reads (an admitted spelling of the same search: ...)`.
4. **Printed grammar list** (`lib/guard/grammar-denials.mjs`): one clause added to the "listing and context forms" entry (recursive grep, the filters, when it is admitted, `-R` not admitted, the `rg -n` alternative).

## Why the screen is safe (measured, not assumed)

- Real-reach test (`lib/passive-read-policy.test.mjs`, last case): for each fixture the REAL `grep -rc NEEDLE .` is run (it prints one line per file it opens, matching or not) and the files it opened are classified by an oracle that is independent of the screen (secret file name, or inside a `.git` directory). The assertion is two-sided: where the screen admits, nothing sensitive was opened; where it refuses and the fixture is not a link case, grep really did open a sensitive file (so a refusal is never vacuous). Fixtures: plain, `.env` at the top, `.env` ignored, key under an ignored directory, key under a hidden directory, `.git` directory, `.git` excluded, `.git` file excluded, `node_modules` pruned, link to a secret, link out of the tree, link inside the tree. It also asserts, on the real binary, that grep -r does not read a link met during the walk.
- The probe `scratch/agent-out/grep-r-probe.mjs` (the coordinator's measurement) showed the gap this closes: with the rg screen, `build/deploy.key` under an ignored directory, `.cache/deploy.key` and `.git/config` pass, and grep -r reads all three.
- The unit cases of the screen itself are in the same file (secret names everywhere, `.git` as directory, file, nested, operand inside it, exclusion by name only, links, 10000 boundary exactly, the rg route unchanged).

## Decisions taken inside the briefing (and why)

- **A link that leads out of the operand's tree is refused**, although grep -r would not read through it (the real-reach test proves that). The briefing lists it as a negative fixture; refusing is the conservative reading and costs only a rare spelling (the `rg -n` form is the alternative). An in-tree link, a cycle and a dangling link are admitted.
- **`--exclude-dir=.git` also admits a `.git` FILE (a worktree pointer).** The briefing says the operand is refused unless the command excludes it. GNU grep prunes only directories by `--exclude-dir`, so it still reads that one-line `gitdir: ...` pointer; the file holds no secret, and without this rule `grep -rn x . --exclude-dir=.git` could never be admitted in a worktree. The read oracle of the test treats a `.git` file as non-sensitive for this reason; a `.git` directory's content is sensitive.
- **The rg form is printed only when the grammar admits it.** The rg screen also refuses a secret name at the top (its inventory globs force secret names into the list), so a `.env` at the top gets no hint at all; the hidden-directory key case does get `rg -n ...` (rg never reads hidden entries).
- The `-s`, `-l`, `-w` flags are plain booleans that change only what grep prints; none of them changes which files are opened.

## Not changed (and why)

- `-R`, `--dereference-recursive`, `-f`, `--file`, `-P`, `-z`, `-d`, `-D`, `--exclude-from`: not admitted, not in a cluster either.
- The rg route and `safeRecursiveTree`: not edited. `isValidPipelineGrepArgs` (the sink) and the cat pipeline source: untouched.
- Line 1290 of `shell-grammar.mjs` (`--files-with-matches` test after the grep branch has already returned) is dead code before and after; left alone.
- Hard links to a secret under another name are not detected by either screen (the same as the rg screen); unchanged.
- `templates/prompts/agent-obligations.md` and its generator: nothing in them says recursive grep is refused (the `rg -rn` note is about rg's `-r` meaning replace and stays true).
- The Critic preimage list and every file it covers: not touched. `harness/verify-suites.json`, the case registry and the inventory: outside this patch; no new test FILE was added (the cases live in the registered suites `lib/passive-read-policy.test.mjs`, `lib/read-command-diagnosis.test.mjs` and the existing `hooks/guard-lifecycle-ready.test.mjs`).

## Admitted for outside directories (D96)

An ordinary directory outside the project is readable by the shared rules (D96) and `rg -n` already reads one. `grep -rn` now gets the same: the all-files screen decides the tree (a `.git`, a secret name, a link out of the tree or more than 10000 entries refuse it), and RCD22 pins both verdicts next to the rg baseline (a clean outside tree is admitted; an outside tree holding `.git` or a hidden key is refused). Session collections and credential roots are refused before the tree is walked, exactly as for rg.

## Screen cost

Measured once with `scratch/agent-out/w316-timing.mjs` (Linux under WSL2, warm file cache, five runs per fixture, fixture of empty files in 100 directories): the screen takes about 170 ms for a tree of exactly 10000 entries (admit path, median 171.6 ms) and about 173 ms for 10001 entries (refuse path, median 173.3 ms; it stops at the bound, the walk and the per-entry root checks dominate). Typical project subdirectories (hundreds of entries) cost a few milliseconds. The per-entry cost is the protected-root comparison (about 14 roots, two identities each); it was left as is because the bound caps the worst case at this figure. "Typical project subdirectories cost a few milliseconds" is an extrapolation from the per-entry cost (about 17 microseconds), not a separate measurement.

If BSD grep follows such a link, a link inside the tree to a directory inside the tree is read twice, not out of the tree.
- The 10000-entry bound is a refusal, not a partial read: a repository root without `--exclude-dir=node_modules` and the like is often over it; the printed alternative is the `rg -n` form.
