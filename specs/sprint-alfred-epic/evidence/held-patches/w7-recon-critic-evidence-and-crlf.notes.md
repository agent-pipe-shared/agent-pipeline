## D51 - diagnostic evidence demands HEAD equal to the candidate

Current behaviour (verified in code):
- Producer: `plugins/pipeline-core/lib/critic-diagnostic-producer.mjs` line 39 and line 45 refuse with `CDI-DIRTY-CANDIDATE` unless `git rev-parse HEAD` equals the bound candidate commit and `git diff --name-only <commit> --` is empty, both BEFORE and AFTER the captured targeted run. `candidate` defaults to `HEAD` (line 37). So the HEAD==candidate rule is a producer-time capture rule (the run must be of exactly that tree).
- Validator: `plugins/pipeline-core/lib/critic-diagnostic-evidence.mjs` does NOT compare against HEAD. It binds by exact commit+tree equality: `validateCriticDiagnostic` line 88 (`value.candidate.commit/tree` must equal the supplied candidate), `inspectCriticVerifyDiagnostic` line 65 (Verify receipt `commit`/`tree` must equal candidate, `mode === "critic"`), `validateCaptureHeader` line 79 (log header identity). Source digests are read from `git show <candidate>:<path>` (lines 58-60, 92).
- Consumer: `plugins/pipeline-core/lib/critic-course-admission.mjs` `deterministic()` lines 483-488 skips (`continue`) any registered diagnostic whose nested candidate differs from the review candidate, then raises `CCA-DETERMINISTIC-UNAVAILABLE` when none match. This is the "every later commit voids the evidence" behaviour: evidence for commit A is invisible to candidate B.
- evidenceOnlyCommits: defined in `critic-course-admission.mjs` line 247 (computed by the range classifier, returned line 482 as `evidence`), exposed at line 278 and asserted in `critic-course-admission.test.mjs` lines 240, 298, 316, 341. Consumed in `plugins/pipeline-core/lib/critic-verify-lifecycle.mjs` `inspectConsumedCriticEvidenceCarryForward` lines 126-171: a reviewed Critic candidate may be followed solely by feature-package-registered evidence commits (`rangeCommits` must equal `evidenceOnlyCommits`, no `correctionCommits`, tree must match target). Produces a `pipeline.critic-evidence-carry-forward.v1` proof; used by `recordCriticVerifyLifecycle` (line 187). So carry exists for the Critic RECEIPT to Verify lifecycle binding, but NOT for the diagnostic evidence lookup (`deterministic()`) nor for the Verify receipt check at `critic-diagnostic-evidence.mjs` line 65 (strict commit equality; `critic-verify-lifecycle.mjs` line 183-184 also demands `evidence.candidate.commit === sourceCandidate.commit`).
- What a later evidence-only commit would have to prove to keep evidence valid: (1) base..target range linear and bounded (<=512), every commit changes only paths registered as immutable retained evidence in the feature manifest with matching sha256 (see `critic-course-admission.mjs` lines 177-215); (2) zero correction commits; (3) the target tree differs from the evidenced tree only in those evidence paths; (4) the original evidence's source digests (spec/guardrails at the original commit) are still the digests at the target (not yet checked by anything for diagnostics).

Gap list:
- G1 (code-fixable-here, medium): `deterministic()` / diagnostic validation has no carry path: evidence bound to commit A is discarded for target B even when A..B is a registered evidence-only range. A minimal fix reuses `classifyRegisteredEvidenceOnlyCommits` (the helper behind `evidenceOnlyCommits`) to admit evidence whose candidate is an ancestor reachable through an evidence-only range with identical non-evidence tree content. Needs design care (tree equality no longer holds; compare tree minus evidence paths).
- G2 (po-decision): is "evidence-only carry" acceptable for diagnostic evidence whose assurance is `captured-process-output-not-host-attested`, or only for Verify receipts? Recommendation: allow, bounded to the exact range proof above, and record the carry proof digest in the admission (as `carryForward` already does for Verify lifecycle). Confidence: medium.
- G3 (po-decision / out of scope here): Verify receipt check (`inspectCriticVerifyDiagnostic`, line 65) is strict; the seven-minute rerun the consumer reports is Verify itself rerunning, driven by `harness/scripts/verify.mjs` (TP-3 protected path, not inspected in this pass).

Slice proposal for G1 (not built): files `plugins/pipeline-core/lib/critic-course-admission.mjs`, `plugins/pipeline-core/lib/critic-diagnostic-evidence.mjs`, test `plugins/pipeline-core/lib/critic-diagnostic-evidence.test.mjs` (+ `critic-course-admission.test.mjs`). RED cases: (a) evidence for A is accepted for B when A..B is a registered evidence-only range; (b) refused when a non-evidence file changes; (c) refused when a spec/guardrail digest differs at B; (d) refused when a correction commit exists. Commit subject: `fix(critic): carry diagnostic evidence across registered evidence-only commits`. Note: `critic-course-admission.mjs` is outside this briefing's write scope, so a real slice needs a new briefing.
