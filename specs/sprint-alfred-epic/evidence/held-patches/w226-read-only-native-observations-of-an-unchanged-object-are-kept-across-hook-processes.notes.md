# w226 — read-only native observations of an unchanged object are kept across hook processes

- Found by: Windows measurements of 19e and 19f. One registry lock cycle costs 130 to 180 PowerShell starts (about 0.5 s each): per hook process 23 `read-source` of the installed sources, 27 to 38 `read`, 19 to 35 `inspect` (private directories), `ancestor` checks, 6 to 17 `publish`. Each hook is a new process, so the process-local memo (w215, w218) never carried over: a refused command (96 s) and a dispatch (124 s) each pay several cold cycles.
- Change (`windows-owned-authority-backend.mjs`): the memo also keeps its validated READ-ONLY observations (`inspect`, `ancestor`, `ancestor-above-root`, `read`, `read-source`, `inspect-source-image`) in a bounded file under the user's private application-data directory (`%LOCALAPPDATA%\agent-pipeline\authority-observation-memo.v1.json`). An entry carries the same key as the in-process memo and the object's lstat identity (device, file id, mode, links, size, mtime, ctime, birthtime); it answers only while the object's CURRENT identity equals the stored one: the check every in-process hit already makes. The file is schema- and helper-hash-bound, at most 8 MB / 1024 entries / 16 KB values, validated entry by entry on load (unknown keys, wrong shapes, a mutating operation, a path that is not the key's path: dropped), merged with what another process wrote and replaced by an atomic rename at process exit and every 24 new entries. `PIPELINE_AUTHORITY_NO_MEMO=1` ignores it; a write through the module drops the persisted entries of the written object, its directory and what is below it; a test that fakes the native spawn never touches the real file unless it names its own. Any fault reading or writing it only means "no persisted answer".
- What it does not do: it never caches a mutating operation or a refusal, and it never answers for an object whose identity changed (content write, ACL or owner change, replacement).
- Tests: SAS21 to SAS24 (a new process answers from the file without a native start; changed size / mtime / replaced file misses; corrupt, foreign, tampered files are ignored entry by entry; opt-out and write invalidation). Suites `session-authority-repair` and `win-authority-rest` 66/66; case-completion policy extended by SAS21-SAS24 and the registry pin 295 -> 319 (extension only).
- Security note for the Critic (the honest part): the trust window of an observation grows from one process to the lifetime of the file. The check is unchanged (identity equality), so the exposure is a same-user attacker who can forge all of an object's times, size and ids AND write the memo file; that attacker can already rewrite the plugin source and the private state, so the memo adds no capability against them. NTFS updates ChangeTime on a security-descriptor change, so an ACL or owner change invalidates the entry. Protected file: `windows-owned-authority-backend.mjs`.
- Not measured on Windows yet: the expectation (reasoning, not measurement) is that a warm process saves the 23 `read-source` and most `inspect`/`ancestor` starts, i.e. roughly half of the starts of a cycle; a cold first process saves nothing.
