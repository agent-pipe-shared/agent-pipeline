# w168 - Windows native authority failures name the path, the cause and the repair; the preflight probes close and push (candidate 19c, E2, E4 text part, Q10, W1, W2, W7)

Built by a Goldfish in a clone (`scratch/agent-out/s-win`) at the repository state plus the held patch w166. **Apply order: w166 first, then this patch** (it edits the same files; against the real checkout alone it does not apply, `apply --check` on a tree carrying w166 exits 0). Criterion binding: AC-108 is the closest existing accepted criterion; the PRD and the Spec are unchanged.

## What it changes

- `lib/windows-authority-readiness.mjs`: new `describeWindowsAuthorityRefusal({reason, platform, ...roots, assess})` (platform and probe injected; empty off Windows or for a non-`WIN-AUTH-*` reason). For `WIN-AUTH-OPEN` it names the exact folder from the readiness probe, a preview that changes nothing (`icacls "<path>"`), the apply command the operator runs (`icacls "<path>" /grant "%USERNAME%:(OI)(CI)F"`), and the rule for a second concurrent launch (one Goldfish launch at a time on Windows). The readiness causes now carry the same `repairPreview` commands.
- `hooks/guard-dispatch.mjs` (`SDC-AUTHORITY-UNAVAILABLE: Reason: WIN-AUTH-OPEN`) and `scripts/verify-evidence-producer.mjs` (`VEP-ERROR: WIN-AUTH-OPEN`, via the new exported `formatVerifyEvidenceFailure`) print that text after the bare code; a failing description never changes the line.
- `lib/session-requester-bridge.mjs`: `ownerRouteProcessStatus` is exported and decides Windows liveness from an injected native observer (vanished pid dead, matching identity live, different identity dead, anything else unknown) instead of always `unknown`.
- `lib/session-authority-registry.mjs`: `registryLockRepairText` keeps the old wait / release-lock sentence and appends the one route that clears a held lock: `session-authority-repair.mjs inspect`, then the routine `heal`, last resort `move-aside`.
- `scripts/pipeline-start-preflight.mjs`: (E2) `observeCloseAndPushCapability`, typed `closeAndPushCapability` beside the result (rows node, acl, lock, ownerRoute, each with a named repair; every probe and the platform injected); (W2) `observeBootstrapFacts`, typed `bootstrapFacts` (runtime status, role and model-role readback, calibration file and handover date with sha256 of both files, Verify availability) and `modelRoleBootstrapField` carries a `nextAction` for `MODEL-ROLE-BOOTSTRAP-POLICY-REQUIRED`; (W7) the scratch-lifecycle and worktree-sweep receipts ride under `bootstrapHousekeeping` in the single stdout document instead of two extra JSON objects on stderr (no housekeeping for an ungoverned project, as before); (W1) `hookRefreshNotice` prints one plain sentence on stderr for `hook-refresh-required` naming that exit 2 is intentional and the command to run.
- `scripts/refresh-mandatory-hooks.mjs`: the output names the plugin version it bound to (`pluginVersion`).
- `scripts/win-authority-readiness-and-preflight.test.mjs` (new, 16 cases) and its entry in `harness/verify-suites.json` (needs registration there; done in this patch).

## Not changed / not proven (read this before accepting)

- **The PowerShell helper is not changed.** `lib/windows-owned-authority-native.ps1` is digest-pinned in `lib/windows-owned-authority-backend.mjs` (`HELPER_SHA256`, verified by `source()`), and the backend accepts the failure envelope only with exactly the keys `ok,code,committed`. Carrying the path out of `Refuse` therefore needs `windows-owned-authority-backend.mjs` (re-pin plus an optional bounded `path` key), a file outside this slice's list. The node side names the path from the readiness probe instead; the launch-case folder stays unproven until a Windows run.
- **Not built, files outside the briefed list:** W3 (the `EPERM` retry lives in `scripts/security-readiness/*.mjs` and `scripts/security-adapters/*.mjs`); W6 (`update-public-handover` is a subcommand of `scripts/pipeline-state.mjs`; the briefed `scripts/update-public-handover.mjs` and `lib/environment-readiness.mjs` do not exist); the E4 slicing hint (emitted by `hooks/native-slicing.mjs`, outside the list) and registry concurrency for parallel launches on Windows; the old plugin version in the W1 output (the hook marker records none, `lib/hook-currentness.mjs` would have to).
- `hook-refresh-required` keeps exit code 2: the enforcement pins (`lib/pins/bootstrap-should-refresh-hooks-when-the-plugin-updated.test.mjs`, `scripts/pipeline-start-preflight-enforcement.test.mjs`) assert a non-zero exit and are outside the list, so the fix is the plain sentence, not the exit code.
- "A heal run must not leave its own lock behind" is not built or proven (needs a Windows run). The lock classification relies on the existing registry judge plus the bridge fix; the default lock probe of the capability row is wired but only exercised by injection and by the process case.
- Nothing ran on native Windows. No Full Verify; independent Critic review not run for this slice.
