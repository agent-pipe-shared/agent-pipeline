# C28-PLAN-GATES: plan gates, bound ADRs before submission, accepted ADRs in the map, a warning for a horizontal first dispatch (notes)

Closest criterion: AC-108. PRD and Spec unchanged. Base: the candidate-28 integration clone state a795c822e; the patch applies on that state, not on the real HEAD (the clone holds other candidate-28 slices, so `apply --check` on the real repo is expected to refuse).

## What

- (1) ADR binding gate. `lib/architecture-effective-decisions.mjs`: `inspectAdrDraftBindings({ rootDir, featureDirs })` classifies every real proposal (`docs/adr/draft-<slug>.md` plus a valid `proposed` sidecar) as `materialized` (an accepted or superseded `NNNN-<slug>` record exists; drafts stay on disk as history, so later features are never refused), `bound` (a `prospective-architecture.json` below the plan and spec folders lists the draft with its CURRENT digest), `discarded` (a discard record for the CURRENT bytes) or `unbound`. `pipeline-state.mjs submit-plan` (epic and feature profile, only where a design package applies, beside the G20-15 sidecar check, `deps.adrDraftBindings` seam) refuses `ADR-DRAFT-UNBOUND` with the exact `bind-adr-proposals.mjs` command (real root, feature id, carrier `<feature folder>/design.md`, selection `<feature folder>/po-selection.json`, one `--draft` each) and the exact discard command per draft. `submitPlan()` and the before-implementation gate are untouched: an already approved plan stays valid.
- (1b) Discard: `create-adr.mjs --root <root> --slug <slug> --discard --reason "<why>"` writes `docs/adr/discarded/draft-<slug>.json` (schema `pipeline.adr-draft-discard.v1`, draft and sidecar digests, reason, time), leaves the draft in place, refuses a missing or multi-line reason, an unknown, already discarded or materialized draft. The subfolder is deliberate: a `.json` directly in `docs/adr` reads as an orphan decision sidecar and would block submit-plan. No signature (an audit record, not an approval).
- (1c) Why design approval and the architecture check passed with drafts only: only a record with status `accepted` is ever read as a decision, and a design with no bindings block is `required: false` (the bindings are optional). The submit-plan gate is the single choke point before the signature; it was not added to the approval or the implementation entry (that would refuse existing approvals).
- (2) Accepted ADR in the map. Nothing derives `adrReferences`: the modules (with their references) are author-typed in the PRD design block and copied byte-for-byte into the concept files and `overview.html`, which are signed, byte-compared design targets (`inspectClosedFeatureArchitecture`, `checkArchitectureOverview`). Rewriting at generation would stale every existing receipt that cites a draft, so the fix is at authoring: `bind-adr-proposals.mjs` prints `adrReferences` (the accepted paths) and says never to cite a draft; `submit-plan` refuses `ADR-DRAFT-CITED-AS-ACCEPTED` naming the accepted path (or "remove it"); `module-inventory.mjs --check` and `generate-architecture-overview.mjs` print a stderr warning for a draft citation (`adrDraftReferenceFindings`), exit codes and bytes unchanged.
- (3) Vertical slice first: `dispatch-briefing.mjs` `verticalSliceFirstWarning` (warning `DBG-VERTICAL-SLICE-FIRST`, never a refusal; reaches build, probe and `prepare-dispatch goldfish`, which forwards the warnings) fires for a module dispatch when the design has two or more modules, the Spec names a covered user journey and no integrated dispatch outside the module cut exists yet; the text states the measured fact and a next step (brief the thin path first as a package without `module`, or ignore the warning for a deliberate foundation module).
- Tests, written first and run red (effective-decisions, baseline and module-inventory: import error; submit-plan pin: 4 cases; dispatch-briefing: 3 cases). Added to registered suites only: `lib/architecture-effective-decisions.test.mjs`, `scripts/architecture-baseline.test.mjs` (7.6b, 7.6c and the 7.12 walk), `scripts/module-inventory.test.mjs`, `lib/pins/plan-submission-must-not-require-separate-po-approval.test.mjs`, `scripts/dispatch-briefing.test.mjs`.
