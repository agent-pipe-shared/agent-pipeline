# w30f4 — the first full Critic review of the successor of a discarded feature is admitted over the inherited range (candidate 30f, C30F-G4)

Applies AFTER the 30e chain plus C30F-G2: the patch is the delta `da8492193369..HEAD` of a clone that already holds both, because it edits the same files. It does not apply to a checkout without them (`apply --check` on the 30e clone: exit 0; on the real repository before the chain: expected to fail). Criterion binding: AC-108 is the closest existing accepted criterion (a fresh bounded attempt under its unchanged text). The PRD and the Spec are unchanged.

## What it changes

- Observed (Codex greenfield, 2026-11-16): a feature was discarded while its implementation stayed in Git history; the successor got a new lifecycle manifest. The approved Spec demands a full review of the whole inherited implementation, but the first review needed `manifestAt(base)` and the repair text sent the operator to the commit that first added the manifest, which silently drops the inherited implementation from the diff.
- Existing relation reused, no new manifest field: the manifest's own `supersedes` (a safe feature id or null; `feature-package-topology.mjs` FTP-SUPERSEDES). In `aliasRead` of `critic-course-admission.mjs` a non-null `supersedes` with NO registered alias descriptor, naming a feature that the State records as discarded, is now the successor of a discarded feature (`original` stays the successor itself). Any `supersedes` with a descriptor is the alias (rename/split) route exactly as before; one that names a feature not recorded as discarded keeps `CCA-ALIAS-MAPPING-UNAVAILABLE` (CCA17 unchanged).
- The discarded record is read in the module by `recordedDiscarded`, through `resolveProjectAuthorityPaths` and `bytes` of `project-authority-read.mjs` (neutral tier first, legacy compatibility, regular file, no symlink), and requires an entry with the predecessor id, a non-empty `discardedBy` and a non-empty `reason` (what `discard-feature` writes). `validDiscardedFeatureEntry` of `onboarding-continuity.mjs` is private to that file, so the check here is lighter than its full shape check.
- `resolveRegisteredCriticCourseIdentity`: when the successor route applies AND the manifest is not readable at the course's genesis base, `successorGenesis` demands (1) the commit that first added the manifest (last line of `git log --diff-filter=A` from the candidate), (2) the base is a strict ancestor of it, (3) it is an ancestor of the candidate, (4) the manifest at the candidate declares the same predecessor. Any unmet condition keeps the plain `CCA-MANIFEST-READ`. A base that already holds the manifest never takes the route (ordinary identity, key byte-identical).
- Identity: `originalManifestSha256` is the manifest as first added (it takes the place of the missing manifest at the base), and the course key subject and the identity gain `successor: { predecessorFeatureId, introducingCommit }` ONLY on this route; the key subject of every other course is unchanged (no null key added). The genesis range base is already in `genesisCandidate`. On every later round the subject is recomputed from Git: the first-added manifest sha must equal the retained binding's `originalManifestSha256` and the recomputed course key must equal each retained `courseBinding.courseKey`, so a different predecessor, introducing commit or manifest fails the existing `CCA-GENESIS-BINDING` instead of opening a second course. `COURSE_BINDING_KEYS` (lineage core) and the persisted records are untouched.
- Repair text: `criticCourseRepair("CCA-MANIFEST-READ")` is byte-identical (the G18B hash pin holds). With `{ declaresPredecessor: true }` it gains exactly one sentence naming the successor route and no feature. `criticCourseDeclaresPredecessor` (new, read-only) decides it from the manifest at the registration commit; `critic-dispatch-preflight.mjs` passes the detail only for `CCA-MANIFEST-READ`.
- Round cap, delta binding, `--confirm-full-round`, candidate binding, evidence-only classification and the alias route are untouched.

## Not changed / not proven

- NO WRITER sets the relation. `feature-package-registration.mjs` writes `supersedes: null` for every new manifest (its line about 354; the supersede-rebuild at about 191 even treats a non-null value as not re-approvable) and `onboarding-continuity.mjs` writes null too. A real successor therefore reaches the route only when its manifest carries `supersedes` set to the discarded predecessor by some other means. Registering that relation at successor creation (and teaching the rebuild path to keep it) is outside this write list and is the follow-up that makes the route reachable without a hand edit.
- The finalizer cannot consume round 1 of a successor yet. `critic-generic-batch.mjs` `reserveFeatureCriticReviewUnitOwnership` (about line 961-964) reads the review unit at `identity.genesisCandidate.base` (`git show <base>:<unit path>` -> `CGB-TARGET`) and calls `readCriticReviewUnit` with that base; for the successor the unit does not exist at the base. The same holds for any review unit introduced after the base (D165-PF75B). It needs the introducing commit as `declarationCommit` (the admission already resolves it in `featureReviewUnit` and passes it to `readCriticReviewUnit`; exposing it in the returned reference, only when it differs from the base, would carry it). File outside the write list, not changed. Consequence: round 1 end to end through `admitSessionCriticReview` is NOT proven; the admission and the preflight are.
- A later round is proven at identity level only (the re-bound record), not through a consumed round 2.
- The State is a mutable working-tree file: the route needs it on the machine that prepares the review. A later round on a machine whose State does not record the predecessor is refused `CCA-ALIAS-MAPPING-UNAVAILABLE` (the manifest still declares `supersedes`, the alias route finds no descriptor).
- `git log --diff-filter=A` history simplification: a manifest added on two merged branches resolves to the last (oldest) listed commit; no such history was tested.
- The full Verify run was not made.
