# w173 — the gates keep the Critic evidence of an earlier reviewed commit valid when every later commit is administration or documentation only (candidate 19, PO decision of 2026-11-04 on open question 2 of the carry-forward ADR)

Delta on w171 (the chain through w171 must be applied first; `git apply --check` of this patch against a checkout without w171 fails by design). Built in a clone that carries w171 as its base commit. **This patch widens what the close gate and the push gate accept for a Critic round.** The criterion binding is AC-108, the closest existing accepted criterion; the PRD and the Spec are unchanged.

## What it changes

- `lib/administration-documentation-paths.mjs` (new): the ONE closed set, named by class and pinned by test: the record-only set of `lib/record-only-paths.mjs` as base (reused, not copied), Markdown under `docs/` except `docs/adr/**`, README files inside the documentation trees, `backlog/**`, the generated `lifecycle.json` and `result.md` of a feature package, `specs/<feature>/evidence/**`, `audit-bundles/<feature>/**`. Source, scripts, configuration, schemas, tests, ADRs, the PRD, Spec and plan texts and the repository root README are content. The module header justifies each class. Feature-bound paths can be restricted to named features.
- `lib/critic-evidence-carry.mjs` (new): `decideCriticEvidenceCarry({ repoRoot, reviewedCommit, candidateCommit, featureIds })` answers whether R is an ancestor of C, the range is not empty and every path changed between R and C is in the set as a regular, non-executable file (mode check from `git diff --raw`); the answer names the passed-over commits, the changed paths and, on a no, the offending paths and a stable code (`CEC-CARRIED`, `CEC-CONTENT-CHANGED`, `CEC-NOT-ANCESTOR`, `CEC-EMPTY-RANGE`, `CEC-INPUT`, `CEC-UNREADABLE`, `CEC-RANGE-TOO-LARGE`). It never throws and fails closed. Also `administrationDocumentationOnlyCommit` (the per-commit test of the registration delta course), `describeCriticCarry` and `readCarriedForwardReadback` (readbacks).
- `lib/critic-verify-lifecycle.mjs`: `inspectConsumedCriticEvidenceCarryForward`, the one reader behind the private Critic and Verify lifecycle receipt (recorded by the Verify evidence producer, read by the close gate, by the push readiness check that `hooks/guard-push.mjs` calls and by `pipeline-state`), takes the decision when the registered evidence-only classification does not carry the range. The refusal codes are unchanged (`CVL-CARRY-RANGE` when the registered classification could not be read, otherwise `CVL-CARRY-CONTENT-CHANGED`). A proof that was carried this way is labelled `route: "administration-documentation"`; a proof of the registered route keeps its exact bytes, so no existing receipt drifts.
- `lib/critic-verify-readiness.mjs`: the readiness result names `carriedForward` (reviewed commit, passed-over commits, route) when the receipt is a carry receipt; the verdict is unchanged.
- `scripts/push-prepare.mjs`: the `critic-bound-verify` check names the original reviewed commit and the passed-over commits when the candidate is bound by a carried review.
- `lib/critic-course-admission.mjs`: `classifyRegisteredEvidenceOnlyCommits` with the carry option (`admitCriticExports`) also passes administration-only commits over and reports them in `administrationDocumentationCommits` (so the close advisory stays consistent with the carry); the course transport (candidate to registration commit) accepts them. The course counters, i.e. the classification without the option, are unchanged and pinned.
- `lib/feature-package-registration.mjs`: the correction candidate chosen by `--add-delta-request` skips administration-only commits.
- `lib/guard-maintenance-window.mjs`, `docs/guard-maintenance-window-threat-model.md`: the two new modules are never-liftable kernel paths (imported by kernel paths).
- `lib/critic-evidence-carry.test.mjs` (new, registered in `harness/verify-suites.json` and the capability inventory): every class by name, content classes, vetoes, malformed paths, the pure decision (carried, one source file in the range, a content change reverted, non-ancestors, empty range, bad input, symlink and executable file, removed files) and the per-commit test. `lib/critic-verify-lifecycle.test.mjs`: two added cases, real gate decisions on a git fixture through the lifecycle record and read (the close gate's reader), the readiness check (the push gate's call), the advisory and the readback; a content change anywhere invalidates, also with administration commits after it.
- Docs: `docs/push-release-flow.md` and the ADR (decision line, point 2, open question 2 marked decided by the PO on 2026-11-04, new amendment); the ADR `.json` digest is refreshed.

## Why it is bounded

- A content path anywhere in the range invalidates exactly as before; the registered evidence-only route and every other case are untouched (all existing lifecycle cases stay green, including the 16c, 15g and N23 refusals).
- Judgement calls where the briefed set met an existing pinned case, each resolved toward refusing: (1) the README class is limited to README files inside documentation trees; the root `README.md` stays content because case 16c refuses it. (2) `specs/<feature>/evidence/critic/**` and the Critic disposition addenda with their Markdown evidence under `evidence/` are vetoed, because they have receipt-bound and record-bound classifiers and cases 15g and N23 refuse their forged variants. (3) Feature-bound classes are restricted to the feature of the receipt, because 16c refuses another feature's directory.

## Not changed

- `lib/record-only-paths.mjs`, `hooks/guard-push.mjs` and `scripts/critic-dispatch-preflight.mjs` need no edit: the push gate and the preflight reach the decision through the receipt reader and the course classification; the registered course (`CCA-PARENT`, the correction budget) keeps counting administration commits that lie between the previous reviewed candidate and a new correction candidate as it did, and the delta paths still cover them.
- `scripts/check-critic-bound-verify.mjs` is outside the briefed scope, so the `push-prepare` readback reads the carry from the private receipt by the receipt id the check already returns.

## Not proven

- No Full Verify and no independent Critic review (suspended by the PO); this slice is a batch item for the Coordinator.
- No spawn of the real `guard-push.mjs` or the close coordinator against a carried Critic fixture: both call the receipt reader that the new cases exercise. The `push-prepare` message path is not covered by a direct case (its test file is outside the briefed scope).
- The registration delta course (candidate choice and transport) is covered only by the existing suites staying green, not by a new end-to-end registration case.
