## Recon (first, as briefed)

- **`unowned-path`** is decided in `observe()` of `architecture-boundary-check.mjs`: the tracked files are first filtered to `DEFAULT_SOURCE_EXTENSIONS` (and `policy.excludedPaths`), then `owningModules()` (longest `ownedPaths` match) returning no module is `unowned-path`; two modules tied is `ambiguous-ownership`. Premise check, stated honestly: because of that extension filter, `.md`, `.json`, `.html` and `.css` files (for example `docs/state.md`) can NEVER be reported; only source-extension files (`.js`, `.mjs`, `.py`, ...) under `public/`, `docs/` and similar can. The plan's list of run B paths is therefore only reproducible for source-extension files; the fixtures use `public/app.js` and `docs/contracts/schema.mjs`.
- **`--write-policy`** writes `architecture/boundary-policy.json` (`pipeline.architecture-boundary-policy.v1`) with one `exceptions` entry per CURRENT violation, create-only (`wx`), refused with exit 1 and "never overwritten" when the file exists. GS-16 protects the file; its first appearance in history is free (`gate-definition-changes.mjs`, proof `first-appearance`).
- **`materialize-architecture`**: `pipeline-state.mjs` calls `materializeArchitectureDesign` (lib). The targets come from `inspectArchitectureMaterializationTargets` (`architecture/map/*`, `overview.html`, `fitness-model.json`, `baseline.json` via `architectureDesignTargets`, plus the receipt `design-materialization.json`). The state-authority companion declares and seals the effects from the SAME inventory (`sealedTargets`, `sealStateCompanion`), so the policy had to join both lists and its bytes must be deterministic.
- **Verify suite** `baseline-architecture` runs `runConsumerVerifyCheck` -> `measureArchitecture` -> `checkArchitectureBoundaries`, which reads the policy through `readBoundaryPolicy` (plus the managed exclusions).

## What changed

1. **Test ownership (L2), derived on read, nothing stored.** In `observe()` a file in no module's `ownedPaths` that is a test (`.test`/`.spec` infix, `_test` suffix, `test_` prefix, or a `test`/`tests`/`__tests__`/`spec` directory) is owned by: (1) the module that lists it in `verificationEntryPoints`; else (2) the module it is named after (its stem or one of its directories is the module id) or whose owned non-test source file it mirrors (same stem). Two candidate modules stay `ambiguous-ownership` (own detail text); no candidate stays `unowned-path`. `owningModules()` itself is unchanged (ABC05, import-target resolution), so explicit `ownedPaths` always win.
2. **Baseline policy at materialize (L11).** `baselineBoundaryPolicy(modules)` in `lib/architecture-design.mjs` builds the policy from the design alone; `inspectArchitectureMaterializationTargets` adds it as a create-only target (before the receipt) to `targets` and `sealedTargets` when the status is `materialization-required` and the file is absent. It is NOT in `architectureDesignTargets` and NOT in the receipt: a later (gate-protected) policy edit is therefore never `ARCHITECTURE-DESIGN-ARTIFACT-DRIFT`, and the receipt bytes and every digest are unchanged. `architectureCommitStep` already lists everything under `architecture/`, so the policy is in the materialize commit set the route names; `pipeline-state.mjs` needed no edit (the monolith is untouched).
3. **No module-less class, no policy (item 4).** A class (`docs/**`, `public/**`, `static/**`, `assets/**`) is listed only while no module's `ownedPaths` reach into it with a directory, a glob or a source file (excluding it would also drop that module's line bound and import checks); an owned document file such as `docs/contract.md` does not count. When no class is left the function returns null and no file is written.
4. **Manual route (item 5).** `--write-policy` is unchanged: over a written policy it still exits 1 with "never overwritten" and changes no byte (pinned after the materialize-shaped policy).

## Deviations and choices to read

- The briefing says the policy is "the same content `--write-policy` writes". `--write-policy` writes per-file `exceptions`; at materialize time the implementation files do not exist yet, so exceptions cannot cover them. The policy uses the existing `excludedPaths` field (class patterns) instead. No key, schema or exception shape was added.
- "Manifests" are not a listed class: manifests (`package.json`, ...) are not source extensions and are never reported; root-level config source files (for example a bundler config) are not covered and stay a design or `--write-policy` matter.
- A derived-owned test is counted in its module's usage and held to that module's `allowedDependencies` like any owned file (a test importing a module its owner does not allow is now `forbidden-dependency`; before it was `unowned-path`, so no green run turns red).
- The GS-16 reason text in `hooks/guard-gate-strength.mjs` names only `--write-policy` as the free creation; it could also name `materialize-architecture`. That file is outside this write list and was not touched.
- Slice-clone commit carries a one-line message (helper limit); the held patch is the delivered artifact.
