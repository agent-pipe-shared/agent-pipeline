## What the patch changes

Measured in the Antigravity greenfield TabletApp_agy_070_3 (P3, C3, 3.4 B): the close took 226 agent turns, 252 tool calls and 64 minutes, walking stage by stage around `pipeline-state.mjs close-feature` and the commit; the signed proofs stayed outside the repository and only their ids reached `audit-bundles/`.
Measurement versus clone: that report names stages and codes that do not exist in this clone (`CONTINUITY-RESULT-CLOSE-BLOCK-MISSING`, `CLOSE-EVIDENCE-INVALID`, `--from`/`--to`, a `continuity-result-close-plan.mjs` script). Here the Result close is the `pipeline-state.mjs` verbs `continuity-result-close-plan` / `-apply`. The patch fixes the same obstacle course (hand-walked stages) against the stages this clone really has.

1. **`scripts/finish-feature.mjs`: `oneShotClose` and the CLI `--one-shot`.** Chosen over `close-coordinator.mjs drive` because finish-feature already owns the stage order (start, checkpoint, prepared, State close) and the G20-66 commit arming of each stage, while `drive` walks one coordinator phase per call and has no stage before the start. Before the commit it runs: the candidate Verify bound to the Critic packet recorded for the repository (exactly one packet on disk, else `--critic-packet-id`), registration of the evidence, the package to `verifying` and `completed`, the audit request, with Continuity the Result close block and the close request, then the close (`finishFeature`) and the `tracked-close-finalized` evidence. It arms `armWriterCommitCapability` for exactly the files it wrote and returns `status: "commit-required"` with the paths, the commit steps and `next` (the same command with `--resume-lifecycle-id`). The resume call, after the commit, freezes the candidate, runs the final Verify and the Security scan, writes the final-verification evidence, runs the cleanup (`drive --apply`) and ends at `closed-local`. Every human point is one typed stop `{ code, reason, repair }` (exit 2 in the CLI, repair on stderr): `ONESHOT-CRITIC-PACKET-MISSING`, `ONESHOT-VERIFY-RED`, `ONESHOT-REGISTER-FAILED`, `ONESHOT-LIFECYCLE-MISSING`, `ONESHOT-OWNER-ROUTE-REQUIRED`, `ONESHOT-COMMIT-PENDING`, `ONESHOT-SECURITY-BLOCKING`, `ONESHOT-RESULT-MISSING`, `ONESHOT-NO-ACTIVE-FEATURE`, `ONESHOT-PHASE-UNEXPECTED`, or the coordinator's own typed refusal code (for example `CLOSE-CRITIC-CALLER-AUTHORED` with its repair text). It signs nothing and pushes nothing; every call goes through the injectable runner. Shared-cause fixes in the same file: `parseJsonOutput` surfaces the coordinator's typed refusal JSON from stdout, the State path comes from `resolveProjectAuthorityPaths`, `IMPACT` accepts the coordinator's five values, `applyBound` is extracted, `flagPairs` handles the boolean `apply`, and the commit facts use the untrimmed `git status -z` output (a trim ate the leading space of the first ` M` entry).
2. **`lib/audit-bundle.mjs`: optional `proofs`.** `proofs/NNN-<kind>.json` with `kind`, `path`, `sha256`, `intentSha256` in the manifest (and the README); planning refuses a proof that does not verify or carries anything beyond the public proof fields (`AB-PROOF-INVALID`). The verifier checks bytes (`AB-DIGEST`), the intent the proof names (`AB-PROOF-INTENT`), the Ed25519 signature over `intentSha256` (`AB-PROOF-SIGNATURE`), `AB-MISSING`, and the manifest shape (`AB-PROOFS`). A bundle without proofs keeps its old shape byte for byte. Exports `isCarriableProof`. Never a private key, only the public proof object.
3. **New `lib/audit-proof-collection.mjs`: `collectAuditProofs({ common, candidate, state })`.** Read-only: the plan approval's signed design approval from State, and the push and feature-package-reconcile envelopes in the private critical approval store whose `forCommit` equals the candidate commit. Anything not a verifiable public proof object is a typed gap (`PROOF-NOT-CARRIABLE`), never blocking.
4. **Wiring.** `scripts/close-coordinator.mjs` collects the proofs when it writes the bundle (`options.proofs`); `lib/feature-close-audit-preflight.mjs` compares them in `reuse-verified`; `lib/feature-close-audit-executor.mjs` syncs the `proofs/` files; `lib/feature-close-audit-receipt.mjs` checks the proofs paths.
5. **`skills/close-feature/SKILL.md`** leads with `finish-feature.mjs --one-shot --by <name> --architecture-impact <value> [--critic-packet-id <id>]`, the resume call and the typed stops, and keeps the per-stage text as the recovery reference; `allowed-tools` names finish-feature.
6. **Tests (QG-04: no assertion weakened).** New cases carry a `P3` comment: `scripts/finish-feature.test.mjs` (5: the CLI case, and fixture feature to the printed commit with the exact stage order and nothing signed or pushed; Continuity gets its Result close block and close request; each human stop gives its typed repair and nothing later ran; the resume call reaches `closed-local`, an uncommitted tree and a blocking scan stop with their repair), `lib/audit-bundle.test.mjs` (4: proofs in `proofs/` with matching digests, offline verify and the old shape unchanged; a tampered proof refused at bytes, intent and signature; planning refuses an invalid or key-carrying proof; the collection from State and the store). No existing test pinned the old stage-by-stage text or the old bundle shape, so none needed restating.
