# w302 — Both Codex Critic roles carry a read-only sandbox, and a host without a usable sandbox still gets its Critic (candidate 22)

Delta on the candidate 22 chain (clone base cea76d1bc). Closest accepted criterion: AC-108 (PRD and Spec unchanged). Built by a Goldfish in a clone that carries the chain; delivered as a held patch.

## Why

PO decision 2026-11-09: `sandbox_mode = read-only` for BOTH Codex Critic roles (`critic`, `critic-high-risk`), existing projects migrate, and a host where the sandbox fails (WSL: `spawnSync node EPERM`) must never deadlock. A Critic is mandatory, so the Advisor's typed-unavailable outcome does not transfer: the exception always ends in a running Critic.

## What it changes

All under plugins/pipeline-core/, plus the repository's own two tracked role files.

1. Projection (`lib/runtime-projection-v3.mjs`, `config/runtime-projection-v3-owned-keys.json`)
   - `CODEX_CUSTOM_AGENT_METADATA` gives `critic` and `critic-high-risk` (not `implementor`) a `sandboxMode`; `codexCustomAgentSeed` renders `sandbox_mode = "read-only"` after `developer_instructions`, as the Advisor renderer does.
   - Measured: a Critic target is projected by patching only its owned values inside the baseline bytes (the frozen V2 kernel preserves the rest), unlike the Advisor, which is re-rendered whole. `sandbox_mode` therefore became an owned key of both Critic targets with a FIXED value (`CODEX_FIXED_OWNED_VALUES`), not a routed one: a hand-edited value is re-projected like `model`; a baseline that predates the key gets the line inserted into the top-level block (before the first table, or at the end), line ending kept; a line that names the key in a form the strict reader cannot patch is refused rather than duplicated. The decision-conflict scan (decision 3) reads only the routed keys, so the sandbox is never a model-decision conflict.
   - `.codex/agents/critic.toml` and `.codex/agents/critic-high-risk.toml` in the repository root carry the new line (`check-routing-projections` RP14 compares them with the plan).
2. Migration (no change to `lib/runner-profile-migration-v3.mjs`, none needed)
   - The classifier, legacy and slim seed tables all call `codexCustomAgentSeed`, so they carry the new seed by construction. An existing project whose Critic file has the old seed is not a hand edit: the owned-key manifest drives the ordinary plan, which now lists the file as changed (old seed bytes in, new bytes out); the existing `apply` writes it, and the plan after is a noop.
   - Proven in `runner-profile-migration-v3.test.mjs` (case RPM38, assertions added in place, count stays 61): fixture critic file without the key migrates to bytes carrying it before `[metadata]`, a hand-edited `workspace-write` in the high-risk file is re-projected, implementor untouched, final plan noop. Proven in `runtime-projection-v3.test.mjs` (4 new C22 cases): old seed in / new seed out byte-identical, hand-edited value, table placement, absent file.
3. Exception route, decided at launch (`lib/codex-critic-launch-route.mjs`, `scripts/codex-critic-launch-route.mjs`)
   - `--role critic|critic-high-risk` and optional `--receipt <absolute path>`; one JSON object, always exit 0. A readable receipt with schema `pipeline.codex-sandbox-preflight.v1`, eligibility `intermediate` or `strong` and terminalCode `ok` prints `{ agentType: <role>, sandboxed: true }`. Everything else prints `{ agentType: "default", sandboxed: false, protection: "instruction-only", reason }` with a closed reason: `no-receipt`, `receipt-unreadable` (missing, directory, relative path, reader error), `receipt-schema-mismatch`, `eligibility-insufficient`, `terminal-code-not-ok`, `role-invalid`, `route-error` (any thrown error or bad arguments). The route only reads; it never stops the lifecycle.
   - New suite `lib/codex-critic-launch-route.test.mjs` (8 cases, library and CLI).
4. Launch text: `skills/pipeline-start/references/happy-path.md` (Critic path, after `session-critic-finalizer.mjs admit`) and the `dispatch-critic` step in `lib/runbook-paths.mjs`; `runbooks/critic-path.v1.json` and `runbooks/index.v1.json` regenerated by `generate-runbook.mjs` (no hand edit). Preflight once (`--run --kind intermediate`), run the route with that receipt, spawn exactly the printed `agentType`. With `default`: model and effort on the call, round recorded as `caller-authored-fallback` with its one human acknowledgement at the close, final message names it as protected by instruction only; a sandboxed Critic that still fails on `EPERM` is launched once more through `default` with the same labelling. This replaces the sentence that said never `default`.

## Deliberately not changed

- The Critic preimage files (`agents/critic.md`, `skills/critic-review/SKILL.md`, `scripts/codex-critic-host.mjs`, the Critic schemas) and the preimage list: untouched, never re-pinned.
- The launch-side sandbox lane (`scripts/codex-critic-selected-host.mjs`, `lib/critic-lane-fallback.mjs`): not the happy path, untouched.
- The `implementor` role (no sandbox), Claude and Antigravity behaviour, runtime projection V2 files and tests, every guard hook, PRD and Spec.
- `lib/critic-source-return.mjs`: a `default` Critic still gets no Source return; that is why the fallback is recorded as `caller-authored-fallback`.
- The route does not validate the whole receipt against its schema (the preflight itself does that when it writes it); it reads the three fields the decision needs.
