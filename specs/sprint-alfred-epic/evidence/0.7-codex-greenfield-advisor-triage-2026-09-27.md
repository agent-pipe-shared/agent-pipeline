## Required correction before 0.7 qualification

- Decide route availability and export permission **before** constructing or
  emitting a prompt-bearing dispatch packet. For a refused/unavailable route,
  output only a typed reason, source paths/digests and bounded metadata.
- Provide a supported, fresh read-only Codex-host Advisor dispatch where the
  host can actually execute it. Bind the selected route, candidate, bounded
  question/evidence digests, observed execution and answer digest into a
  validated `pipeline.advisory-receipt.v1`. A self-reported subagent answer or
  a fabricated host identity cannot satisfy this contract.
- If no admitted host route exists, issue a real `unavailable` receipt and a
  truthful, validated route-attempt trail. The design-workflow package must
  then expose its existing explicit PO exception path instead of ending at
  `DAC-RECEIPT-MISSING`. Whether route selection without child launch counts
  as an attempt needs an explicit contract decision; it must not be invented
  by this triage.
- Test the complete Codex/WSL Greenfield Feature path from fresh onboarding
  through Advisor answer or governed unavailability, independent readiness,
  final package validation and implementation approval. Assert no prompt
  output, child launch or export on unavailable/denied paths.
- Align the printed trailer examples with the admitted Git grammar and add a
  test that passes the installed examples through the actual guard.
