### F1 — The PRD's traceability table binds the PO's Critic-per-document duty to a spec section that does not carry it, and no spec section does

**Gap.** PRD §10 routes the PO constraint "Critic-per-document duty" to
"§7.2 of spec". Spec §7.2 is *D2 — Agent-first architecture standard (#104)*
and contains nothing about Critic rounds; the duty appears nowhere in
`spec.md`.
**Risk.** A PO-stated design-phase constraint is recorded as specified when
it is unhomed, so nothing in the accepted contract obliges it — the
traceability table, whose purpose is to prove every input landed, actively
asserts a false landing. **major**
**Evidence.**
- `specs/sprint-alfred-epic/prd_sprint-alfred-epic.md:346` — `| PO input
  2026-08-27 | design/po-input-2026-08-27.md → §1–2 outcomes, §5 model

  architecture standard (#104)`

  **one independent Critic round per design document** before the PO` (the
  duty's actual source)

  Verify + security gate + Critic reviews per block`; `acceptance.md:27`
  (A14) covers *"Every wave's deliverables"*, i.e. implementation waves, not
  design documents.

**Spec-ref.** `kickoff-design.md:206-208` — the Spec must cover "PRD-to-Spec

about Alfred's coupling to Nova. A gate nobody enumerates is a gate nobody
clears. **major**
**Evidence.**

  `- no active Sprint branch is expanded or coupled to Alfred.` (fifth

  `**Current design base:** feat/sprint-alfred at a50c8093 (clone of the
