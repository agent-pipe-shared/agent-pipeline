## Disposition rule

“Open” or “not accepted” means only that the original full acceptance criterion has no current candidate-bound accepted closure. It does not establish missing implementation or missing test execution. Use these separate dispositions:

- **Codegap / reproduced RED:** a current, concrete behavior failure remains. This needs a scoped implementation outcome.
- **Prepared integration:** a named private candidate or targeted repair passed its stated checks, but it is not integrated or accepted. This is not an unfixed code RED.
- **Current-proof join missing:** evidence exists or may exist, but its source/dependency/candidate binding is absent, stale, or not established against the latest approved criterion. Do not relabel it as either failed behavior or current PASS.
- **Native-only remaining:** fixture/source checks pass at their declared scope; an actual runner/platform/installed boundary is the remaining required evidence. This is not evidence of a Source code defect.
- **PO acceptance/disposition:** technical proof alone cannot complete the criterion; an explicit required PO disposition/approval remains.

Multiple labels can apply to one AC because its clauses have different remaining obligations. Any exact evidence remains at its recorded scope. The 174-row matrix currently reports zero accepted items; that global fact does not mean each row has a code defect.
