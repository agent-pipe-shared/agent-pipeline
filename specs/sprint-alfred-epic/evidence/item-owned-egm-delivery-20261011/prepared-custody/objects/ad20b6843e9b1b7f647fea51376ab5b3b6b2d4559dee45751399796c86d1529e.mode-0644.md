## Corrected Verify route

The earlier inference from absence in `harness/verify-suites.json` was incorrect. That file supplies declarative additional suites; it is not the complete suite registry. The built-in `TEST_SUITES` list in `harness/scripts/verify.mjs` directly registers both AC-24-relevant suites:

- `antigravity-execution-host-tests` → `plugins/pipeline-core/lib/antigravity-execution-host.test.mjs`, with Verify case-completion IDs `EPH01` through `EPH24`.
- `goldfish-antigravity-host-tests` → `plugins/pipeline-core/scripts/goldfish-antigravity-host.test.mjs`, with Verify case-completion IDs `E3H01` through `E3H15`.

The runner combines built-in `TEST_SUITES` with declarative/scoped registrations, resolves the invocation selection, then passes the selected suites to `runVerifyJournal`. Thus AC-24's E3 Verify-suite requirement has a dedicated registered suite, and its expected E3H completion cases are bound by the built-in registration. It does not rely on an unrelated aggregate suite to cover E3. The lower-level EPH suite is separately registered as well.

The exact route is:

```text
harness/scripts/verify.mjs
  TEST_SUITES:
    goldfish-antigravity-host-tests
      -> plugins/pipeline-core/scripts/goldfish-antigravity-host.test.mjs
      -> expected E3H01–E3H15 completion IDs
    antigravity-execution-host-tests
      -> plugins/pipeline-core/lib/antigravity-execution-host.test.mjs
      -> expected EPH01–EPH24 completion IDs
  -> resolveSelfVerifySelection(... registeredSuites ...)
  -> runVerifyJournal(... selected suites ...)
```

`harness/verify-suites.json` has no direct E3 entries, but that is not a coverage gap because the built-in registrations above own these suite entries. No direct suite registration or E3 source edit is indicated by the evidence reviewed here. The exact invocation selection and test receipt for a current candidate were not observed, so registration alone is not a completed Verify result.

Required evidence is an E3 Verify suite, a `pipeline.cross-runner-dispatch-receipt.v1` fixture receipt, and A1/A2/A3/A5 precondition readback. The AC explicitly says fixture success, `agy plugins list`, and a sandbox flag are not native-guard or three-runner proof.

`specs/sprint-alfred-epic/spec.md` §8.1 specifies the same boundary and adds isolation/refusal cases for candidate drift, duplicate/traversal inputs and occupied result destinations. It requires a current measured A1 runner row, E3 placement (A2), protected host/receipt surfaces (A3), and PO-authorized CAS-bound repair evidence (A5). The shipped `policies/alfred-e3-gate-readback.v1.json` is `unavailable`; candidate and artifact digests are null. The spec explicitly defines this as refusal. No current candidate-bound readback or qualifying run receipt was inspected in this audit.

Source inspection confirms the intended implementation shape:

- `plugins/pipeline-core/scripts/goldfish-antigravity-host.mjs` is the E3 caller and invokes the shared AGY boundary once after gate, packet, candidate, destination, and local marker checks. It normalizes a typed `pipeline.cross-runner-dispatch-receipt.v1` receipt.
- `plugins/pipeline-core/lib/antigravity-execution-host.mjs` owns the lower-level preflight and single injected executable invocation.
- `plugins/pipeline-core/scripts/goldfish-antigravity-host.test.mjs` contains fixture cases for bound success and schema-valid persisted receipt, malformed/legacy output, requested/observed model mismatch, timeout, explicit cancellation, missing/mismatched marker, occupied/escaping result destinations, and forged/unavailable gate refusals. The fixture injects an A1 qualifier to exercise the seam; that does not qualify the production gate.
- `plugins/pipeline-core/lib/antigravity-execution-host.test.mjs` contains lower-level process-boundary tests, including exactly-one launch, malformed/mismatched output, timeout and zero-spawn invalid packet/preflight cases.

These files and Verify registrations were inspected, not executed. Their presence establishes suite/case registration and authored fixture coverage only, not successful test completion or current acceptance.
