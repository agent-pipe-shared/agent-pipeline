# Direct mini final approval: bounded unapproved design draft

The accepted goal is ordinary conversational intake and agent-owned submission/presentation followed by one final design signature. An existing exact generated-mini design decision may be reused; installation consent cannot substitute for that decision. A direct or already-bound mini has no generated checkpoint from which to restore such a receipt.

## Current reuse result

The crypto primitive is reusable; the current reviewed-design request and its State consumer are not reusable unchanged. No `prepare-design-approval` command exists in the inspected current Source scripts/lib or harness scripts. The actual current producer is `present-plan --review-receipt` plus `createDesignApprovalBinding` / `createDesignApprovalRequest`.

## Proposed contract for the collected final PO package

This is design content to decide, not a new public API or executable authorization. Reuse `createPoApprovalIntent` / `verifyPoApprovalProof`, current committed human-approval mode, existing external signer/trust posture, physical file checks, repository topology and CAS machinery. Keep reviewed epic/feature DAB and its independent review requirements intact. Introduce an explicitly separate mini final-decision subject rather than claiming that an empty review chain passed.

The proposed closed mini subject fields are `repositoryFingerprint`, `featureId`, `profile: "mini"`, `submissionSha256`, `presentationSha256`, `profileSha256`, `prd: {path, sha256}`, `spec: {path, sha256}`, `candidate: {commit, tree}`, and `policy: {mode, sourceSha256, runtimeSha256, receiptSha256, revision}`. The unsigned request would carry `schema`, that `subject`, `subjectSha256`, and `approvalIntent: {value, sha256}`. Exact schema identifier, intent kind and policy revision must be assigned in the design package; this item does not mint them. The intent must bind the same feature, Plan/Spec digests, actual candidate and complete subject digest. No checkpoint, fabricated reviewed verdict, receipt list, model label or installation-consent field belongs to this subject.

Preparation belongs to the existing mini `present-plan` transaction after exact submission and physical document observation, or a clearly specified agent-owned internal producer called by it. It emits the current unsigned request automatically. Inspection returns the existing human-terminal final signing action for that exact request, once; names/profile/scope remain ordinary conversational questions. Request preparation and presentation require no content acknowledgement, signature or additional operator preparation. Pending request bytes cannot grant implementation authority.

`approve-plan` must branch on exact current mini decision provenance: reuse a genuinely observed current original generated-mini final decision when available; otherwise consume the direct-mini request and genuine final proof. It must refuse ambiguous simultaneous bases, stale original receipts, changed documents/candidate/policy, wrong profile/mode, absent proof and foreign intent. It must re-observe all subjects immediately before commit. Persisted approval must have a closed recognized mini proof basis; choose a versioned approval record or explicit typed sibling plus readers in the design package. Existing v8 null review fields alone cannot assert a new signature basis. Update lifecycle recognition and calibration readback consistently; never store only `approvedBy: verified:<label>` as proof.

Required ownership extends beyond the assigned State pair: mini request contract/validator, existing signing request observer, State producer/consumer, `plan-spec-state-v2` current approval recognition, and calibration proof revalidation. Any necessary command catalogue/companion changes belong to their owner. No implementation is proposed here because that contract/authority scope is unresolved. No new trust anchors, review waiver, optional preliminary human gate or global key-store write is needed or authorized by this draft.

## Exact prospective cases and expected evidence

| Case | Expected outcome and evidence |
| --- | --- |
| Direct bound mini, no checkpoint/receipt | Sanctioned submit/present creates one unsigned request over actual tracked current documents, profile, candidate and policy; confirmation false on agent actions; State unapproved. No bootstrap request or receipt created. |
| Already-bound mini after conversational intake | Same final request path, no reconstruction of generated staging authority and no extra operator preparation. |
| Genuine final signature | One external final signature verifies against existing public trust policy; approve-plan consumes exact request once; lifecycle/calibration readback recognizes its durable basis. Requires an actual supplied sealed proof fixture or attended final signature, never an invented one. |
| Missing proof / changed request / stale candidate | Consumer refuses with exact typed reason and zero State mutation; pending unsigned request never unlocks implementation. |
| PRD or Spec drift / changed presentation or submission | Current observation rejects old request/proof; agent rebuilds final presentation only for the actual current package; no automatic approval replay. |
| Foreign repository / feature / profile / signer | Consumer refuses even if proof is structurally valid for another intent; no remapping to this mini. |
| Committed mode or policy digest changes | Old request/proof refused; request regenerated from actual current policy. Chat and signature mode cannot silently substitute for each other. Normal conversational questions alone never represent a signature decision. |
| Generated mini with exact original final decision | Genuine Source-produced original bootstrap final proof/receipt is reused once by existing route; no second content acknowledgement or signature. Readback confirms current Plan/Spec/profile and signer provenance. |
| Generated mini with unavailable/stale original decision | Preserve exact refusal; never create checkpoint/receipt from labels, installation consent or test-shaped data. Explicit current final-decision successor policy must be decided before implementation. |
| Replayed final decision / simultaneous original and direct bases | Exact completed replay has the documented zero-write semantics; foreign/conflicting replay or double-decision basis refused. Preserve original negative tests. |
| Epic/feature reviewed design | Existing nonempty independent review chain, Source binding and proof validation remain required; no mini empty-chain exception reaches DAB. |

No human signing, new public schema, Source application or approval was performed. Root's next concrete action is to include this bounded producer/record/reader contract and its ownership in the collected PO design package, rather than weakening the existing review contract in the owned State pair.
