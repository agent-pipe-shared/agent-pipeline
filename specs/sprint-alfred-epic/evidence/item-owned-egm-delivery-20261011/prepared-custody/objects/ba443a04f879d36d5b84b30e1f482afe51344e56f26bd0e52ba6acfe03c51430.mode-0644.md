# Empty v2 preparation option: bounded design, not an implemented route

An empty pipeline.slice-queue.v2 for the current feature is structurally valid. lib/slice-queue.mjs:535 requires slices to be an array; item-delivery fields are checked only inside its per-slice iteration starting at line 541. The existing empty-queue unit assertion is at lib/slice-queue.test.mjs:207 (that assertion uses its ordinary queue helper and does not independently prove the v2 case). resolveGovernedItemQueue checks v2 schema, full validation and exact current feature, but imposes no nonempty requirement (native-goldfish-host-state.mjs:802-805).

This would fix missing-queue availability only. Empty metadata yields no ready item or delivery binding. prepareNativeGoldfishHostState requires a named ready item at lines 159-163; guard-dispatch.mjs:451-457 still requires supported native transport and genuine marked binding. Existing prepareGovernedItemQueue still requires bound requester association at line 826 before authentic ready-item authoring. Empty preparation must not change any of those conditions.

ADR-0087 is accepted but absent from the older compiled decision projection read earlier. Its actual document docs/adr/0087-owning-verification-authenticated-controller-test-channel.md explicitly limits the verification channel to existing journal effects and sanctioned disposable fixtures, granting no State/approval/public-authority write. Operating Model lines 307-321 define internal owning-verification preparation under a real approved course. The fixed controller entry at scripts/owning-verification-controller.mjs:117-125 obtains genuine runtime through session-requester-bridge.mjs:1589; the bridge admits only that exact fixed program/cwd/six-selector argv, real approved course and original physical references. This is not a generic course-writer enrollment hook.

Bounded implementation option for Root evaluation:

- Add a distinct Source-owned empty-course preparation function in lib/native-goldfish-host-state.mjs, or an exact small helper imported there, using the existing observeCurrentPlanApprovalForCalibration and inspectSignedDescriptorCustodyRepository observations. Derive feature, path and candidate from genuine current approval/State, accepting no caller feature, requester, actor, receipt, queue body or item selectors.
- Give it a fixed entry, for example a proposed scripts/prepare-governed-item-queue.mjs --root <canonical-root>. This is a NEW proposed command, not executable current Source. It must observe current original signed approval, physical selected State/PRD/Spec/candidate, safe containing directory and exact absent queue before preparing only {schema:ITEM_QUEUE_SCHEMA,feature:<derived>,slices:[]}.
- Publish exclusively without replacing an existing queue, with 0600 inode, fsync and bounded readback. Recheck the same original approval references, State and candidate before and after publication. Idempotent replay accepts only an already valid empty same-feature queue; existing nonempty/v1/malformed/linked/foreign evidence is preserved and refused or handed to its existing owner. Do not migrate, amend or create ready rows.
- Keep all existing native ready-item/requester checks unchanged. Do not introduce this effect in a Verify child, use verification-only handles to authorize it, or weaken the fixed owning-controller identity check. Any guard admission must cover only this one derived empty preparation, never general node/interpreter/queue writes.

Expected owned files: the bounded queue preparation implementation and fixed CLI, focused native-goldfish-host-state/CLI tests, and whichever existing canonical command/write-path classifier the exact new entry needs. Update architecture/map/pipeline-core.md and the appropriate Source contract inventory if a new public entry is exported. Do not change Pipeline State, Main/C2 approval producers, live authority bytes, v2 schema or ready-item binding contract. Exact guard files should be selected only after Root inspects current command-registration ownership; this audit does not invent an admission allowlist.

Focused case plan: (1) genuine current approved course + missing queue creates exact empty v2; (2) replay preserves identical bytes; (3) no approved course, stale/revoked/mismatched original proof or foreign root refuses without queue; (4) State/PRD/Spec/candidate drift before publish refuses; (5) symlink/hardlink/unsafe directory or existing foreign/v1/malformed/nonempty queue conserves preimage; (6) exclusive concurrent publication permits one owner and never overwrites; (7) empty queue passes governed structural projection but ready-item dispatch still refuses NGHS-ITEM-NOT-READY; (8) direct ready-item authoring still refuses absent authentic requester; (9) no State/approval/member/release changes or additional human ceremony. Production qualification needs genuine Source default observations; controlled tests alone are not native authority.

The existing native requester requirement protects an effect that both creates the queue and authors an authenticated ready item; current Source does not separate those effects. Empty-only initialization has no ready-item or requester authority to grant, so schema/runtime evidence does not require inheriting that requester condition. Removing the condition from the existing writer WOULD weaken productive admission and is excluded. A separate tightly bounded metadata preparation is an additive Root policy/implementation choice under the stated user recovery intent, with architecture/significance assessment and independent review appropriate to the changed writer boundary. It is not already granted by ADR-0087's verification-only child channel, and this audit does not self-approve a new authority or claim acceptance.

No implementation, queue creation, fake association, Source mutation or test execution occurred. Reports v1-v3 and Root-observed refusals remain intact.
