## Exact cause and owner semantics

In `plugins/pipeline-core/hooks/guard-dispatch-budget.mjs`:

- `localCounterLockOwner`, lines1051–1064, dispatches win32 then explicitly throws for every non-Linux platform at1057. Darwin cannot even publish its uncontended first lock.
- `readCounterLock`, lines1097–1113, only admits linux/win32 at1107 and only numeric processStart at1111. Merely adding a Darwin producer would still reject existing Darwin records.
- `counterLockOwnerState`, lines1131–1145, dispatches win32 then returns ambiguous for non-Linux or platform mismatch at1134. Darwin stale/live ownership is never evaluated.
- `win32CounterLockOwnerState`, lines1024–1048, compares creation epoch only for its own PID. For a different PID, successful kill(pid,0), and even EPERM, produce live without comparing creation time. A reused live foreign PID therefore pins a provably stale identity. Whole-second Date.now-minus-uptime identities also have ±2s process and ±300s boot tolerances; these are not an immutable native process-creation identifier.

Lock authority should be only local host + platform + boot identity + PID + kernel process creation identity; nonce binds this lock publication. Kernel-proved absence or creation mismatch is dead; exact boot mismatch on the same known host is dead; matching immutable identity is live. Foreign host/platform, unavailable/permission-denied observer, malformed native output, unknown result or drift is ambiguous and preserves persisted bytes. Liveness alone cannot prove identity. Do not replace the owner tuple with mutable cwd/argv/parent/group/session comparisons: those richer supervisor facts can change without the lock holder dying. Do not use wallclock-minus-uptime, ps lstart, PID alone or a caller-provided fixture as native evidence.

Current contention wait is3000ms, monotonic performance.now, backoff5ms doubling to100ms, stable-read up to8 attempts with1ms sleeps. Its four retryable outcomes are busy/changed/recovery-busy/recovery-raced; malformed, ambiguous and genuine recovery failure return immediately.
