# Proposed ADR: A controlled METHOD review target has its own truthful admission class

## Status

Proposed, unnumbered, 2026-10-10. No acceptance, activation, exception or source implementation. Root collects this decision for the absent PO. Existing admission and typed-unavailable behavior remain authoritative. ADR numbers are allocated at acceptance; this draft claims none.

## Context

The genuine controlled continuity producer records a source-derived task, actual C0/C1/C2 commits, signed accepted package, real syntax diagnostic/log and registered evidence-only course. Its opaque private handle and private observation binding deliberately make no model-authored, native-host or independent-review claim. The ordinary Critic target reader accepts a required authored v3/v4 delivery or the separate genuinely signed-quality-import branch. Consequently a METHOD observation cannot currently enter the ordinary packet/session admission route. Durable real result, receipt, consumed state and C1-to-C2 carry-forward writers already exist; the gap precedes them.

The immediate demand came from twenty-six controlled positive State/I08 constructor cases. A testing need is not by itself authority to change production review policy. Creating historical v3 rows, native v4 observations, JSON PASS verdicts or pretending that a syntax diagnostic is a review would falsify provenance. Copying the final Alfred review's receipt to a different repository/task/C1/diff is equally invalid.

ADR-0014's current batch amendment requires one genuine fresh independently briefed read-only Critic per batch and delta-only followups. The user said one Critic followed by diff reviews. That can describe a bounded review policy per work batch; it does not itself answer whether separate controlled fixture targets are separate review work. Root's current operational brief is stricter: one final Alfred Critic, retained until the PO clarifies. This proposal changes neither rule and authorizes no additional review invocation.

## Decision proposed for the PO

Choose whether to authorize a distinct, confined source-owned METHOD target-admission class, or retain existing ordinary/authored admission and supply a real same-task review through that route. Do not add a production schema merely to turn synthetic constructor tests green.

If the distinct class is accepted for a justified operational need, implement exactly these boundaries:

1. A new source-private target module constructs an opaque handle from the genuine METHOD producer and private local METHOD binding. It reopens physical root/common, task/feature, C0/C1/C2, original signed accepted package/course/diagnostic and source custody. There is no caller record, approved boolean, model/native ID or arbitrary path/command.
2. Packet preparation accepts only that genuine opaque handle through a named option. It stores a distinct closed `pipeline.controlled-method-review-target.v1` snapshot in its coordinator-only binding. Serialized JSON alone cannot select the branch or mint admission. Ordinary authored and signed-import branches remain unchanged.
3. Session admission/finalization reopens the same private source target and retains every actual preflight, course, candidate, reference, session, route, verdict, durable result/receipt/consumption and replay check. An actual independent fresh read-only reviewer supplies the verdict. Source construction never does.
4. The continuity carrier selects this exact target branch, reads the genuine default consumed C1 receipt, verifies real evidence-only carry to C2, and uses the actual committed suite/default FD3 journal. Full Result/audit/coordinator/owned descriptor closure remains mandatory.

The new target declares METHOD provenance, `native=false` and effective model identity unverified. Reviewer assurance remains `functional-equivalent-read-only; OS isolation not asserted`. This is target admission, not an executor, agent launcher, host-enforcement receipt, provider attestation or generic grant. M1 host-first mutation admission, M2/M3 report-only and M5 native authored observation/attempt/terminal gates remain unchanged.

## Alternatives and recommendation

### A. Use the existing genuine ordinary review route first

An actual host-authored same-task delivery can supply the existing local binding. Then existing preflight, real fresh review, session finalizer and default consumed reader operate without a new target class. Native isolation is optional for ordinary session review; genuine authored source provenance and reviewer independence still matter. This is the preferred option when an actual lawful delivery and review are available. It avoids a production schema change whose only immediate beneficiary is a synthetic test harness. It does not authorize fabricating such a delivery, activating unavailable native hosts, changing runners or spending an extra Critic.

### B. Add the confined METHOD target class

This truthfully represents a source-generated target without impersonating model authorship, and reuses real review/consumption rather than adding an executor. It adds an enduring admission/schema/security contract across four source leaves, with explicit private-handle and persisted-snapshot compatibility requirements. It still requires a real review of that exact target; it does not make twenty-six unrelated fixture targets covered by the final Alfred review. Select this only if the PO wants this target type beyond a convenience for synthetic positives, and closes the actual review-budget application.

### C. Retain component qualification and the fullclosure gap

Qualify genuine physical producer/registry/State/transport invariants and the refusal when no consumed review exists. Keep the complete constructor acceptance explicitly open until real review evidence can be supplied. This provides useful honest evidence now without widening policy, but cannot be reported as all twenty-six complete positives or a production happyflow acceptance.

Recommendation: try A where genuine existing source evidence is available; otherwise retain C while the PO decides whether B has a sufficient operational justification. This recommendation does not approve or reject B on the PO's behalf.

## Consequences

A distinct class makes target provenance honest and can remove the incorrect dependency on fictional native/model delivery. It also widens which targets are eligible for durable review admission and adds compatibility/security surface. Exact private source authentication, source/physical CAS, one-use lifetimes, result/receipt journal consistency and negative controls are necessary. The existing batch policy must remain explicit: a review of one fixed candidate cannot be reused across different roots/tasks/diffs. Native/Windows assurance, provider identity, full State/I08 positives and final owned closure remain separately evidenced.
