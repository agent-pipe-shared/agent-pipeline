# External repair verifier design candidate

This is an inert Alfred Level C prototype, not an approved or installed repair tool. It does not establish a known-good release artifact, an operator signer anchor, Windows/macOS/WSL host evidence, or permission to touch a real source/install tree.

The standalone [external-repair.mjs](external-repair.mjs) imports Node built-ins only. `inspectIntent` reads exact physical source, installed-plugin and owner-private recovery roots, limits a manifest to eight existing `.mjs` code/test files under Pipeline `hooks/`, `lib/`, or `scripts/`, and binds root device/inode identities, preimage/postimage hashes, diff hash and expiry. State, private runtime material, proofs, trust/config files, arbitrary paths and creation/deletion are outside its allowlist. Postimages are read from the separate private root. The signed intent is the canonical manifest hash with the fixed `pipeline.external-source-repair.v1` domain; the verifier accepts Ed25519 only. The CLI requires operator-supplied artifact and public-key hashes on argv independently of the private request file, and requires an attended TTY with exact intent digest entry for apply. The CLI cannot sign.

On apply, an existing lock always returns `LOCK-OWNER-LIVE-OR-AMBIGUOUS`; age cannot reclaim it. The verifier archives immutable preimages, writes a journal, replaces each file through a same-directory temporary file and rename, and records the completed prefix. Replay accepts an already-written next file only if it matches the exact signed postimage, while all prior files match postimages and remaining files match preimages. Drift preserves observed target bytes and returns a typed unavailable or recovery-required result. A correction after replacement needs a new signed forward transaction. Tests cover happy path, interruption/replay, foreign writer drift, invalid proof, expiry, forbidden State path, retained lock, symlinked postimage and weak private custody. Fixture keys sign only synthetic test bytes; no operational proof was created.

The prototype deliberately returns `PLATFORM-RESOLVER-UNVERIFIED` outside native Linux. Its direct `lstat`/digest check followed by `renameSync` still has a concurrent-writer race; Node's path APIs do not provide an atomic compare-and-swap replacement against the previous inode. It is **not qualified for real apply** until that custody gap and host-specific layout/ACL/atomicity are resolved. A crash may leave a lock requiring attended owner inspection, and release/source channel trust still needs independent operator evidence.

No alternate test lane or override was used; runtime tests are unverified. Source/install/State/cache/proof/key/guard files were not edited.
