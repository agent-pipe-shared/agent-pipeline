# Design note: worktree-per-Goldfish (decision AQ, order 3 of 3)

Status: options for the PO (non-blocking); implementation follows in 0.7.0 with its own test slice, fix and full Critic (`plans/po-decisions-2026-10-07.md:49`, row AQ). Author: goldfish-deep, dispatch DESIGN-WT, 2026-10-08. Legend: [D] derived from a cited repo line (or documented git behaviour, marked "git semantics", not re-run here); [C] a choice or an unverified hypothesis. Nothing here was executed against worktrees; no cost figure is measured.

## 1. Problem, from the repo's own record [D]

- **Wrong base.** A host worktree is provisioned from the LOCAL `refs/remotes/origin/HEAD` target, not the current branch; here it sat on `origin/main`, hundreds of commits behind (`CLAUDE.md:49`). Self-heal by `git checkout --detach <sha>` is safe only inside a dispatch's OWN worktree (`CLAUDE.md:51`).
- **Isolation silently not granted.** 2026-08-25: three `isolation: "worktree"` dispatches landed in the Elephant's checkout (`git worktree list` showed one entry) and a retry's self-heal detached the Elephant's live HEAD (`CLAUDE.md:53`; `workflow-dispatch.md:47-50`). Hence the containment check (compare `rev-parse --show-toplevel` with the briefed path BEFORE any detach; `CLAUDE.md:51`) and the hard stop on a one-entry `git worktree list` (`CLAUDE.md:53`; `workflow-dispatch.md:52-59`).
- **The shared tree has its own record.** In a 10-dispatch round one ~47-call uncommitted edit was wiped by a sibling's self-heal and four commits sat on an orphan chain (`workflow-dispatch.md:76-87`). Rule: no self-heal in shared-tree briefings; sequence commits or "give each its own `isolation: "worktree"`" (`:89-103`). The two modes exclude each other (`:63-74`).
- **Records do not travel.** The worktree is discarded, so the Elephant writes any missing dispatch record itself (`workflow-dispatch.md:165-179`).
- **Toil a private index would remove:** T44 `.git/index.lock` collisions and false `GHS-SOURCE-DRIFT` (`evidence/toil-log-2026-10-06-07.md:49`, quoted in the write-lease note :8). **Not removed:** T51 ledger-flip stall, shared plan files (write-lease note :9, :19-23).

## 2. Seams in the code

- **Provisioning already exists.** `createDetachedWorktree` (`lib/worktree-lifecycle.mjs:1604`) resolves the OID itself (:1606), targets `<primary>/branch/detached/<purpose>-<oid12>` (:292-300), refuses an existing target (:1608), registers a `remove-worktree` cleanup intent in a session manifest (:1621-1630), runs `git worktree add --detach <target> <oid>` (:1632) and verifies readiness (:1633). `createBranchWorktree` is the branch form (:512). CLI wrapper `scripts/worktree-create.mjs:13-14,120-121`; also `scripts/clean-candidate-run.mjs:16,286`. Cleanup and hygiene: `cleanupSession` (:1733), `checkSessionHygiene` (:1878), `lib/session-cleanup-recovery.mjs:2534`. Because the creator resolves the SHA, the origin/HEAD base error cannot occur on this path.
- **Nothing provisions one per Goldfish today.** The briefed path+SHA pair (`CLAUDE.md:51`) serves host isolation only. Host isolation is detected, never prevented: the pre/post count check warns "exit 1, never blocks" (`hooks.json:39`; `lib/worktree-count-check.mjs:4-10,548`).
- **Guards keyed to the main root.** `CLAUDE_PROJECT_DIR` is the MAIN checkout while the cwd is the worktree; `guard-git.mjs:1048-1062` already needed a fix (message file refused as `GIT-03-UNREADABLE-MESSAGE-FILE`, 2026-08-28) and now derives containment from the cwd's own `show-toplevel` (:1066), "deliberately narrower" so a sibling worktree's files are refused. [C] Every other guard reading a repo-relative path (e.g. the `guard-devplan` exempt prefixes `docs/ specs/ scratch/`, `templates/prompts/agent-obligations.md` section 3) needs a worktree fixture; not audited here.
- **Location.** The detached target is inside the primary root (`branch/detached/...`, :296), so it stays inside repo containment (contrast `GUARD-CROSS-REPO-MUTATION` for outside paths, `workflow-dispatch.md:195-196`); the primary hides it with `ensurePrimaryBranchExclude` (:394, :1612).
- **Private state is keyed to the git common dir, so it is SHARED by all worktrees:** dispatch budget `<common>/agent-pipeline/dispatch-budget/<agentId>.json` (`hooks/guard-dispatch-budget.mjs:131,374-378`), fanout ledger (`lib/fanout-ledger.mjs:8`), verify runs (`scripts/verify-evidence-producer.mjs:206,381`), human-override capabilities (`lib/human-guard-override.mjs:192,934`), protected-path baseline (`scripts/check-protected-path-integrity.mjs:71,231`), signed packages (`lib/signed-quality-package.mjs:190`). Budget is per `agentId`; the other stores have no per-worktree isolation.
- **Hooks are per clone, not per worktree.** `pre-commit`/`pre-push` live in `<common>/hooks` with `impl.mjs` under `<common>/agent-pipeline/` (`scripts/pre-commit-hook-install.mjs:60-65`, `scripts/pre-push-hook-install.mjs:21-29`); linked worktrees run them (git semantics).
- **Per-worktree, not shared:** index, HEAD, and the untracked `evidence/` and `scratch/` directories. A record written in a worktree is invisible to `dispatch-authorship-verify` until copied (`workflow-dispatch.md:165-179`). Ledger, `STATUS.md`, `docs/state.md` live on the main checkout (write-lease note :13, :48). Refs, `refs/stash`, config and the object database stay shared (git semantics), so `git stash` and ref writes still cross worktrees.

## 3. Options [C]

**A. Elephant-provisioned detached worktree per Goldfish.** Elephant runs the sanctioned `worktree-create` verb at the exact candidate SHA; the briefing carries path + SHA; the Goldfish opens with the containment check; the Elephant merges back and removes the worktree.
- Breaks: (1) [C] whether the host can start a subagent with cwd = that path is NOT established in the repo (agent cwd resets between calls, so absolute paths are needed everywhere); (2) unaudited guards (section 2); (3) the dispatch record: write it inside the worktree and let the merge-back verb copy it, or Elephant-only (`workflow-dispatch.md:165-179`); (4) merge-back changes SHAs: `git cherry-pick` of the Goldfish's commits gives new SHAs, so the record's `commits` must hold the landed SHAs, and `--ff-only` when the base is unmoved keeps them; unmerged commits are unreachable after `git worktree remove`, so cleanup must refuse until they are on the branch (git semantics); (5) overlapping scopes need the existing "zero file overlap, else manual resolution" rule (`workflow-dispatch.md:97-99`).
- Cost: moderate. Provisioning, manifest, cleanup exist; new are the merge-back verb, briefing fields and guard fixtures. Per-dispatch checkout time and disk are unmeasured; Windows path length under `branch/detached/` is a risk, unmeasured.
- Failure mode: loud (typed `WT-TARGET-EXISTS`, containment mismatch, merge conflict) and local; a leaked worktree is swept by cleanup.

**B. Host `isolation: "worktree"` with mandatory post-launch verification and shared-tree fallback.**
- Breaks: nothing new in the repo. The base is chosen by the host, so the SHA self-check stays mandatory (9/9 landed with it, 0/9 without, `workflow-dispatch.md:44-46`); the containment check stays.
- Cost: lowest; detection exists (`hooks.json:39`). Failure mode: silent. Isolation can be not granted, the count check only warns after launch, and the fallback runs the dispatch in the shared tree it was meant to avoid. The 2026-08-25 incident is exactly this path. Merge-back and record copying remain manual.

**C. No worktrees; serialise writers through the write lease** (`orchestrator-write-lease-2026-10-08.md`).
- Breaks: parallel throughput (writers wait). The lease is advisory: a raw `git commit` or a subagent Edit bypasses it, and PreToolUse does not fire in subagents (write-lease note :39), so a half-edit after a cap-cut (T56) stays possible.
- Cost: lowest additional once the lease lands. Failure mode: contention and TTL waits, not corruption; no SHA-rewrite or record-copy problems.

## 4. Recommendation [C]

Take **A** for write-heavy parallel rounds whose scopes are disjoint, **C** as the default for single-writer, docs-only or one-file tasks and as the fallback whenever A's preconditions fail, and keep **B** only as a documented host path (never the primary). Rationale: A removes the failure class in section 1 by construction (the creator pins the SHA, so no self-heal is needed, and the worktree exists before launch, so "not granted" is observable before the dispatch starts); B's failure is silent and its only guard is after-the-fact detection; C alone leaves T56 and serialises everything. A is conditional on slice 0.

## 5. Interaction with the other two AQ items

- Order is fixed by AQ: script-mediated writes first (`script-mediated-writes-2026-10-07.md`, recommendation A: check against pinned digests at the next guarded call, pre-commit and pre-push; the pin source is its open PO question). [D] A common-dir pin store already exists for protected paths (`<common>/agent-pipeline/protected-path-integrity/baseline.json`, `check-protected-path-integrity.mjs:71`). [C] Whatever pin source the PO picks should be common-dir keyed, so a worktree and the main checkout compare against one pin; a protected-path edit made in a worktree must be caught before merge-back, and a legitimate change must move the pin once, at the main checkout, through the same ceremony; otherwise worktrees become a second write channel the pin never sees.
- Write lease: the lease root must be the common dir, not the per-worktree dir (write-lease note :36). Per-worktree indexes retire key `index` for the worktree itself, but the merge-back verb writes the main index, so it takes `index` and `ledger`; shared plan keys remain. The ledger verb (write-lease note :45-48) is the natural merge funnel.
- Shared private state (budget, overrides, baseline) needs no migration; it is already common-dir keyed.

## 6. Slice plan (test-first) and PO choices

- **Slice 0 (probe, no product code):** Elephant records, as an evidence file, whether the host can start a Goldfish with cwd = a provisioned worktree and what `show-toplevel`, `CLAUDE_PROJECT_DIR` and `git worktree list` report from inside. Gates A.
- **Slice 1 (red first), new `lib/goldfish-worktree.test.mjs`:** provision returns path+SHA for a given OID and refuses an existing target; the containment check accepts a matching `show-toplevel` and refuses a mismatch without ever emitting `checkout --detach`; the budget and override stores resolve to the same common dir from main and worktree; a `-F scratch/msg` commit in the worktree is admitted, a write into a sibling worktree is refused.
- **Slice 2 (red first):** merge-back verb: `--ff-only` when unmoved keeps SHAs; diverged cherry-pick keeps the `Dispatch:` trailer and records landed SHAs; overlapping paths refuse with a typed code; cleanup refuses while commits are unmerged.
- **Slice 3:** briefing template fields (path, SHA, containment first step, no self-heal for A) and a scripted post-launch `git worktree list` check; guard fixtures for any guard slice 1 finds keyed to the main root. Protected files: new `*.test.mjs` only; registering suites in `harness/verify-suites.json` is TP-13 (signed ceremony).
- **PO choices (non-blocking):** (1) A, B or C as the default for parallel write rounds; (2) merge-back policy: ff-only else cherry-pick, or always cherry-pick; (3) dispatch record written in the worktree and copied, or Elephant-only; (4) cap on simultaneous worktrees (disk, Windows path length unmeasured); (5) worktrees for every write dispatch or only rounds with intersecting scopes; (6) retire the self-heal block for A-provisioned dispatches.
