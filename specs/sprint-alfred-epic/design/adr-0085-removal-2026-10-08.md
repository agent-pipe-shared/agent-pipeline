## 0. PO items first (decisions this note needs)

1. **Ordering of the §17 edit (consequence, not a stop).** Editing `spec.md` changes the Spec digest. The current
   approval binds that digest (`project/pipeline-state.json:621-622`, `poGateAuthority.specPath/specSha256`), and the
   v2 package also binds it as a source. From the commit that edits §17 until the new approval is written,
   `guard-devplan` therefore refuses every implementation write outside the exempt prefixes. This holds for every
   0.7.0 slice in flight, not only this one. Recommendation: implement all code slices (section 5, T0–F8) under
   decision I inside the current approval. Then make the §17 rewrite the **first design revision through the new
   route**: one review, then `present-plan --review-receipt`, then one signature. Batch it with every other pending
   spec reconciliation, such as the survey's spec/ADR reconciliation note
   (`plans/backlog-survey-2026-10-08.md:132-133`), so that the 0.7.0 candidate pays exactly one re-approval.
2. **This repo's own approval stays verifiable without a re-approval, under one condition (section 4).** The approved
   package bytes live at `evidence/design-course/sprint-alfred-epic/r5d.package.json`
   (`project/pipeline-state.json:626`). The survey maps that location to an ignored directory: item
   `2026-10-06-approval-bound-design-package-lives-in-an-ignored-directory` → R7-3 (`backlog-survey-2026-10-08.md:126`;
   I did not re-measure the ignore rule). On this machine the re-read works as long as the bytes exist. On a fresh
   clone or the second PC it works only if those exact bytes are tracked. If they are lost, the consequence is one
   re-approval of revision 5, or, if item 1 is accepted, the §17 revision's approval doing that job. Recommendation:
   migration step M1 (section 4).
3. **Approval mode of the new record.** Current §17 allows the final decision "in either configured chat or
   signature mode" (`spec.md:1038-1040`). The landed U1–U3 contract reserves the new record with `mode: "signature"`
   (`plans/adr-0085-u1-u3-api-contract.md:201`). This needs a decision; see [C] C4 below.
4. **Meaning of "removal" in BM.** Recommendation: in 0.7.0, remove the old stack **behaviourally**. It stops being
   an approval input, its entry points return typed retirement codes, and the implementation boundary stops reading
   it. Defer **physical** deletion of the then-unreferenced library modules to 0.8. See [C] C9.

## 2. [C] Removal / fold plan

Every option is judged against BJ: keep the enforcement layer; consolidate, don't rebuild; fewer blocking states,
paths and repairs.

**Enforcement properties kept (all options below must keep them):**

| Property | Old carrier | New carrier |
|---|---|---|
| PO decision binds the exact sources | package digest + signed intent | U3 `bindingSha256` over sources/receipts/verdict/open findings, plus a signed `design-approval` intent |
| Signature against the trust anchor | `verifyStoredDesignWorkflowPackageSignature` (`design-workflow-approval.mjs:137`) | the same trust policy (`guard-devplan-policy.mjs:129-131`) over the new intent |
| Authority only while the scope is unchanged | package source digests vs current files | binding source digests vs current PRD/Spec/companions at the boundary |
| Stale / replayed approval rejected | request path + package sha + readback (`pipeline-state.mjs:11100-11118`) | request binds `bindingSha256` + candidate (`design-approval-binding.mjs:63`); atomic readback kept |
| Independent review | readiness child + Critic | one mandatory independent review receipt (U2), ≤2 rounds (QG-13) |
| Typed, never silent failures | DWP/DWP2/DAA/DAC codes | DCC (U1), DRR (U2), DAB (U3) and retirement codes |
| Mini profile needs no design artifact | `guard-devplan-policy.mjs:104-108` | unchanged |

**BJ accounting:** nothing below adds a lifecycle state. `DWP2-LEGACY-APPROVED-REREAD` is a read mode of an
existing approved state. The retirement codes are typed refusals on retired entry points. Removed blocking surfaces:
the course-store and candidate-drift refusals on the hot path (`DWP2-FAILURE-DRIFT`, `DWP2-PHYSICAL-OR-GIT`,
`DWP2-DURABLE-*`, `DWP2-*-HOST-*`), Advisor-course admission (`DAC-*`, `DAC2-*`), readiness binding/host refusals and
the authoring continuity registration.

**C1. Implementation boundary (`guard-devplan-policy.mjs:93-203`)**
Recommendation: (a) add a new-record branch selected **only** by the new record schema. It verifies the U3 binding
and the signature, and compares current source digests with the bound ones. It does not run U1 per write (U1 runs at
present/approve). (b) Route the v7 legacy branch (`:103-152`) through the re-read mode of C2 instead of
`readApprovedDesignWorkflowPackage`. (c) Freeze the pre-v7 branch (`:153-199`) as it is in 0.7.0. (d) Rewrite the
remediation text (`:205-209`) to name `present-plan --review-receipt` instead of `design-advisory-coordinator.mjs`.
Rejected: deleting the pre-v7 branch now, because it strands older consumer approvals, contrary to ADR-0085's
"existing approvals stay valid". Rejected: running U1 on every write, because it reads traceability per write and adds
cost and no extra protection beyond the digest comparison. Rejected: keeping the full v2 reader on the hot path,
because that keeps T83 and the second-PC failure.

**C2. Legacy re-read mode `DWP2-LEGACY-APPROVED-REREAD` (decision T)**
Recommendation: a new export in `design-workflow-package.mjs` that verifies only what decision T lists:
1. the package bytes at the recorded path hash to `designWorkflowPackageSha256`;
2. the closed package shape (v1/v2);
3. the package's PRD/Spec references equal `poGateAuthority.planSha256/specSha256` and the current file bytes;
4. `designWorkflowAdvisorExceptionBinding` recomputed from the package bytes equals the recorded `advisorException`
   (`design-workflow-package.mjs:641-646` uses package fields only);
5. the signature against the trust anchor.

It reads **no** course store, host evidence, revision chain or live candidate. `verifyStoredDesignWorkflowPackageSignature`
must call this re-read instead of `readApprovedDesignWorkflowPackage` (`design-workflow-approval.mjs:145`). Otherwise
the signature path still reaches the course store.
Rejected: requiring re-approval of revision 5, because it costs a PO signature for no content change and violates
ADR-0085's Consequences. Rejected: trusting the state record without re-hashing the package bytes, because the signed
intent binds the package digest, so dropping the byte check would weaken the signature binding. Rejected: keeping the
revision-chain `git show` check, because decision T does not list it and it needs the historic commits.

**C3. present-plan / inspect (`pipeline-state.mjs:10581-10677`, `:4139-4142`)**
Recommendation: `present-plan --review-receipt <path>` (at most 2). It runs U1, builds the U3 binding and request,
writes the request and review summary to `scratch/` and prints one ready sign command with absolute paths and the key
directory (T25). The legacy `--design-workflow-package` flag gets the typed refusal `DWP-PRESENT-RETIRED`
(decision V). inspect replaces the course invocation with a read-only U1 result and the next action
`present-plan --review-receipt`. Rejected: keeping both flags, because two presentation routes double the states and
repairs (BJ). Rejected: auto-discovering receipts, because which receipt is meant becomes ambiguous.

**C4. approve-plan, record and mode (`pipeline-state.mjs:10833-11118`; `plan-spec-state-v2.mjs:16`, `:219`)**
Recommendation:
- `approve-plan --design-approval-request <path>` verifies the U3 request and writes `pipeline.plan-approval.v8`,
  carrying `designApproval` (`pipeline.design-approval.v1`) instead of the four `designWorkflow*`/`designAdvisor*`
  fields. v7 stays readable through C2.
- **Mode:** keep the configured mode, so the new record carries `mode: "signature"` (detached proof) or
  `mode: "chat"` (attribution record bound to the same `bindingSha256`, labelled as attribution, no proof). That
  follows current §17 and the push-gate model (ADR-0056). It requires amending the contract's P1 keys (PO item 3).

Rejected: a v7 envelope with an extra optional field, because U3 classifies hybrid records as invalid
(`design-approval-binding.mjs:352-359`) and a hybrid is a third record shape. Rejected: signature-only, because it
would silently remove a mode §17 grants today and strand chat-configured repositories; ADR-0085 removes machinery
between "finished" and "signs", not the PO's configured mode.

**C5. submit-plan and continuity**
Recommendation: keep `submitPlan` and its idle-continuity clause (`plan-spec-state-v2.mjs:676`; clause [D-plan]). It
no longer trips, because nothing registers a design authoring dispatch any more. Remove only the authoring-dispatch
requirement, which lives in the retired course session. Rejected: deleting the idle precondition, because it is
enforcement unrelated to the design registration (BJ "keep protection paths").

**C6. Advisor stack (1.3)**
Recommendation: it is no longer an approval input. `scripts/design-advisory-coordinator.mjs` and
`scripts/design-advisory-admission.mjs` become typed stubs returning `DESIGN-ADVISORY-COURSE-RETIRED`, with the hint
"ask an Advisor on demand; run one review; `present-plan --review-receipt`". The on-demand Advisor (the
`advisor-consult` skill and `consult-advisor` agent) stays. Its answer may be cited in the sources or review, with no
receipt schema required. Advisor transport rules (consent, export denial is final) stay. Rejected: deleting the
transport/consent rules, because they protect egress and are not design-phase machinery.

**C7. Readiness stack (1.4)**
Recommendation: remove the readiness gate from every reader except the frozen legacy readers. Readiness entry
scripts become typed stubs returning `DESIGN-COURSE-RETIRED` (readiness was a course stage, so no fifth code).
`agents/readiness-reviewer.md` is retired. The one review is done by the existing independent Critic (`critic` agent,
`templates/prompts/critic-review.md`), and its result is written as the U2 receipt.
Rejected: keeping readiness-reviewer as the reviewer, because that keeps a second reviewer role with readiness-specific
host isolation duties. Rejected: a dedicated `DESIGN-READINESS-RETIRED` code, because it adds one more code for the
same remedy.

**C8. Course session, builder, catalogue (1.5)**
Recommendation: `runDesignCourseV2`, the package builder and the course coordinator become typed stubs returning
