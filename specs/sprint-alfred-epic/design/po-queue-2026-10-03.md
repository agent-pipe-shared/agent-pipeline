## PO decisions after approval (2026-10-04, chat)

- **Restructure belongs to 0.7.0; the release slips accordingly.** The Pipeline's own architecture must become
  usable and evolvable now. Rationale (PO): every fix round currently produces follow-on defects because of
  the poor dogfood architecture.
- **Local intermediate candidates are allowed** where they simplify the work (for example, first install a
  candidate with a sound design phase before fixing the implementation phase). Each is stamped locally and
  installed by the PO; it is not the qualified 0.7.0 candidate.
- **Fable review scope:** (1) process defects, needless pass-through states, duplicate fields and double
  checks; (2) all oversized modules with concrete split proposals; (3) code to consolidate or delete.
  Output: a staged, priced proposal for the PO decision (D4 dogfood route; input only, no scope change).
- **Brownfield architecture fitness is optional** and is corrected only on PO request.
- **Model gap:** the model lacks an explicit "established/active" architecture state in which the accepted
  baseline keeps ratcheting (net-new findings block, accepted ones frozen) while full adoption is deferred.
  Owner: D3/D4 design check plus the Fable review input. Hotfix 10 (deferred → fitness report-only) is the
  interim unblock, not the target model.
- **Agreed order:** W0 persistence → W0-3 port of hotfixes 1–10 plus the minimal approved-state fix →
  intermediate candidate 1 → Fable review → staged restructure candidates → qualified 0.7.0.

## PO decisions 2026-10-04 evening and 2026-10-05 (chat)

- **One design review instead of Advisor plus readiness review (2026-10-04).** The design-phase Advisor and the
  independent readiness review merge into ONE independent review with two outputs (improvement proposals and a
  ready/not-ready verdict), run after the draft and once more after the revision; one course state and one evidence
  chain (R5). Needs the design amendment (Spec §17, §21.5), R5, the critic-review template and QG-13.
- **Proportionality for profile `feature` (2026-10-04, PO: "Ja dein Vorschlag oben passt").** Exactly one design review
  and one implementation Critic; no re-review and no re-Critic rounds. Findings are fixed and the fix is proven by
  tests and Verify; a single bounded re-check only for a `blocker` finding in an authority, security or guard area.
  Profile `epic` keeps the current bounded rounds (QG-13).
- **Session-residue root fix, first cut (2026-10-04, AskUserQuestion).** A foreign session descriptor with an
  unobservable owner and no resources is archived without a signature (typed action, bytes preserved, digest-bound,
  never deleted, audited); a foreign resource-free residue only warns. Verify retires its own descriptor on every exit.
- **Verify timing for intermediate candidate 1 (2026-10-05, PO: "ja der full verify reicht mE nach der installation
  wenn sonst alle tests so grün sind bzw es nur testfehler sind").** The full Verify runs after the install on the new
  code; test-only failures are listed in the candidate report.
- **Readiness root fix, superseding the first cut (2026-10-05, PO: "Ja okay mache das so").** Session readiness
  evaluates only the own session's descriptor. Foreign descriptors (any producer, live or dead, with or without
  resources, any platform) never make the session `partial`; they go to a cleanup list that warns and offers archive.
  Verify and other tool runs create no session descriptor at all; they keep their own run record and cleanup duty
  outside session readiness. A live second Elephant session in the same repository (EL-18) stays a visible warning via
  the concurrent-session check, not a lock. This replaces "descriptors with resources keep blocking" from the first cut.
- **Own-session identity for readiness (2026-10-05, AskUserQuestion: "C jetzt, A mit R3").** Today no runner (Claude,
  Codex, Antigravity) creates a persistent own session descriptor, so every descriptor counts as foreign and only warns.
  When a runner flow starts creating persistent own descriptors (e.g. one worktree per Goldfish in R3), its start hook
  exports an owner nonce bound to the descriptor, and from then on the own descriptor blocks again. No hook change now.
- **Verify duration is a gate requirement (2026-10-05, PO: full Verify ~15 min on WSL, target 5–10 min; the >1.5 h
  native-Windows run "können wir so nicht laufen lassen").** The native-Windows Verify cost is fixed before the next
  full Verify; measured root cause: every git-hook install copies and per-file verifies the whole plugin (894 files)
  including per-file PowerShell DACL reads (~85 s per onboarding test case).
- **Integration model for parallel Goldfish work (2026-10-05, PO: "finde ich gut! gerne advisen und dann für einen
  der kommenden kandidaten vorsehen zB R3?").** Target picture: one worktree per Goldfish; the Goldfish commits inside
  its own worktree (protects against loss); the Elephant integrates into the working branch by cherry-pick or rebase.
  Until then: exactly one committing agent at a time plus read-only parallel work. Advisor consult first, then planned
  for an upcoming candidate (proposed: R3), via the design amendment before S2.
- **Ground rule: full runner, platform and repository matrix (2026-10-05, PO: "diese ganzen verbesserungen müssen
  immer für claude, codex, agy und windows, unix/wsl und macOS und eigenes repo und user repos gelten! das ist eine
  ganz kritische grundregel die viel zu oft missachtet wird!").** Every fix and improvement is designed, tested and
  reported for Claude, Codex and Antigravity × native Windows, Unix/WSL and macOS × this repository and consumer
  repositories. Every briefing carries a matrix DoD, every Critic spec matrix acceptance criteria, every candidate
  report a matrix table with tested / untested (no host evidence, with reason) / not applicable — never silent.
- **Signatures are never a reason to defer work (2026-10-05, PO: "Signaturen sind nie ein Problem und sollten dich nie
  davon abhalten dinge fertig zu machen. Einfach anfragen! ich teile mit wenn sie länger nicht möglich sind wegen afk").**
  Protected-baseline fixes land in the current candidate as a signed package; the agent requests the signature.
  Roadmap after 0.7.0: remote/asynchronous signing so packages can be signed while the PO is away from the terminal.
- **Dispatch budget: checkpoint and hand back instead of a hard abort (2026-10-05, PO: "dass ein goldfisch dann nicht
  mehr hart abbricht sondern nur diese info dem elephant gibt damit der entscheidet was passiert und definitiv wird auch
  ein zwischenbericht dann geschrieben um darauf aufzusetzen").** Before the cap, the dispatched agent is told to commit
  green work, write an interim report (done / remaining) into its dispatch record and hand back to the Elephant; at the
  cap the closing lane admits that report (and the Critic's notes); the Elephant decides — grant more budget through a
  sanctioned record and continue the same agent, or dispatch a follow-up that builds on the interim report. Claude:
  hook-enforced; Codex and Antigravity: binding briefing duty in both templates until their budget adapters exist.
- **Single source of truth for configuration (2026-10-05, PO: "Genau so was muss behoben werden eine config an zwei
  Stellen das muss die Architektur eigentlich abfangen").** A configuration value has exactly one source; every other
  consumer derives it. First case: agent `maxTurns` lives only in `agents/*.md`; `dispatch-policy.mjs` derives its tier
  from the definition (its own table is removed), so guard-dispatch and guard-dispatch-budget cannot disagree. The S0
  ratchet test is extended to duplicated configuration values, not only duplicated helper names.
- **Verify duration: one more optimisation round, then stop (2026-10-05, PO: "Okay eine optmierungsrunde dann noch
  und dann lassen wir es erst mal so").** After the IC-2a full Verify, the slowest suites (by measured per-suite

- **Pipeline overhead target and measurement (2026-10-05, PO: "in einer perfekten welt kriegen wir das auf 10%
