## 3. Contract [C]

**BJ statement. R6 adds NO blocking state, no new State field, no new repair route and no new writer.** Drift is a read-only projection in `inspect` whose recovery is a pointer to the existing `continuity-authority-revision-plan` route (seam 7). The audit index is a read-only report that nothing else consumes, so its "missing step" list cannot block anything. Not needed because: both clauses ask to SURFACE and to NAME, and surfacing needs no state. Rejected alternatives: a fifth `blocker.type` (seam 6; would make a stale digest stop dispatch and add a state a human must clear); reusing `continuity.recovery` (wrong semantics, CAS-written, inspect is read-only); a new `drift` field inside the 8 KiB continuity object (schema change in a closed, validated record); a completeness gate on `close-feature` (new blocking state, see open choice 4).

**Q1 Which `inspect` verb (plan `:213`).** Recommended: `node scripts/pipeline-state.mjs inspect` (seam 1). It is the only `inspect` that holds `continuity.authority.{prd,spec}` and already has the drift-to-recovery pattern. Rejected: the onboarding `inspect` (`scripts/project-onboarding-v3.mjs inspect`, schema `pipeline.project-onboarding.v4`, not read; a different checkpoint model); a new verb (BJ). Open choice 1 records the residual doubt.

**Q3 Open-recovery entry shape (plan `:215`).** Recommended: one additive payload key `continuityAuthorityDrift`, `null` when `base.continuity` is absent (the payload's own convention, seam 1), else:
`{ schema: "pipeline.continuity-authority-drift.v1", status: "current" | "drift", featureId, revision, artifacts: [ { role: "prd"|"spec", path, recordedSha256, observedSha256: <hex>|null, state: "match"|"changed"|"unobservable" } ], recovery: null | { kind: "repair-required", code: "CONTINUITY-AUTHORITY-DRIFT", route: "continuity-authority-revision-plan", mutation: false, requiresConfirmation: false, guidance } }`.
- Compare exactly `prd` and `spec` (SPEC wording); `result` and `plan` are excluded (`result` is null before close, `plan` shape unread).
- Fail closed: "cannot prove a match" is drift. A null observation (missing file, or unsafe path per seam 4) gives `state: "unobservable"` and `status: "drift"`; this mirrors the plan path, which passes null observations on (`:3988-3989`). Any thrown error while observing is caught and treated the same; `inspect` never throws because of this field.
- Observer injected: a pure module takes `(continuity, observeSha256)` where `observeSha256(relPath)` returns hex or null. Production passes a wrapper over `physicalRebindFile`; tests pass fakes. No filesystem access inside the module.
- `nextAction` precedence: the existing branches (mixed-plan, `reopen-design`, lifecycle) win and the drift is reported in the field only; when `buildInspectNextAction` would return `null` and drift exists, it returns the `recovery` object as a `repair-required` action. One edit to the PRD that also drifts the plan submission therefore yields ONE recovery action (the existing one), not two. `status`, `lifecycle`, `planApproved` and `continuityDispatchAllowed` are untouched by drift (report-only, open choice 2).
- Paths in the field are exactly the repo-relative strings recorded in State; digests are 64-char lowercase hex; nothing machine-specific is emitted.

**Q2 Audit index: location and format (plan `:214`).** Recommended: a standalone read-only script `scripts/audit-index.mjs` over a pure module `lib/audit-index.mjs`, printing one JSON document to stdout; persist it with the existing `scripts/capture-evidence.mjs` into the ignored `evidence/` root (seam 10) rather than inventing an output path or flag. `--out` is NOT added in v1. Change unit: one feature, `--feature <id>` defaulting to the active feature (State keys PRD/Spec, approvals and close evidence by feature; a commit range has no gate digests). Shape:
`{ schema: "pipeline.audit-index.v1", featureId, sources: [ { role, path, sha256, recordedSha256, state } ], commits: [ { sha, attribution: "dispatch"|"stage-0"|"unattributed", taskId, recordPath, recordSha256 } ], gates: [ { gate, status: "present"|"missing"|"digest-mismatch", artifact: { path, sha256 }|null, locator } ], missingSteps: [ { kind: "source"|"commit"|"gate", ref, code, expected } ], complete: boolean, indexSha256 }`.
- `sources` reuse the drift module's per-artifact record (one implementation of "recorded vs observed", not two).
- `commits` are enumerated 40-hex SHAs (the feature's commits come from an explicit list or `--base <sha>`; never a bare range echoed back). Commit subjects are NOT included (free text, may carry private content). A commit with no `Dispatch:` trailer is listed as `unattributed`, never dropped (mirrors `UNVERIFIABLE`, seam 9).
- Gate set v1, closed and sorted: `plan-approval`, `verify`, `critic-review`, `push-approval`, `close-evidence`, each with a `locator` naming the existing carrier from seam 9. Gate digests are read from those carriers, never recomputed from prose. This set is a recommendation: derive the final list at slice start from the close-check/close-block gate list (not read, open choice 5) so there is one list, not two.
- `missingSteps` codes: `AUDIT-GATE-MISSING` (no artifact or State key), `AUDIT-GATE-DIGEST-MISMATCH` (artifact present, recorded digest differs), `AUDIT-SOURCE-DRIFT`, `AUDIT-SOURCE-UNOBSERVABLE`, `AUDIT-COMMIT-UNATTRIBUTED`, `AUDIT-COMMIT-UNKNOWN`. Each entry names what was expected and where, so a human can act on it.
- Deterministic: sorted rows, canonical JSON, NO timestamp; `indexSha256` = SHA-256 of the canonical JSON of the document without that key. Exit 0 whenever the index was generated, `complete` carries the verdict (report, not gate). Refusals (unknown flag, no State, unknown feature) are typed, non-zero, with zero writes.
- Guard admission: an agent runs scripts through the closed shell grammar, so a new script may need a sanction entry (`templates/prompts/agent-obligations.md:124-129` shows the read-only script exemption is a derived table). That entry would be a guardrail surface (section 5, F5); it was not read (section 7).

## 4. Test list (test-first; fixtures only: temp repos and in-memory State, never the real home)

All tests go into NEW unprotected files (seam 11). If a new file needs registration in `harness/verify-suites.json` (TP-13) that is a stop condition for T0, not an edit.

Files: `lib/continuity-authority-drift.test.mjs` (cases 1-6, 12, 13), `scripts/pipeline-state-inspect-continuity-drift.test.mjs` (cases 7-11, 12 CLI half; spawns the CLI against a temp repo; the name does not match TP-5), `lib/audit-index.test.mjs` (cases 14-21, 25), `scripts/audit-index.test.mjs` (cases 22-24, 26).

Drift (R6-2):
1. Recorded and observed digests equal for PRD and Spec -> `status: "current"`, `recovery: null`, both artifacts `match`.
2. PRD bytes changed -> `status: "drift"`, prd `changed` with `recordedSha256 !== observedSha256`, spec `match`, `recovery.code === "CONTINUITY-AUTHORITY-DRIFT"`.
3. Spec only changed -> symmetric to 2.
4. Both changed -> two `changed` artifacts, still ONE `recovery`.
5. PRD observer returns null (missing or unsafe) -> prd `unobservable`, `observedSha256: null`, `status: "drift"`; a throwing observer gives the same result and never propagates.
6. Purity: the observer is called exactly twice, with the recorded repo-relative paths in `prd`, `spec` order; the module imports no `fs`.
7. State without `continuity` -> `continuityAuthorityDrift === null` and every pre-existing payload key keeps its value (key-by-key against explicit expectations).
8. R6-2 fixture through the CLI: temp repo whose State carries a valid continuity object and whose PRD bytes differ -> `inspect` prints `continuityAuthorityDrift.status === "drift"` with recorded and observed digests.
9. Read-only: State file bytes are identical before and after `inspect`, and no lock, journal or temp file appears next to it.
10. Precedence: with a mixed-plan or stale-plan `nextAction` present it is unchanged and the drift is still reported; with none present `nextAction.kind === "repair-required"` and `code === "CONTINUITY-AUTHORITY-DRIFT"`; a single PRD edit that drifts both carriers yields exactly one action.
11. Not a blocker: `status`, `lifecycle`, `planApproved` and `continuityDispatchAllowed(continuity)` (`lib/continuity-state.mjs:452`) are identical with and without drift.
12. Registry consistency: `recovery.route` is a member of the exported verb list (`PIPELINE_STATE_COMMANDS`) and equals `continuity-authority-revision-plan`; the guidance names `--proposal-file`.
13. Sanitization: serialized projection contains only repo-relative paths and 64-hex digests (no drive letter, no home-directory shape).

Audit index (R6-4):
14. Complete fixture (every gate present, every commit attributed, sources match) -> `complete: true`, `missingSteps: []`, every gate row has a digest.
15. R6-4 fixture, exactly one gate deliberately missing -> `complete: false`, exactly one `missingSteps` entry, naming that gate with `AUDIT-GATE-MISSING` and its `expected` locator; all other rows unchanged.
16. Table-driven: each gate in the closed set is removed in turn and yields exactly its own entry.
17. Artifact absent vs digest differs -> `AUDIT-GATE-MISSING` vs `AUDIT-GATE-DIGEST-MISMATCH`, never merged.
18. Determinism: two runs on the same input are byte-identical; rows are sorted; the document contains no timestamp.
19. `indexSha256` recomputed from the document without that key equals the emitted value; altering any row changes it.
20. Source rows come from the drift module: a changed PRD gives `AUDIT-SOURCE-DRIFT` and the same `recordedSha256`/`observedSha256` the drift projection reports for the same fixture.
21. Commits: a `Dispatch:`-trailer commit, a `stage-0` commit and a trailer-less commit are listed as `dispatch`, `stage-0`, `unattributed` (the last also produces `AUDIT-COMMIT-UNATTRIBUTED`); an unknown SHA gives `AUDIT-COMMIT-UNKNOWN`; no commit subject appears in the output.
22. Read-only: `git status --porcelain` and the State bytes of the fixture repo are unchanged after a run.
23. Exit code is 0 for an incomplete index; refusals (unknown flag, no State, unknown feature) are non-zero with a typed code and zero writes.
24. Persisting through `scripts/capture-evidence.mjs` into `evidence/` works and the stored bytes equal stdout (no extra path logic in the script).
25. Sanitization: no host-path shape (drive letter, `/home/`, user directory) in the output.
26. Static: the new modules hold no host-path literal and `harness/scripts/check-consumer-safe-paths.test.mjs` passes (plugin source ships to consumers; `templates/prompts/goldfish-task.md:374-381`).

## 6. Open choices for the PO (non-blocking, recommendation first)

1. Which `inspect`: the State `inspect` of `scripts/pipeline-state.mjs` (recommended) vs also relaying a one-line drift hint through the onboarding `inspect`/`v4Inspection` (not read; rejected for v1, one source of truth).
2. Drift severity: report-only plus a pointer (recommended; adds no blocking state) vs make drift remove dispatch permission (a fifth blocker type; contradicts BJ).
3. Audit index home: standalone read-only script over a pure module (recommended) vs a new `pipeline-state.mjs` verb (hot module, another sanction entry) vs an `inspect --audit-index` flag (makes the per-turn `inspect` heavier).
4. Completeness: report only, exit 0 (recommended) vs an opt-in `--require-complete` exit code vs refusing `close-feature` on `complete: false` (a new blocking state; only if the PO wants audit completeness enforced, then it is its own decision).
5. Gate set: closed v1 list from section 3, derived at slice start from the close-check/close-block list (recommended) vs a freshly invented list. Whether `light`-profile work may legitimately lack a gate is unread; if so a gate row needs a `not-applicable` status.
6. Change unit: one feature id (recommended) vs a commit range.
7. Output: stdout JSON persisted via `capture-evidence` into ignored `evidence/` (recommended) vs a tracked copy under `specs/<feature>/evidence/` when a gate cites it.
8. Observation, left untouched: `physicalRebindFile` conflates missing and unsafe paths (seam 4); this note keeps it and lets the field say `unobservable`. Splitting the reasons would change the plan-lifecycle callers and is out of scope.
