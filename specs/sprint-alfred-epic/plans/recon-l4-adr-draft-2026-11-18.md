## 2. Why a Claude greenfield design ends without one (b)

No single missing step; five soft spots add up (all PROVEN, the run itself NOT READ):

1. **The marker is empty by default.** The generated design skeleton ships `adrReferences: []` (`lib/design-authoring.mjs:8`); the instruction to fill it sits in one HTML comment line (`:15`).
2. **The step needs its own input.** Runbook `record-decisions` has the need "the design package names its decisions to record ... in the module adrReferences" (`plan-path.v1.json:73-75`): with an empty list the step has nothing to do, so an agent skips it without any signal. It is circular.
3. **The review only asks.** The readiness reviewer raises "a question, never a block" when the design makes such a choice and no module names an ADR path (`agents/readiness-reviewer.md:119-124`). One question among many; nothing re-asks later.
4. **The close row stays quiet.** With an empty `adrReferences` the row `adr-decision` falls back to the typed impact the agent itself passes at close (`lib/close-quality-readback.mjs:77-97`): `no-architecture-impact`, `architecture-conforms` or `architecture-summary-updated` read as `not-applicable` (`:39`, `:92`), never "missing". Only a stated `architecture-decision-added` with an empty `docs/adr` reads "missing" (`:93-96`). INFERRED that run A passed one of the quiet values.
5. **The seeded README points at a different route.** Onboarding creates `docs/adr/README.txt` (`lib/architecture-map-scaffold.mjs:21-41`, written by `initialGreenfieldDecisionRecordTargets` `:68-74`): it demands an ADR "before implementing" a costly choice, but describes a hand-written `docs/adr/XXXX-<slug>.md` plus hand-computed sidecar and a template with a `Status: proposed` line (`:30-33`, `:43-63`). That contradicts the sanctioned route (draft-prefix, never hand-write or rename, no status line in the Markdown: `create-adr.mjs:18-22`, `SKILL.md:81-86`) and does not name `create-adr` at all. INFERRED: this explains run B's single hand-written/renamed file (a rename is forbidden by `SKILL.md:81-83`) and, together with 1 to 4, run A's empty directory. The seed is create-only, so installed consumers keep the old text.

## 3. Where the design marks a decision as expensive (c)

- **The only design-side marker of a decision to record is a list of paths.** `adrReferences` per module (`schemas/pipeline.module-inventory.v1.json:7,19`: array of strings, required but may be empty). Template and review text say "title, trigger and ADR path" (`design-authoring.mjs:15`, `readiness-reviewer.md:122`, `happy-path.md:37`), but the schema holds a path string only: the title and the trigger have no field. The design block's `disposition` carries `decision`, `scope` and `rationale` only (`design-authoring.mjs:10-11`). The `architectureDecisions` array of the bindings block (`bind-adr-proposals.mjs:235-237`, `lib/design-decision-bindings.mjs:103-106`, at most 64) lists decisions ALREADY recorded or bound (id, digest, selection), so it is a result, not a marker of an expensive choice. PROVEN for the lines read; "no other field" is INFERRED (the whole design-block validator was not read).
- **A derived list without a stored field is possible for the DECLARED decisions.** Parse the `pipeline-architecture-design` block of the draft PRD (the same `submitDesignDraft.design.modules` that `submit-plan` already walks, `pipeline-state.mjs:12310-12312`) or, after materialization, `architecture/map` (`scripts/close-coordinator.mjs:1311-1316`, `promisedAdrPaths`). Each entry `docs/adr/NNNN-<slug>.md` gives a slug (title derivable from it), and the state of that slug is derivable from the files (`inspectAdrDraftBindings`, plus an accepted record with the same slug). No stored status. PROVEN for the readers; INFERRED for the slug rule.
- **Undeclared decisions cannot be derived from the design.** PRD and Spec templates carry no "expensive" marker (rg for expensive / hard to reverse / costly / irreversible over `templates/prd.md` and `spec.md` finds only unrelated sentences). The only other deterministic signal is path-based: `architecture-baseline.mjs` (five axes, `:30-56`, `evaluateSignificanceAxes` `:101`), which works on a diff of changed files, not on a design, and is noisy for a greenfield (every `src/` file is new). NOT RECOMMENDED as the trigger (INFERRED: it would fire for every first feature and become the new loop).
- **Known weakness of the existing derived row.** `adrRow` tests the exact promised path (`close-quality-readback.mjs:81`). Because the design names the number before `bind-adr-proposals` assigns it (`bind-adr-proposals.mjs:175-182`), a different final number reads "missing" although the decision exists. INFERRED (not run).
