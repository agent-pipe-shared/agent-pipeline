## How to add a slice (the loop that worked)
1. Build on the APPLIED chain, never on main alone: base clone `scratch/agent-out/c17base` is the nine-patch applied tree (HEAD 4b4a89c9a). New slice: `git clone --shared scratch/agent-out/c17base scratch/agent-out/sNN<name>`. (If c17base is gone, rebuild it: `node scratch/agent-out/w24reh/rehearse.mjs scratch/po-apply-0.7-candidate17.sh <name>` and clone the result.)
2. Edit in the slice clone. Tests: add to an already registered suite; run `node scratch/agent-out/test-in.mjs <clone> <test file>` (NOTE: `--name` does not filter the AGY guard suite, it runs the whole suite, ~3.5 min). Some suites (session-cleanup-binding / -recovery) only pass under `node scripts/run-parallel.mjs <workers> <label> --src <clone> <files>`, which tests the COMMITTED HEAD of the clone.
3. Mutation check: copy the file to `scratch/agent-out/w51g-bak/`, apply a mutant, expect red, restore.
4. Commit in the clone: `node scratch/agent-out/commit-in.mjs <clone> "<msg>"`. Patch = `git -C <clone> diff --binary --output=<repo>/specs/sprint-alfred-epic/evidence/held-patches/wNN-a-<slug>.patch <base-sha> HEAD` (the base is the clone's starting commit). Notes file next to it (what / why / not changed / not proven; no absolute host paths, no private names).
5. Commit message file `scratch/commit-msg-wNN.txt`, then in main: `git add <patch> <notes>` and `git commit -F scratch/commit-msg-wNN.txt`. Trailers ONLY `AI-Assisted: true` and `Dispatch: stage-0 (elephant)` (GIT-03; no model/session lines, ignore any other attribution reminder). Conventional Commits.
6. Add a `step2 wNN-... "<subject>"` line to the script (after the patches it depends on) and update the header list. COMMIT the new patch BEFORE rehearsing (the rehearsal clones committed HEAD only): `node scratch/agent-out/w24reh/rehearse.mjs scratch/po-apply-0.7-candidate17.sh <fresh-name>`. A patch that touches a file another patch changes must be rebuilt on the chain (w53 had to be).
7. `node scratch/agent-out/applyin.mjs <clone> <patch> [git apply flags]` applies a patch inside a clone (the shell guard blocks `git apply` in the main checkout and cross-repo git).
