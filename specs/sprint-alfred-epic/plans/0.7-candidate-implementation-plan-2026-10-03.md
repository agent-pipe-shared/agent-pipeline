# 0.7.0 local candidate — implementation plan (draft, 2026-10-03)

Status: **planning draft, no authority.** Implementation begins only after the
single final PO plan approval of the Alfred package (PRD §14, Spec §21). This
plan slices the PO goal into dispatchable work packages: realize all open
Alfred items, fix all Pipeline defects for all supported runners and
platforms, and produce a stamped local 0.7.0 candidate that the PO installs.
Sources:

- the findings register `../design/greenfield-0.7-findings-round-2026-10-03.md`
- `backlog/STATUS.md` (55 open `sprint: alfred` items at the 2026-10-03 index)
- the 2026-10-03 items not yet reconciled into the index

## Rules for every package

- One package, one Goldfish dispatch from `templates/prompts/goldfish-task.md`.
  The budget line is a list item, `- Tool budget: ≤N tool uses`.
- Bugfix packages use the BUGFIX module: reproduce first, root cause only, and
  the regression test stays.
- Every package proves its Spec §21 acceptance cases or its item's acceptance
  with machine-written evidence.
- Windows (Git Bash) and POSIX fixtures are both mandatory for guard,
  lifecycle and host code.
- An independent Critic reviews each wave's diff; Verify and the security scan
  run on the integrated candidate.
- Operator hotfixes 1–8 (installed copy, `scratch/hotfix-*`) are first ported
  verbatim into source (W0-3, so source equals installed and a plugin refresh
  cannot drop them), then replaced by proper source fixes in Waves 2–3. The
  candidate must not depend on any hotfix.
